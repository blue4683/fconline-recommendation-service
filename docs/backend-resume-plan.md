# 백엔드 재개 범위

2026-10-20 사용자가 웹 담당 부분을 제외하고 중단한 개발을 재개하도록 요청했다. 이전 문서 전용 승인은 이번 사용자 요청 범위에서 기능 구현으로 이어진다. 웹 화면/클라이언트는 별도 담당 소유이며 기존 제품·수집·데이터·비용 제한은 유지한다.

## 구현 순서

| 증분 | 구현/검증 범위 | 경계 |
|---|---|---|
| R0 / W1 | 강화 누적 규칙·1강 기준 1~13강 순수 계산·원본/규칙/결과 해시·입력 검증·합성 테스트 | 원본/모델/추천 허용 5~11 변경 없음. 파일/DB/HTTP 없음 |
| R1 / W1 | 명시 seed·시각·자료 버전의 합성 MaterialProvider, 파생 5강 호환 자료, 필요한 강화 자료 | 가상 생성 규칙 명시. 가격/급여/자격은 독립 합성. 실데이터 변환·모델 입력에 자동 사용하지 않음 |
| R2 / W1 | 의존성 검증·고정, 주입 가능한 그래프와 테스트용 추출기, 기존 build 연결 | 실제 모델/외부 서비스 없이 정상/누락/미지원/실패 상태 검증 |
| R3 / W2 | 코드 결과 표/허용 사실·안전 템플릿·상태 전달 | 웹 파일 수정 없이 DTO/백엔드 경계 구현. 검증 후 출력·최종 만료 유지 |
| R4 / W3 | 승인된 두 Ollama 모델의 추출 소량 비교·어댑터 검증 | 아래 1회 상한. 모델 선택과 지표의 근거를 실측과 구분 |

모듈 구현의 내부 타입/파일 구성은 기술 선택으로 기록하되 기존 공개 계약의 의미를 바꾸지 않는다. 새 제품 조건·모델/운영 정책이 필요한 지점은 질문하고 독립 작업을 계속한다. 이후 API/실제 웹 연결·MCP는 로드맵의 선행/공용 계약과 미정 정책을 확인해 진행한다. 합성 평가의 표본 수/실제 Agent 성공 기준을 임의로 확정하지 않는다.

## R0 계산 계약

- 규칙은 기존 [강화 설계](reinforcement-derivation-contract.md)의 누적값을 그대로 사용한다. 원본 PlayerCard는 기본 1강이어야 하며 객체도 다시 검증한다.
- 34개 능력치 키는 기존 학습 입력 목록과 정확히 일치해야 한다. 목록을 공통 스키마 상수로 분리하더라도 기존 순서·피처 해시·학습 계약은 유지한다.
- 반환값은 상세 능력치/기존 포지션 OVR와 출처만 담는 독립 파생 결과다. 메타데이터·가격·급여·자격을 포함한 완전한 PlayerCard/추천 관측을 자동 생성하지 않는다.
- 원본 배치/버전/강화·정규화한 원본 payload SHA256·규칙 SHA256·대상 강화·계산값을 연결한다. payload 해시는 원본 HTML/파일 manifest를 새로 검증한 해시라고 주장하지 않는다.
- 원본 source/status/observed_at/valid_until/delete_after를 보존한다. 계산기에는 시계/최신 선택이 없고 unknown 승격·기한 연장·원본 수정이 없다.
- 출력 자료는 깊게 불변이거나 복사본으로만 조회할 수 있게 한다. 결측/추가 능력치·잘못된 강화·정수 범위 초과는 오류다. 없는 OVR 키를 만들거나 OVR 200 초과를 잘라 맞추지 않는다. 추천 단계가 기존 범위 제외를 적용한다.
- 기준 b 대비 차이는 B(target)-B(b)이며 이중 가산을 방지한다. 현재 5강 기준 계약은 후속 합성 어댑터에서만 연결한다.

## Ollama 비교 1회 범위 — 사용자 승인

사용자가 qwen3.5:2b와 qwen3:8b를 같은 합성 요청 5개씩, 총 최대 10회 비교하는 안을 선택했다. 설치 목록을 읽기 전용으로 다시 확인했으며 모델 다운로드/서버 종료는 하지 않았다.

- 로컬 127.0.0.1:11434에서 순차 실행, 각 추론 HTTP 시도 최대 120초, 재시도 0. 실패/결과 미상 시도도 10회에 포함한다.
- 동일 5개 시나리오와 정답/스키마/프롬프트를 실행 전 고정한다. 모델 digest·런타임·추론 설정·최초 로드/요청 지연·구조/의미 결과를 구분해 기록한다.
- 새 실행 ID와 누적 시도를 Git 제외 로컬 산출물에 기록한다. 완료 실행을 자동 재시작하거나 남은 상한을 재사용하지 않는다. 타임아웃/연결 오류로 서버 작업 종료가 불명확하면 중단해 중복 실행을 피한다.
- 외부 전송·새 다운로드·유료 호출·새 넥슨 요청·LangSmith 업로드 없음. 실데이터 원문/선수 정보는 프롬프트에 넣지 않는다.
- 5개 소량 결과는 모델 후보의 동작 확인이며 전체 한국어 의미 정확도/Agent SLA 증명이 아니다. 결과를 보고 모델/설정 추천과 남은 판단 사항을 구분한다.

## 협업과 완료 기록

backend-agent-mvp 전용 작업 디렉터리를 사용하고 각 증분은 최신 develop에서 분기한다. [공용 기록](agent-collaboration.md)의 INT-*에 범위·기준·계약 영향·검증·PR을 남긴다. 웹 담당의 파일/기록을 수정하지 않고 원격 변경을 다시 읽는다.

각 코드 PR은 전체 pytest·Ruff 린트/포맷·최신 head CI와 diff를 확인한 뒤 Squash 병합한다. 1-D/1-F·실데이터 추천·웹 완료 여부는 별도로 유지한다.

## 새 비교 승인 (2026-10-20)

사용자가 첫 실행의 사전 점검 연결 거부/추론 0회를 확인한 뒤 설치된 Ollama 서버 시작과 같은 조건의 새 비교 1회를 승인했다. 원래 manifest/승인 잠금은 보존하고 별도 승인 디렉터리 `artifacts/llm-comparisons/approval-20261020-002`에서 실행 ID `ollama-extraction-20261020-002`로 진행한다. 두 모델×동일 5문장, 최대 10회·각 120초·순차·재시도/다운로드/외부 전송 없음은 유지한다. 서버는 loopback에만 바인딩하고 cloud 기능/시작 시 모델 blob 정리를 끈다. 결과/선정 근거는 실제 실행 후 별도 기록하며 새 운영 정책 승인은 아니다.

R4 비교 뒤 사용자 선택으로 [후보 구간·ID 선택 설계](candidate-selection-adapter-design.md)를 작성한다. 설계만 승인됐으며 첫 문형/상한/명확화 전달·구현·추가 실제 비교는 후속으로 구분한다.
