# 모델 없는 브라우저 상태 진단

2026-10-22 사용자 “다음 단계 진행” 요청에 따라 E2E004 뒤의 페이지 초기화를 조사했다. 실데이터 경로의 Stage 4-A/4-B·단계7 후속 진단이며, 실제 모델 재실행은 포함하지 않는다. 기준은 `feat/real-data`의 `0f39112f0bf919fcda9ae34f8752b5ecf3810a55`다. 현재 요청에 필요한 모의 비교를 새 진단 ID로 기록했고, 소진된 E2E004 승인/잠금을 재사용하지 않았다.

## 확인한 사실과 결론

**원인은 미확인이고, 초기화는 이번 모의 비교에서 재현되지 않았다.** 제품 오류를 고쳤다거나 실제 남은2사례를 검증했다고 보고하지 않는다.

E2E004의 해당 세션 도구 기록에는07:02:33.990 KST의 `getAXStateAndScreenshot` 호출,07:02:36.925의 다음 `setValue` 호출과 이전 페이지 요소 오류,07:02:40.799의 전체 AX 조회가 있다. 현재 AX는 빈 입력/연결 미선택 화면이었다. 캡처에서 다음 입력까지 약3초였으므로, 장시간 방치 뒤 발생한 것으로 해석하지 않는다. 이 시각만으로 누가/무엇이 페이지 상태를 바꿨는지는 알 수 없다.

[OpenAI Docs의 문제 해결 문서](https://learn.chatgpt.com/docs/reference/troubleshooting#feedback-and-logs)가 안내하는 로컬 앱 로그/세션 위치를 참고했다. 관련 날짜의 앱 로그와 해당 대화의 도구 메타데이터만 좁혀 읽었으며 원인을 확정할 탐색/새로고침 기록은 확보하지 못했다. 다른 대화·원문 로그·토큰·비밀값을 복사/게시하지 않았다. 공식 문서가 이번 IAB 초기화 원인을 설명한 것은 아니다. 로컬 앱 버전은26.1013.40934(build20770)다. 앱 설정·권한·코드 변경이나 업데이트/재시작은 하지 않았다.

## 모델 없는 실제 브라우저 비교

같은 IAB와 `http://127.0.0.1:5173/`를 사용했다. origin 변경이나 권한 우회는 없다. 각 화면에서 모의 응답을 선택하고 입력A→모의11명 결과→화면 수집→입력B→두 번째 모의 결과→004와 같은 기본 결합 캡처→입력C를 수행했다. 강제 전체 AX 결합 캡처와 기본 결합 캡처를 모두 확인했다.

| 화면 | 모의 제출 | 캡처 뒤 연결/입력/11명 표 | 초기화 재현 |
|---|---:|---|---|
| 기존 주 checkout v0 | 2 | 유지 | 없음 |
| 최신 v1 Vite 개발 서버 | 2 | 유지 | 없음 |

첫 비교 `browser-lifecycle-20261022-001`은 기존 v0를 그대로 사용했다. 두 번째 `browser-lifecycle-20261022-002`는 현재 사용자 요청의 모델 없는 원인 조사에 필요한 가역적 비교로 수행했다. v0 PID16148/cwd/명령/시작시각을 대조한 뒤 잠시 종료하고, 같은5173에서 v1 개발 서버 PID19340과 정적 preview PID19669를 순차 실행했다. API 주소를 설정하지 않아 실제 연결은 비활성이었고, 모의 모드만 선택했다. 필요한 서버를 새 작업 디렉터리에서 실행했으며 자료 체크아웃/사용자 파일은 변경하지 않았다.

v1 빌드는 같은 package-lock의 기존 로컬 node_modules만 사용해 통과했다(다운로드0). 정적 preview에는 HMR이 없지만, 개발 서버에서도 재현되지 않았으므로 HMR이 원인이었다거나 preview가 문제를 해결했다고 결론 내리지 않는다. 실제 API/health 전환과 실데이터 렌더링은 이번 비교 범위가 아니다.

새 임시 두 프로세스·탭은 종료했다. 원래 v0를 주 checkout/cwd/Node22 명령으로 **PID19940**에 복원하고 합성 안내/실제 연결 비활성 화면을 확인했다. MongoDB는 그대로 유지했다.8001/11434 listener는 없다. 신규 Ollama metadata/추론·Agent 요청·DB 읽기/쓰기·넥슨 수집·LangSmith 전송은 모두0이다. 공식 문서 읽기는 이 제품 실행 계수와 구분한다.

## 관측 방식 보완

004의 O01 텍스트 파일은 전체 AX 대신 “변경 없음” 차이 출력이었다. 기존 증거/종료 기록은 수정하지 않고, 후속 관측 도구를 로컬 Git 제외 경로에 준비했다.

- `artifacts/handoff/browser-e2e-observer-20261022.mjs`: `getAXState({disableDiffing:true,emit:false})`로 전체 상태를 먼저 저장하고, 화면 PNG를 저장한 다음 전체 AX를 다시 읽는다. 기대한 정확한 origin·선택 연결 방식·입력·관측 실행ID·결과 제목/11명 표 존재 여부를 전후 대조한다.
- 연결 미선택/입력 손실/자료 변경/결과 변경이면 오류로 중단한다. 이 도구에는 클릭·전송·재연결·상태 복원 기능이 없다. 기존 증거는 `wx`로 덮어쓰지 않는다. 상태를 유지시키거나 초기화를 막는 제품 수정은 아니다.
- `browser-e2e-observer-check-20261022.mjs`: 합성 텍스트·UI 대역으로 전체 AX 부재, origin/연결/입력/자료/결과/표 변경, 캡처 중 상태 손실, 기존 파일 덮어쓰기, 파일명 경로 탈출을 거부하는 경계를 확인했다. 실제 네트워크 없이 통과했다.
- 실제 v1 정적 모의 화면에서도 새 관측 도구로 캡처 전후 입력C/모의 연결/11명 표 유지와 전체 AX/PNG 저장을 확인했다. 이 모의 성공을 실제 모델 E2E로 합산하지 않는다.

다음 실제 E2E는 이 관측 가드를 쓰되, 페이지가 바뀌면 자동 복구/재전송 없이 중단해야 한다. 권한 거부가 있으면 다른 브라우저/origin/직접HTTP로 우회하지 않는다. 미실행 급여300/예산 충돌을 검증하려면 새 계획·해시·상한과 실제 모델 호출 승인이 필요하다. 자동005 생성/실행은 하지 않았다. 남은2사례·원인 미확인·기존 빈 결과의 “다섯 조건” 문구는 그대로 미해결이다.
