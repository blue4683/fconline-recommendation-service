# OVR 동점 조합의 예산 활용

2026-10-22 사용자가 **OVR 최대 유지, 동점이면 예산 더 활용**을 선택했다. Stage 3-B/C의 목적 우선순위 변경이며 합성/명시 관측 공통 엔진에 적용한다. 기준 develop5d83876에서 별도 feat/budget-tiebreak로 진행한다. Stage 1-D/F 전체 완료나 새 수집·모델·배포 승인이 아니다.

## 계약

1. CP-SAT의 OVR 합 최댓값을 먼저 확인한다. 그 값이 미확정인 feasible이면 보조 목적을 실행하지 않고 기존 상태를 유지한다.
2. OVR 최적을 확인하면 합계를 고정한 뒤 총 가격을 최대화한다. OVR1점을 포기해 더 비싼 조합을 고르지 않는다. 예산/급여 상한·11명 자리·같은 인물 중복 금지·클럽/배치/강화·독립 검증·만료는 유지한다.
3. 모든 탐색 단계는 기존 최대10초/1스레드/시드123을 공유한다. 단계마다10초를 새로 배정하지 않는다. 부가 모델 구성/검증·자료/HTTP 전체 지연의 SLA라는 뜻은 아니다.
4. 가격 목적의 전체 정수 범위가2^53-1 이하이면 단일 정수 목적을 쓴다. 그 밖에는 기존 base1,000,000 잔액의 높은 자리부터 차례로 최소화해34자리 BP·1BP 차이를 유지한다. 큰 정수를 float로 변환하거나 OVR과 가격을 큰 가중치로 합치지 않는다. 자리별 가격의 안전한 상·하한으로 이미 고정된 자리는 추가 탐색하지 않는다.
5. 시간 내 보조 최적을 확인하지 못하면 OVR이 같은 유효해 중 지금까지 가장 비싼 해를 유지한다. 원래 해보다 저렴한 임시 해로 교체하지 않는다. 모델 오류·예외·확인된 유효성과 모순되는 실패는 내부 오류로 중단한다.

`EngineResult.price_optimization_status`는 not_run/optimal/incomplete로 OVR 상태와 구분한다. 기존 optimal은 OVR 최적을 뜻하며, 보조 목적 미확정을 가격 최적으로 보고하지 않는다. 코드 최종 답변에 "동일 OVR 내 최대 예산 활용은 시간 내 확인하지 못했습니다."를 붙인다. 실패/만료 응답에는 이 안내나 표를 남기지 않는다. 웹v1/healthv2 구조는 바꾸지 않고 기존 answer를 사용한다. 엔진/코드 출력 버전 해시를 갱신하며 과거 실행/평가를 덮어쓰지 않는다. 탐욕 비교 두 방식의 순서/동점 규칙은 변경하지 않는다.
