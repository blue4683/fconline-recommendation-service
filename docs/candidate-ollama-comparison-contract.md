# C4 로컬 ID 선택 어댑터·새 비교 계약

2026-10-20 / 데모 W3·Stage 4-A. 사용자가 실제 Ollama ID 선택 어댑터 구현과 새 비교 1회를 승인했다. C0~C3의 실제 모델 제외는 이 C4 범위에서 확대한다. 기존 원문 검증·미해결 입력 명확화·ID 전체 커버리지·기술 오류/입력 문제 구분은 유지한다.

## 구현과 실행 범위

설치된 qwen3.5:2b·qwen3:8b에 동일 7사례를 적용한다. 준비 단계에서 막힌 사례는 모델에 보내지 않아 실제 추론은 총 최대 12회다. 로컬 순차, 호출별 전체 기한 120초, 재시도·다운로드·외부 전송 없음, 서버/연결 오류 즉시 전체 중단이다. 새 실행/승인 잠금/원본 응답·시도 기록을 Git 제외 경로에 무기한 보관한다. 기존 실행/잠금과 남은 횟수를 재사용하지 않는다.

실제 비교는 prepare → ID 선택 → 엄격 디코드/원문 복원 → 기존 정규화까지만 실행한다. 스쿼드 엔진·DB·새 수집·API/SSE·웹 연결은 제외한다. 정상 전송이 완료된 잘못된 JSON/ID는 품질 실패로 기록하며 같은 입력을 재시도하지 않는다. 서버/연결/전체 기한·불확실한 응답 오류는 다음 사례도 중단한다. 중단·미상 시도도 상한에 포함한다.

## 고정 사례와 재현

기존 직접 구간 비교의 complete/missing/unsupported/conflicting/decimal_list 5사례를 보존하고, 순서/숫자 쉼표와 같은 예산 반복 2사례를 추가한다. unsupported는 준비 단계에서 명확화하며 모델 미호출을 별도로 평가한다. 각 모델은 정상 준비 6사례만 호출한다. 기대 SourceSpan은 원문과 수동 정답으로 미리 고정하고 모델 응답/후보 생성 결과로 정답을 만들지 않는다.

프롬프트·JSON schema·후보/선택 규칙·원문/후보집합·수동 정답·실행 소스 해시·설치 모델 digest·런타임을 첫 추론 전 기록한다. 두 모델은 temperature=0, seed=123, num_ctx=4096, num_predict=1024, think=false, stream=false, keep_alive=0을 동일하게 적용한다. JSON schema에 현재 후보집합 ID를 고정하고 여섯 ID 배열을 모두 요구한다. 인덱스/금액을 모델이 새로 생성하지 않는다. 서버는 127.0.0.1:11434만 사용하고 프록시 환경·redirect·자동 추적 업로드를 사용하지 않는다.

기본 명령은 계획만 출력한다. 실제 실행은 별도 --run·안전한 실행 ID를 요구하고 승인 root의 1회 잠금을 만든다. 시도 pending을 디스크에 기록한 다음 HTTP를 보낸다. 읽기 전용 모델 상태 확인은 별도 최대 4요청이며 추론 횟수와 구분한다. 자동 재개/재실행은 없다.

## 검증·보고와 한계

실제 호출 전 MockTransport/합성 단위 테스트와 전체 pytest/Ruff를 통과시킨다. 원문/ID 바인딩, 잘못된 응답/기한/redirect/연결 중단, 승인 잠금·pending 선기록·준비 실패 미호출을 검증한다. 기존 직접 구간 추출기의 계약은 보존한다. 구현 후 실제 소량 결과·지연·실패·manifest 해시를 같은 기능 PR에 기록한다.

정형 파서가 필드와 후보를 이미 정하므로 ID 선택 성공은 제한된 문형에서의 형식/근거 복원 성능이다. 일반 자연어 이해 개선, 실제 모델→엔진/웹 E2E, 운영 모델 선정 완료로 확대하지 않는다. 7사례 전체 중 준비 성공/명확화와 실제 모델 6사례의 근거/정규화 성과를 구분하고 이전 직접 구간 5사례 수치와 분모를 혼동하지 않는다. 모델 채택·API 동시성/취소 등 미정 운영 정책은 후속 결정이다.
