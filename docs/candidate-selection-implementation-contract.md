# 후보 선택 C0~C3 구현 계약

2026-10-20 / 데모 W3·Stage 4-A. 사용자가 개발 계속 진행을 요청했고 후속 질문에 정형 조건문 우선·순서 자유, 누락/중복 보존, 알 수 없는 표현/부정/정정은 명확화, 값 후보 128개·문맥 64개 상한과 전체 거부, 입력 문제/모델 오류 구분을 확정했다. [설계안](candidate-selection-adapter-design.md)의 이 범위를 구현한다. 실제 모델 호출·선정·API/SSE·웹·실데이터 변경은 포함하지 않는다.

## 첫 문형

쉼표로 나눈 조건 절을 순서와 무관하게 받는다. 예산/급여 절은 `예산 <금액>`·`급여 <정수>`, 나머지는 정식 클럽명·하이픈 포메이션·강화 표현이다. 주변 공백은 원문 위치 계산에 반영하고 값을 바꾸지 않는다. 마지막 요청 표현은 `으로 구성해줘` 또는 `로 구성해줘`, 마지막 마침표는 선택 사항이다. 다른 설명/어휘를 무시하는 목록을 임의 확대하지 않는다.

금액 쉼표와 강화 목록 쉼표는 보호한다. 숫자 토큰 안의 쉼표는 잘못된 묶음도 전체로 보존해 기존 파서가 거부하게 한다. 이어지는 강화 표현은 하나의 강화 목록 후보로 보존한다. 따라서 쉼표가 숫자/목록과 조건 구분으로 겹치는 표현은 보수적으로 처리할 수 있으며 명확한 구분 공백을 권장한다. 문장 중간 마침표·부정·정정·별칭 등은 임의 분해/추정하지 않고 미해결 문맥으로 명확화한다.

단일 절 전체를 해석한다. 예산에서 `1조5000`의 `1조`만, 클럽에서 `리버풀 제외`의 `리버풀`만, 강화에서 유효 접두어만 잘라 정상 후보로 만들지 않는다. 지원 밖 숫자/문법은 기존 파서 오류로 보고하고 입력 전체를 명확화한다. 예산/급여가 반복되면 출현별 후보를 유지한다. 쉼표로 이어진 강화 목록 내부 중복 정리는 기존 강화 파서 계약을 따른다.

## 준비 결과와 불변 registry

`prepare_candidates(original)`는 코드만 실행하는 준비 단계다. 원문 4,000자·금액 100자 한도를 유지하고 값 128개/문맥 64개를 넘으면 앞부분을 채택하지 않는다. 원문 타입/공백/미해결 절/기존 값 파서 오류/상한 초과는 새 준비 사유로 반환한다. 이 사유는 기존 normalizer가 생성한 결과/버전으로 위장하지 않는다.

준비 결과는 candidate_set과 input_issues를 분리한다. registry에는 원문, 생성 규칙 버전, 내용/원문 해시, 문맥·값의 원문 구간/허용 필드/출현별 ID를 불변으로 고정한다. 첫 문형에서는 알려진 조건 절당 값 후보 1개이며 문맥 상한이 먼저 걸릴 수 있다. 두 상한은 구조/모델 출력에서도 강제한다. 저장된 registry를 사용할 때 같은 원문/생성 규칙으로 재검증해 위조·다른 요청 혼입을 거부한다.

## ID 출력 계약

제안했던 다양한 문맥 분류 대신 첫 정형 문형은 미해결 문맥을 모델 호출 전에 종료한다. 준비가 정상인 registry의 모든 문맥은 정확히 한 값 후보를 갖는다. 출력은 candidate_set_id와 기존 여섯 필드 배열이며, 모델은 ID 문자열만 반환한다. 첫 다섯 필드는 값 후보 ID, unsupported는 문맥 ID namespace다. 첫 버전에서 미지원/미해결 문맥은 준비 단계에서 중단하므로 준비 정상 출력의 unsupported는 비어 있어야 한다.

엄격 JSON·필수 배열·추가 필드/중복 키/비유한 값·잘못된 타입/ID·다른 후보집합·중복 선택·잘못된 필드 배정·누락 출현을 거부한다. 모든 준비된 값 후보가 정확히 한 번 맞는 필드로 선택돼야 하므로 문맥별 별도 모델 분류 없이 전체 커버리지를 코드가 대조한다. 모델의 자유로운 filler 분류로 문맥을 버리지 않는다. 빈 필수 필드는 입력에 실제 후보가 없을 때만 유지되고 기존 정규화가 missing을 판단한다.

서버가 보유한 원문 SourceSpan으로만 복원하고 기존 normalize_conditions를 다시 적용한다. 후보 전 출현 자동 선택·외래 ID 보정·마지막 값 선택·임의 기본값·fallback은 없다. 출력 필드/버전/새 사유 코드는 이 내부 증분에서 명시하고 해시로 고정한다. 웹 DTO 확정/변경이 아니다.

## 그래프 연결

새 selector 프로토콜은 registry를 받고 JSON 선택 문자열을 반환하는 주입 인터페이스다. 실제 Ollama ID 선택 어댑터/호출은 이번 범위에 없다. 준비 문제가 있으면 selector/자료/시계/엔진을 호출하지 않는다. 선택의 구조/ID 오류나 ExtractionError는 안전한 provider_error로 보고 자료/시계/엔진을 호출하지 않는다. 예상하지 못한 구현 오류를 무조건 잡아 성공/명확화로 숨기지 않는다.

정상 선택만 기존 ExtractedConditions로 복원해 요청별 고정 추출기와 기존 SquadAgent에 전달한다. 기존 AgentRunResult·normalizer·build·스냅샷·CP-SAT·독립 검증·출력 계약을 유지한다. 새 준비/선택 결과는 별도 wrapper 결과에 담아 입력 명확화와 기술 오류를 구분하며 API 직렬화/화면 적용은 후속이다. 정규화 missing/ambiguous는 기존 결과로 전달한다. 재시도/상태 누적/현재 배치 자동 선택은 없다.

## 검증과 완료

C1 후보 생성/registry, C2 ID 검증·복원, C3 테스트 대역 연결을 같은 승인 범위에서 순차 구현한다. 알려진 문형의 순서/공백·정확 금액·강화 목록·반복/충돌·누락, 잘못된 숫자 쉼표/금액 접두어·부정/정정/추가 표현, Unicode/길이/상한, ID 위조/누락/교차 필드/다른 요청을 합성으로 검증한다. 정상 경로는 기존 실제 CP-SAT/독립 검증/코드 표까지 대조하고 문제 경로의 selector·자료·시계·엔진 미호출을 확인한다.

정형 문형에서는 파서가 필드를 이미 결정해 모델 선택의 추가 가치가 작다. 모델 대역 성공을 자연어 모델 개선/전체 E2E로 보고하지 않는다. 향후 파서 단독과 실제 모델 경로의 비교는 별도 사례/승인 범위를 정한다. 이번 구현에서는 지난 두 모델 비교/잠금을 보존하며 추가 추론 0회다. 필수 pytest/Ruff·환경 검사·최신 head CI 통과 후 develop에 Squash 병합하고 완료 브랜치를 정리한다. master에는 기능 묶음 PR만 생성한다.
