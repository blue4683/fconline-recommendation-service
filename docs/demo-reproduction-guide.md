## 2. Python 준비와 검사

Python3.11.15·저장소 `.venv`·pip를 사용한다. 기존 환경을 쓰면 재설치하지 않는다. 새 환경 설치는 아래 명령 예시이며 이 문서 작업에서 설치를 새로 실행하지 않았다. 의존성 내려받기와 실제 모델 내려받기를 혼동하지 않는다.

```sh
python3.11 -m venv .venv
.venv/bin/python -m pip install pip==26.2.1
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pip check

.venv/bin/python -m pytest
.venv/bin/python -m ruff check .
.venv/bin/python -m ruff format --check .
.venv/bin/python -m FRS --check-environment
```

최종 로컬 기능 검사 이력은1,571개 통과다. CI는 고정 Python 환경의 테스트/린트/포맷/import를 검사한다. 모델 요청은 기본 pytest에서 실행하지 않으며 실모델 실행기 테스트도 MockTransport/접속 차단을 사용한다. 실제 모델16회 성적을 위 테스트 통과 수와 합치지 않는다. 웹 CI/파일 권한 자동 격리는 미구축이다.

## 3. 실제 모델 없이25문장 재현

현재 저장소 루트에서 실행한다. 실행ID는 이전과 다른 안전한 영문 소문자/숫자/하이픈으로 지정한다. 아래는 고정 과거 합성 관측/응답 시계이며 현재 자료의 유효기간 연장이 아니다.

```sh
# 계획만 출력하며 파일/자료/엔진/모델을 실행하지 않는다.
.venv/bin/python -m FRS.evaluation.offline \
  --run-id w7-offline-local-check \
  --observed-at 2026-10-21T00:00:00+00:00

# 정답 ID 대역으로 합성 엔진/출력까지 검사한다. 모델/HTTP 요청 없음.
.venv/bin/python -m FRS.evaluation.offline \
  --run-id w7-offline-local-check \
  --observed-at 2026-10-21T00:00:00+00:00 --run
```

결과는 Git 제외 `artifacts/agent-evaluations/<run-id>/report.md`와 `manifest.json`이다. `plan.json`·`material.json`도 남긴다. 기존 디렉터리는 덮어쓰거나 자동 재개하지 않는다. 사전 증명이 실패하면 결과를 좋게 만들도록 자료/문장을 바꾸지 않는다.

읽을 항목은 metric_mode=synthetic_oracle_contract_only, actual_model_metrics=null, 모델/외부 요청0, 전체 분모25·선택 대상16·정상8이다. 대역 성공률100%를 실제 모델 정확도100%로 발표하지 않는다. 위 명령은 stdio MCP/브라우저까지의 동작을 새로 검증하는 명령도 아니다.

## 4. 저장된 실제 결과 확인

저장소의 공개 결과 요약은 [실모델 평가 문서](stage-w6-model-evaluation.md)에 있다. 원본/학습 모델/실행 보고서는 커밋하지 않았으므로 새 clone에 자동으로 들어 있지 않다. 이를 실행 실패나 숨겨진 기본 데이터로 바꾸어 설명하지 않는다.

원래 로컬 작업 환경에는 아래 기록이 있다.

```text
artifacts/agent-model-evaluation/approval-20261021-001/
  approval-consumed.lock
  w6-model-20261021-001/
    plan.json
    material.json
    manifest.json
    report.md
```

실제 상태2회·추론16회는 이미 사용한1회 승인이다. 잠금/manifest를 삭제하거나 다른 경로에 복사해 다시 실행하지 않는다. 실제 모델 출력은 비결정적이며 저장된24/25가 다음 실행에서도 같다고 보장하지 않는다.

요청 없이 실모델 계획만 보는 명령:

```sh
.venv/bin/python -m FRS.evaluation.model \
  --observed-at 2026-10-21T04:36:34.993000+00:00
```

위 명령은 현재 코드의 계획 조회이며 과거 plan.json의 복원이 아니다. Git 기준이 달라지면 계획 해시도 달라질 수 있으므로 실제 실행의 봉인된 계획/해시는 결과 문서를 확인한다.

`--run`을 붙이는 새 실행은 이 안내/기존 승인 범위에 포함하지 않는다. 새로운 실행ID/승인 루트·호출/상태 상한·배치/시각·종료 정책을 확정해야 한다. 예전 관측 시각을 현재로 조용히 바꾸어 재사용하지 않는다.

## 5. 화면 설명과 과거 증거

[실제 브라우저3사례 기록](agent-browser-e2e.md)은 정상11명·누락/충돌 안내·기존 표 제거를 확인한 과거 실행이다. 검증 뒤 서버를 종료했으므로 현재 화면에서 바로 live 요청할 수 있다는 뜻은 아니다. [웹 문서](../frontend/README.md)의 연결 방식/5173·8001·CORS 경계와 원문/수치 규칙을 확인한다.

화면만 새로 확인하려면 웹 모의 모드를 사용할 수 있다. 이 문서 작업에서 실행하지 않은 수동 명령 예시다. Node22.x의 프로젝트 엔진/lock을 충족해야 하며 실제 통합 검증 환경은22.23.3이었다.

```sh

```

브라우저에서 **모의 응답**을 직접 선택한다. 이는 고른 시나리오를 재생하는 UI 데모이며 원문 이해/실제 모델 실행으로 설명하지 않는다. `VITE_FRS_API_BASE_URL`을 넣고 **실제 연결**을 고르면 별도8001 서버/새 모델 상태 조회·추론이 필요하므로 자동 전환하지 않는다. 실제 API 키·비밀값을 프론트 설정에 넣지 않는다. 개발 서버는5173이고 preview4173은 승인한 실제 연결 origin이 아니다.
