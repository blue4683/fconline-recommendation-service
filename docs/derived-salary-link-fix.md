# 강화 후보의 파생 급여 연결 수정

2026-10-22 사용자 요청: 최신 develop에서 별도 브랜치를 만들어 5~11강을 허용해도 전원5강만 추천되는 문제를 해결한다. Stage 1-E/3-0/3-B·C의 관측 연결 오류 수정이며 실데이터 경로다. 기준 develop ec9a1a7, 작업 브랜치 fix/derived-reinforcement-salary다.

## 원인과 변경

수집기는 5강 능력치 응답 해시를 기준으로 급여에는 `<hash>-same-salary-N`, 능력치에는 `<hash>-derived-N`을 남긴다. 검색과 독립 검증이 급여/능력치 version의 완전 일치를 요구해 6~11강을 제외했다. 이는 가격·급여 상한 때문이 아니었다. 기존 DB 검증의 "11강 후보0/version_mismatch"는 당시 사실로 보존한다.

직접 관측의 기존 동일 version 규칙은 유지한다. 서로 다른 version인 파생 관측은 다음 조건을 모두 대조한다.

- 기본 카드 버전이 SHA256 형식이고 기준 강화가5다.
- 급여와 능력치가 같은 대상 강화6~11이고 강화 능력치의 기준 버전/강화가 기본 카드와 같다.
- 두 version이 동일 카드 원본 해시의 정확한 `same-salary-N`/`derived-N` 형식이다.
- 카드·급여·능력치의 spid·배치·웹 출처·관측 시각·유효 기한·삭제 기한이 모두 같다.

검색은 적합한 강화 후보를 만들고, 독립 검증기는 검색 함수를 호출하지 않고 같은 출처 규칙을 다시 확인한다. 단순 suffix 제거, 임의 버전 일치 처리, 기본5강 급여 행의 다른 강화 대입은 하지 않는다. 원래 status/충돌/신선도/가격·급여 상한 검사도 유지한다. `snapshot_spec.salary_link`에 새 정책을 기록해 버전 해시를 바꾸며 과거 산출물은 수정하지 않는다.

## 합성 회귀

전체 pytest **1,858 통과(29.06초/4 worker)**, Ruff·format265파일·pip check·환경 import 통과다. 첫 부분 검사는 새 만료 테스트가 관측 시각과 같은 유효 기한을 만들어 스키마에서 실패했다(278 통과·1 실패). 합성 관측 시각을 과거로 고친 뒤 부분279개와 전체를 다시 통과했다. 제품의 시간 검증은 완화하지 않았다.
