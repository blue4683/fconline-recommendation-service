2026-10-23. 웹 v2를 다른 담당이 구현하는 동안 독립 작업으로 포메이션·강화·예산별 엔진을 진단했다. 기준 develop은 `ced45730af8df6e1967c23d276825b4accc9c3ae`다. [GK 목적 계약](mf3-gk-priority-objective.md)의 정책·15/5/2 허용폭·30초/OVR10초·1스레드·시드123과 [v2 계약](web-agent-v2-contract.md)은 유지한다. 새 품질/지연 통과 기준이나 기존 D6 합성60문제의 대체가 아니다.

## 자료와 실행

[gk_priority_benchmark.py](../FRS/evaluation/gk_priority_benchmark.py)는 별도의 합성 자료를 만들어 OVR과 GK 우선 모드를 같은 후보 풀에서 비교한다. HTTP/Agent/LLM/DB나 서버 합성 자료 생성기를 사용하지 않는다. 실제 관측·판단·모델·.env·종료 실행을 읽거나 변경하지 않는다.

- 고정 계획: 3포메이션 × 허용 강화3종(5 / 5~11 / 8~11) × 예산2종 = 해 존재18문제. 포메이션별 급여 부족3문제와 작은 전수 대조3문제를 더해24문제다. 문제별 시드는123~146이다.
- 가상 인물11명에 시즌별 변형을 만들고 같은 인물의 중복 선택을 금지한다. 34개 능력치와 양발을 명시한다. 강화별 능력치/OVR 증가는 이 진단의 가상 규칙이며 실제 게임 공식이 아니다.
- 가격 단위는 `10**20 + 37`이다. 기본 급여310, 예산은 알려진 최저 강화·기본 변형 스쿼드 비용의1.2배/8배다. 제품 기본 예산을 정하는 값이 아니다.
- 해 존재 문제는 가능한11명 기준 해를 두 모드에서 먼저 독립 검증한다. 해 없음 문제는 인물별 최소 급여 합보다1 낮은 상한이다. 정확히11명이므로 빈 슬롯이 없어도 해가 없다는 하한 증명이 된다.
- 작은3문제는 전체 조합을 열거한다. 원관측·정책의 별도 Fraction 산술로 후보 점수를 대조하며 운영 scorer/solver를 정답으로 호출하지 않는다. 계약의15/5/2 허용폭과 S2의(GK,필드) 사전식 조건을 직접 적용한다.
- OVR은(총 OVR,가격), GK 모드는 S1·S2(GK,필드)·S3 점수·S4 가격의 전수 최적값과 비교한다. 주 목적 최적과 가격 최적은 따로 센다.

기본 동작은 계획 출력이다. 실제 실행에는 정책 경로·기대 해시·새 실행 ID·출력 경로를 모두 명시한다.

```sh
python -m FRS.evaluation.gk_priority_benchmark
python -m FRS.evaluation.gk_priority_benchmark \
  --run \
  --policy docs/examples/multi-factor-core-policy.json \
  --expected-policy-version 7df0b5607406d4a89da82086feb88c18b0d3a3924fd9d3b1fbc7db85d1b5a0fc \
  --run-id <새-실행-ID> \
  --output-dir artifacts/gk-priority-benchmarks
```

Python socket을 차단한다. Git 제외 출력은 manifest·문제별 JSON·summary이며 기존 실행 ID는 덮어쓰거나 재개하지 않는다. 중단/실패는 당시 완료 수와 오류 종류를 보존한다. 계획·정책·자료·스냅샷·소스 해시와 Python/OR-Tools/플랫폼을 기록한다. `criteria=null`, `passed=null`이며 구조/산술/상태 불일치가 있으면 CLI 종료 코드1이다.

## 측정 분모와 한계

- 요청 지연은 스냅샷 구성 + solver 호출이다. solver 안의 준비·탐색·독립 검증을 포함하며, 프로세스 시작·자료 생성·정책 읽기·기준 해 검증·별도 오라클·추가 결과 감사는 제외한다. 추가 감사 시간은 따로 기록한다.
- 같은 문제에서 OVR을 먼저, GK 우선 모드를 다음에 한 번씩 실행한다. 반복/순서 무작위화나 독립된 성능 측정 장비를 사용하지 않는다.
- 해 존재18 / 전수3 / 해 없음3의 분모를 분리한다. percentile은 nearest-rank이고18표본의 p95는 최댓값이다. 빠른 실패를 성공 요청 p95에 섞지 않는다.
- `optimal`은 주 목적의 의미다. 가격 최적 미확정을 전체4단계 최적으로 부르지 않는다. unknown/feasible·가격 상태·전수 대조 가능 건수도 따로 보고한다.
- 실제 자료 규모·분포, HTTP/DB/모델·브라우저·운영 SLA와 사용자 선호 개선은 측정하지 않는다. 기존 OVR D6 판정을 갱신하지 않는다.

## 발견한 상태 오류와 수정

수정 전 `gk-synthetic-20261023-001`은24문제를 완료했지만 급여 부족3문제에서 GK 모드가 infeasible 대신 internal_error를 반환했다. OVR 모드는 같은 조건을 infeasible로 판정했다. 나머지21문제는 두 모드에서 주 목적 optimal이었다. 이 실행·보고서·실행기 원문을 보존한다.

원인은 [solver.py](../FRS/core/squad_recommend/solver.py)의 `_solve_gk_priority.finish`가 해를 찾기 전 종료할 때 후보 배열과 빈 선택 배열을 `zip(..., strict=True)`로 묶은 것이다. 길이 불일치가 solver 실패 처리로 들어갔다. 선택 해가 없으면 두 빈 배열을 묶도록 수정했고, 선택 해가 있을 때의 길이 검사는 유지했다. 목적·가중치·가격 처리·OVR 경로는 변경하지 않았다.

첫 단계 UNKNOWN은 unknown을 유지하고 모델 오류는 internal_error인지 대역으로 확인했다. 실제 후보 풀은 있지만 총 급여가 부족한 경우는 실제 CP-SAT으로 검증한다.
