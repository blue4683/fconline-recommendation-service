# 다요소 선수 성능 점수 설계 초안

작성일: 2026-10-22. Stage 3-A/D7 후속 **설계 문서**다. 기준은 develop `58c954e7a64753fda0e0dc7fbeca053f46472ed5`와 그 시점의 [공용 기록](agent-collaboration.md)·[웹 설계도](web-agent-blueprint.md)다.

사용자는 OVR 외에 약발·체형·속력·가속력·포지션별 핵심 능력치를 반영하는 방향에 동의하고 설계를 요청했다. **아래 계산식·가중치·역할·검증 기준의 수치는 검토용 제안이며 사용자 확정값이나 실전 성능 검증 결과가 아니다.** 이번 요청으로 운영 D7을 교체하거나 구현·실제 추천·학습·수집·DB 쓰기·모델 호출·배포를 실행하지 않는다. D1 실데이터 경로와 기본 합성 실행, 1-D/1-F 미완료 및 종료한 실행/잠금은 유지한다.

## 1. 목표와 현재 구조

목표는 같은 예산·급여·클럽·포메이션·허용 강화 안에서, OVR이 조금 낮아도 해당 역할에 필요한 능력과 약발 등이 더 적합한 카드를 선택할 수 있게 하는 것이다. 산출물의 의미는 **정의한 정책에 따른 역할 적합 점수**다. 승률·득점 확률·게임 엔진의 실제 체감 성능을 보장하는 수치로 표시하지 않는다.

| 현재 코드에서 확인한 사실 | 설계 영향 |
|---|---|
| [performance.py](../FRS/core/squad_recommend/performance.py)는 선택 강화의 포지션 OVR/2만 사용 | 세부 능력치 점수를 별도 정책으로 정의해야 함 |
| [solver.py](../FRS/core/squad_recommend/solver.py)는 raw_ovr 합을 최대화하며 성능 탐욕도 raw_ovr 순 | 표시 점수만 바꾸면 선택 결과는 바뀌지 않음 |

현재 확정 D7은 [OVR 계약](stage-3-a-performance-contract.md)이다. 이번 문서는 그 계약의 자동 대체본이 아니다. 다요소 정책은 승인 후 새 버전으로 도입하고 과거 결과는 원래 규칙으로 재현한다.

## 2. 점수의 원칙

- 세부 능력치를 주 근거로 삼고 OVR은 기존 방식과의 비교·표시용으로 보존하는 안을 권한다. OVR과 그 구성 능력치를 다시 합산하는 중복 반영을 피한다. OVR 혼합형은 별도 비교 후보이며 초기 기본안에 넣지 않는다.
- 가격·급여는 제약, 팀컬러 자격·배치 허용·동일 인물은 적격성이다. 비싼 가격·높은 사용률·포지션 분류 확률을 좋은 성능의 증거로 직접 더하지 않는다.
- 같은 관측·강화·역할·정책에는 후보 수와 무관하게 같은 점수를 준다. 요청 후보들의 최솟값/최댓값이나 분위수로 정규화하지 않는다.
- 모든 항목은 정해진 0~100 척도로 변환하고 가중 평균한다. 80점은 승률 80%가 아니다. 포지션 사이 1점의 가치도 실증된 사실이 아니므로 스쿼드 자원 배분을 별도로 점검한다.
- 체형에는 공통 우열을 정하지 않는다. 역할/플레이 성향에 대한 명시적인 선호 함수와 검증 사례가 필요하다. 체형 문자열의 정수 인코딩 순서를 점수로 쓰지 않는다.
- 자료 오류·누락은 0점 성공으로 바꾸지 않는다. 해당 후보 제외와 사유, 포지션별 남은 후보 수를 보고한다. 모든 실패를 해 없음으로 묶지 않는다.

## 3. 입력과 강화 해석

입력안은 기존 명시 배치·카드 관측·강화 관측·기준 시각에 `scoring_policy_id`와 슬롯별 `profile_id`를 결합한다. 이는 내부 설계안이며 현재 HTTP/MCP 요청 필드를 추가한 것이 아니다. 서버에서 정책과 프로필을 명시 고정하고, 미지정/미등록 정책을 최신 버전으로 자동 선택하지 않는 안이다.

1. 기존 D5에 따라 배치 허용을 먼저 확인한다. 점수 프로필 대응은 등록 포지션·모델 클래스·배치 범위를 확대하지 않는다.
2. 목표 강화가 기준 강화면 `PlayerCard.stats`를 사용한다. 다르면 연결이 확인된 `ReinforceStats.stats_delta`를 기준 stats에 **한 번만** 더한다. spid·기준 카드 버전·기준 강화·목표 강화를 모두 대조한다.
3. 필요한 키의 차이값 누락을 0으로 보충하지 않는다. 복원한 값의 자료형·음수·정수 초과·정규화 정책 범위를 검증한다. 목표 강화의 OVR은 이미 절대값이다.
4. [강화 파생 계약](reinforcement-derivation-contract.md)의 원본/규칙/해시는 유지한다. 직접 관측과 파생을 구분하고 같은 보너스를 중복 적용하지 않는다. 신체·체형·발 수치에 능력치 강화 보너스를 더하지 않는다. 별도 변경 근거가 생기면 새 계약이 필요하다.
5. 사용한 모든 관측의 상태·기한·출처를 검증한다. unknown/만료 관측을 사용 가능한 자료로 승격하거나 기한을 연장하지 않는다. 응답 직전 전체 스냅샷 만료 검사를 유지한다.

프로필의 가중치가 양수인 항목에 필요한 필드는 필수다. 예를 들어 공격수 평가에 쓰지 않는 GK 능력치 누락 때문에 공격수를 제외하지 않지만, 약발 가중치가 있으면 왼발/오른발 모두 필요하다. OVR은 비교 경로의 기존 유효성 계약을 유지하며 새 점수의 누락 대체값으로 사용하지 않는다. 이행 초기에는 기존 OVR 적격 후보에서 비교하고, OVR 없이 다요소 평가만 허용할지는 별도 결정으로 남긴다.

## 4. 세부 능력치 그룹과 정규화

아래 그룹 내부 비율도 **첫 비교 실험을 위한 초안**이다. 각 행의 합은 100이다. 34개 키를 한 그룹에 한 번씩만 배정해 숨은 중복 가산을 피한다. 포지션별 조정이 필요하면 내부 비율도 정책에 기록하고 버전을 바꾼다.

| 그룹 | 기존 키와 내부 비율(%) |
|---|---|
| 주력 | speed 55, accelartion 45 |
| 슈팅 | goal_determination 30, positioning 20, shooting_power 15, mid-distance_shot 15, volley_shot 5, penalty_kick 5, composure 10 |
| 패스 | short_pass 30, long_pass 20, field_of_vision 20, cross 15, curve 10, free_kick 5 |
| 볼 다루기 | dribble 25, ball_control 25, agility 20, balance 15, reaction_speed 15 |
| 수비 | man-to-man_defense 30, tackle 30, intercept 30, sliding_tackle 10 |
| 경합·활동 | struggle 30, stamina 30, jump 15, header 15, positiveness 10 |
| GK | gk_diving 25, gk_handling 20, gk_reaction_speed 30, gk_positioning 20, gk_kick 5 |

`accelartion` 등 기존 키 표기는 호환성을 위해 그대로 썼다. 키 교정 작업을 이번 설계에 섞지 않는다. 개인기·특성은 현재 구조에 있지만 초기안에서는 점수에 넣지 않는다. 포함하려면 역할별 의미·보정표·회귀 사례를 따로 정의한다.

세부 능력치 j의 변환안은 `N_j(x) = 100 × x / U_j`이고, 그룹 점수는 내부 비율로 N_j를 평균한다. U_j는 정책에 고정한 정규화 기준이며 게임 공식 상한을 뜻하지 않는다. **합성 산술 검토용 후보는 U_j=200**이다. 기존 D7의 OVR 상한 200을 상세 능력치의 확정 상한으로 자동 전용하지 않는다.

실자료 적용 전 기존 명시 배치에 대해 범위·누락·키 의미를 오프라인 감사하고 U_j/입력 범위를 결정해야 한다. 범위 초과는 제외/사유 보고하며 자동 클리핑·상한 변경을 하지 않는 안이다. 고능력치의 한계효용을 줄이는 비선형 곡선은 후속 비교 대상으로 남기고, 이 초안에서는 약발과 신체 선호에만 비선형 규칙을 제시한다.

## 6. 약발과 신체·체형

### 6.1 약발: 단계별 비선형 점수

양발 값이 각각 1~5 등급임을 검증한 뒤 `weak_foot = min(left_foot, right_foot)`로 계산하는 안이다. bool·실수·범위 초과·누락은 거부한다.

| 약발 등급 | 변환 점수 W |
|---|---:|
| 1 | 0 |
| 2 | 15 |
| 3 | 35 |
| 4 | 80 |
| 5 | 100 |

3→4를 45점, 4→5를 20점으로 두어 사용자가 말한 차이를 표현할 수 있게 했다. 이 차이의 실제 크기는 미검증이다. 포지션별 영향은 §5 약발 가중치로 달리한다. 예를 들어 전체형 ST의 3→4 기여 차이는 `16% × 45 = 7.2점`, CB는 `2% × 45 = 0.9점`이다. 이것은 정책의 산술 결과이며 게임 내 성능 향상량이 아니다.

왼발/오른발 선호·역발 윙어·크로스 성향은 별도 역할 계약 없이는 반영하지 않는다. 약발 4 이상 같은 필수 조건도 보정과 다른 기능이다. 현재 원문 정규화/API가 지원한다고 표시하지 않고 후속 범위로 둔다.

### 6.2 신체·체형: 역할별 선호 함수

신체·체형 점수 B는 `h × H(height) + m × M(weight) + t × T(physical)`로 정의하는 안이며 h+m+t=1, 각 함수는 0~100이다. 속력·민첩성·밸런스·몸싸움 수치는 기존 그룹에서만 반영하고 B에 다시 더하지 않는다.

- H/M은 프로필별 고정 기준점 사이의 선형 보간으로 표현한다. 키/몸무게가 클수록 항상 좋다는 가정을 두지 않고, 적합 구간·상승/평탄/하락 구간을 명시할 수 있다. 기준점 밖을 자동 자르거나 외삽하지 않고 정책에 정의한 유효 입력 범위를 검증한다.
- T는 체형 문자열별 명시 대응표다. 정수 인코딩의 크기나 문자열 순서에 의미를 부여하지 않는다. 미등록 체형을 유사 문자열로 추측하지 않는다.
- 예를 들어 돌파형과 경합형의 선호표를 다르게 만들 수 있다. 이때 키·몸무게·체형이 게임 엔진에서 어떤 효과를 내는지 입증했다고 주장하지 않고 역할 선호의 근사치임을 표시한다.
- H/M 기준점·T 대응표·h/m/t·역할별 선호는 **미확정**이다. 게임에 없는 고유 모션/AI/숨은 특성을 신체 값만으로 복원했다고 표시하지 않는다.

근거가 부족한 체형 점수를 중립 50으로 카드마다 채워 넣으면 누락 자료가 유리해질 수 있다. 다음 두 정책을 분리하는 안을 권한다.

| 정책 후보 | 구성과 사용 조건 |
|---|---|
| `core-stat-foot` | 신체·체형을 정책 전체에서 비활성화하고 나머지 §5 가중치를 한 번 정규화. GK는 GK 그룹 100%. **첫 합성 검증 권장안** |
| `body-aware` | §5 전체 가중치 사용. 역할별 H/M/T와 계수가 확정·검증되어야 하며 필요한 신체 필드 누락은 후보 제외 |

두 정책은 서로 다른 해시를 가진다. 특정 카드의 누락에 따라 가중치를 재분배하거나 body-aware 실패를 core-stat-foot으로 자동 대체하지 않는다. 같은 요청에서 정책을 섞어 순위를 만들지 않는다. core 단계의 결과에 체형을 반영했다고 표시하지 않는다.

## 7. 최종 계산과 가상 비교

역할 r, 활성 항목 집합 A에 대해:

```text
S(c, r) = Σ[w(r, g) × G(c, g)] / Σ[w(r, g)]    (g ∈ A)
```

G는 세부 능력치 그룹, 약발 W 또는 신체·체형 B의 0~100 점수다. 전체형은 분모 100이고 core형은 신체·체형을 제외한 합이다. 모든 가중치는 음수가 아니어야 하며 활성 합이 0인 정책은 거부한다. 후보별로 분모를 바꾸지 않는다.

아래는 `core-stat-foot` ST의 **가상 산술 예시**다. 비교를 단순하게 하려고 각 카드의 약발 이외 활성 그룹 점수를 모두 같은 값으로 둔다. OVR에서 세부 점수를 역산한 예시가 아니다.

| 가상 카드 | 표시 OVR | 약발 | 약발 외 그룹 점수 | 기존 OVR/2 | 새 점수 |
|---|---:|---:|---:|---:|---:|
| 카드 A | 128 | 3 | 모두 70 | 64 | (74×70+16×35)/90 = 63.78 |
| 카드 B | 125 | 5 | 모두 68 | 62.5 | (74×68+16×100)/90 = 73.69 |

이 가설에서는 OVR이 낮고 다른 항목이 조금 낮아도 약발 5인 B를 선택한다. 차이가 과도한지 검증하는 것이 다음 과제다. 약발만 같게 두거나 약발 항목을 제거한 비교도 함께 수행한다. 모든 포지션/카드에서 약발이 다른 능력을 항상 이기도록 규칙을 만들지는 않는다.

연산은 유리수 또는 정확한 십진수로 하고 최종 1회만 `ROUND_HALF_UP`으로 0.01점 단위 정수 `score_units`(0~10000)로 양자화하는 안이다. 탐색·탐욕·검증은 모두 이 정수를 사용하고 화면 점수는 score_units/100으로 표시한다. 위 예시는 6378/7369 units다. 원시 구성값도 남겨 산술을 재현한다.

0.01점 미만 차이가 동점이 될 수 있으며 카드당 반올림 오차는 최대 0.005점, 11명 합계는 최대 0.055점이다. 최적 상태는 이 정수 목적에 대한 최적이다. 점수 단위·반올림 방법을 바꾸면 정책 해시도 바꾼다. 이 정밀도 역시 운영 확정 전 검토 대상이다.

`scorer_version`은 방식 식별자, 슬롯/프로필 표, 모든 가중치·정규화/신체 함수·약발표·키/강화 규칙·누락/범위 정책·점수 단위의 정규 직렬화 해시로 만드는 안이다. 엔진/스냅샷/출력 버전도 영향에 맞춰 갱신한다. 과거 버전 자동 로드/최신 선택 대신 명시 버전을 요구한다.

후속 내부 결과 필드 후보는 policy_id/hash, profile_id, score_units, display_score, components(원시값·변환값·가중치·기여), observation_refs, exclusions다. 현행 DTO에 그대로 넣을 수 있다고 가정하지 않는다. 전체 스쿼드 점수 합(0~1100)과 선수 평균(0~100)을 구별해 표시하고 필드 단위를 문서화한다.

설명은 검증된 기여와 실제 비교 대상이 있을 때만 작성한다. 예: “같은 ST 프로필에서 카드 A보다 총 9.91점 높고, 약발 항목의 기여 차이는 11.56점입니다.” 단순 선택만으로 후보 전체 최고·경기 성능 우위·승률 향상을 주장하지 않는다. LLM이 가중치나 점수를 결정하지 않으며 새 설명 모델 호출도 이번 범위가 아니다.

### 9.2 점수 타당성: 비교 정답부터 수집/확정

첫 검토 세트 제안은 포지션 프로필 8종×10쌍=80쌍이다. 약발과 OVR 충돌, 속력/가속력 균형, 공격/수비 핵심 능력, 신체 선호, GK 전용 판단을 포함한다. 같은 선수/카드의 여러 시즌·강화가 조정/평가 양쪽에 새지 않게 인물 그룹으로 나누고, 튜닝용과 보류 평가용 세트/정책 해시를 먼저 고정한다. 구체적인 분할·사용 배치·작성자는 미확정이다.

판단 기록에는 동일 역할·강화·조건의 두 카드, 선호/동등/판단 불가, 이유, 플레이 성향, 게임 버전/판단 시점을 남긴다. 가격 효과를 분리한 능력 비교와 예산 안에서의 선택을 구별한다. 복수 평가자의 불일치도 보존한다. 판단 불가·동등을 임의 승패로 바꾸지 않고 별도 분모로 보고한다.

OVR 방식과 비교할 지표는 보류 세트 선호 일치율/표본 수·포지션별 오순위, 항목을 하나씩 제거한 변화, 가중치 민감도, 누락 제외율이다. 실제 사용자 비교에서 통과할 수치 기준은 아직 결정하지 않는다. 사용률/가격은 성능 정답 대신 보조 관찰로 분리하며, 이번 작업에서는 추가 외부 자료를 수집하지 않는다.

11명 조합에서는 한 자리의 개선과 다른 자리의 손실을 맞바꾸는 사례도 평가한다. 포지션별 점수 분포와 예산 배분을 살펴 동일 가중 합산이 특정 포지션에 과도한 투자를 유도하는지 확인한다. D6 기존 합성60문제/지연 기준은 회귀로 보존하되 새 목적의 fixture/전수 오라클과 OVR 결과를 별도로 기록한다. 운영 지연·추천 품질을 기존 D6 통과만으로 보장하지 않는다.

선호 자료가 충분히 쌓인 뒤에는 쌍별 선호를 예측하는 순위 모델을 별도 실험으로 비교할 수 있다. 목표 라벨은 등록 포지션이 아니라 같은 조건의 선호/동등 판단이어야 한다. 인물 그룹 분리·보류 평가·게임 버전별 변화·설명 가능성을 검토하고 규칙 기반 기준보다 나아졌는지 확인한다. 모델 선택·학습·실행 승인은 이번 설계에 포함하지 않는다.
