## 2. 준비 도구

[FRS/evaluation/preference_prep.py](../FRS/evaluation/preference_prep.py)는 MF-2 `PreferenceSet` 계약과 평가 CLI를 그대로 사용한다. 다요소 점수를 계산하지 않고, 네트워크·DB·모델을 쓰지 않는다.

- `SelectionSpec`(`mf-pair-selection.v1`): 세트 ID·출처·배치·기준 시각·정책 버전·프로필 순서·프로필당 쌍/보류 수·시드·강화(5만)·OVR 차이·주력 차이를 모두 명시한다. 기본값은 없다.
- 적격성: 기준 시각에 사용 가능, 슬롯의 등록 계열 기본 배치, OVR 있음, 정책이 요구하는 필드 문제 없음. 제외는 사유별로 센다.
- 후보: 같은 슬롯·다른 인물·OVR 차이 ≤ 2이고, 약발 등급이 다르거나 `speed+accelartion` 합 차이 ≥ 10. 같은 두 카드는 프로필마다 한 번만 두며, 정렬 순서상 첫 슬롯을 쓴다.
- 추출: `Random(123)`으로 프로필 순서대로 정렬한 후보를 섞고, 이미 쓴 인물이 없는 쌍을 고른다. 고른 쌍마다 A/B 순서를 무작위로 정하고, 프로필별 보류 평가용 1쌍을 뽑는다. 규칙 설명은 `selection_rule_version`으로 해시한다.
- 판단 양식(`form.html`): 카드 이름·시즌·spid·강화·등록 포지션·키·몸무게·체형·양발과 약발·개인기·특성·34개 능력치(그룹별)·관측 배치/시각을 보여준다. **OVR·다요소 점수·방식의 선택·가격·급여·사용률·팀컬러·정책 가중치는 넣지 않는다.** 판단은 선호 A / 선호 B / 동등 / 판단 불가와 근거, 공통 판단자 ID(가명)·플레이 성향이다. 입력 중에는 브라우저 저장소에 임시 저장하고, "판단 파일 저장"으로 `judgments.json`(`mf-judgment-sheet.v1`)을 내려받는다. 판단 시점은 해당 쌍을 마지막으로 바꾼 시각이다.
- 가져오기: 판단 전 세트 버전과 판단 파일의 버전이 같아야 한다. 판단이 이미 있는 세트, 세트에 없는 쌍, 같은 쌍 중복, 근거·시점 없는 판단은 거부한다. 판단은 `judge_kind=human`, `basis=ability`로만 기록한다. 판단하지 않은 쌍은 대기로 남는다. 기존 합성 판단을 사람 판단으로 바꾸는 경로는 없다.

```sh
python -m FRS.evaluation.preference_prep prepare \
  --material-dir <가공 배치 폴더> \
  --policy docs/examples/multi-factor-core-policy.json \
  --spec <선정 규칙 JSON> \
  --output-dir artifacts/multi-factor-evaluation/<세트ID>
python -m FRS.evaluation.preference_prep import \
  --set artifacts/multi-factor-evaluation/<세트ID>/set.pre.json \
  --judgments <내려받은 judgments.json> \
  --output artifacts/multi-factor-evaluation/<세트ID>/set.judged.json
python -m FRS.evaluation.multi_factor \
  --set artifacts/multi-factor-evaluation/<세트ID>/set.judged.json \
  --policy docs/examples/multi-factor-core-policy.json \
  --material-dir <가공 배치 폴더> \
  --output artifacts/multi-factor-evaluation/<세트ID>/report.json
```

`prepare`는 폴더의 `report.json`에 기록된 `player_card.jsonl` 해시와 실행 ID가 실제 파일·명시 배치와 다르면 중단한다. 세 명령 모두 기존 출력을 덮어쓰지 않는다.

## 4. 판단 방법

1. `artifacts/multi-factor-evaluation/mf2-pilot-20261022-b/form.html`을 브라우저로 연다(로컬 파일, 서버 불필요).
2. 위쪽에 판단자 ID(가명, 영문·숫자·`-`/`_`)와 플레이 성향을 적는다.
3. 각 쌍에서 같은 슬롯·5강 기준으로 능력만 보고 A 선호 / B 선호 / 동등 / 판단 불가 중 하나를 고르고 근거를 적는다. 쌍이 판단에 부적합하면 판단 불가와 이유를 적는다.
4. "판단 파일 저장"으로 `judgments.json`을 받아 전달한다. 일부만 판단해도 가져올 수 있고, 나머지는 대기로 남는다.

판단을 받은 뒤 가져오기·평가를 실행한다. 판단 전후의 세트 버전을 모두 기록하고, 판단 파일 SHA256을 함께 남긴다.

## 5. 판단 후 평가 절차 (고정)

- 같은 비교 가능 분모에서 OVR과 정책을 비교하고, 판단 불가·동등·자료 제외·미지원 기준·대기 쌍을 따로 보고한다. 슬롯·프로필별 결과와 오순위 사례를 보존한다.
- 항목 제거·민감도는 조정용 16쌍에만 적용한다. 가중치 조정은 이번에 하지 않는다. 조정하려면 변경 범위·절차를 먼저 정하고, 보류 평가 결과를 본 뒤 가중치·쌍·판단을 바꾸지 않는다.
- 판단이 부족하면 미평가 또는 표본 부족으로 보고한다. 24쌍 파일럿은 프로필별 보류 평가 1쌍뿐이라 포지션별 결론을 낼 수 없다.

## 6. 검증과 제한

- 신규 합성 테스트 21개([tests/test_multi_factor_preference_prep.py](../tests/test_multi_factor_preference_prep.py)): 결정적 추출·입력 순서 무관, 프로필별 2:1, 인물 중복 없음, 다요소 점수 미계산, OVR 차이·대비 규칙, 부족분 보고(규칙 완화·인물 재사용 없음), 적격성 제외 사유(배치·기한·필드), 규칙·정책·프로필·배치·중복 오류, 양식의 OVR·점수·가중치 미노출과 HTML 이스케이프, 판단 템플릿·가져오기(사람 판단 표시·판단 전 세트 불변·중복/누락/버전 오류), 합성 판단 세트의 재표시 거부, CLI 준비→가져오기→평가와 해시 불일치 거부.
- 합성 카드로 만든 양식을 jsdom으로 열어 판단 2건 입력→저장→가져오기를 확인했다(판단 2건, 대기 22쌍). 실제 양식에는 판단을 입력하지 않았다.
- **선택 편향**: OVR이 비슷한 쌍만 골랐으므로 이 쌍에서는 OVR의 선택이 거의 무작위에 가깝다. 결과는 "OVR이 비슷하고 약발·주력이 다른 카드" 범위의 비교이며, 전체 카드에서 다요소 정책이 OVR보다 낫다는 근거가 아니다.
- 슬롯은 같은 카드 쌍이 여러 슬롯에 적격일 때 정렬상 첫 슬롯(예: st는 LS)을 쓴다. 점수 키는 같은 프로필이다.
- 새 수집·모델/metadata 호출·학습·DB 쓰기·서버 교체·배포, MF-3 연결·새 목적·동점 예산 정책은 없다. 실제 카드·판단·선수별 결과·상세 보고서는 Git에 넣지 않는다.
