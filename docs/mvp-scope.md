# MVP 범위와 보관 정책

2026-10-18 사용자 답변을 기준으로 한다. 실행 중 선택한 제품 값을 임의의 기본값으로 대체하지 않는다.

## D2: 로컬 무기한 보관

사용자는 원본·가공·백업·모델 모두 기한 없이 보관하기로 결정했다. 기한에 따른 자동 삭제를 하지 않는다. 보관 정책은 신선도와 별개이며 오래 보관한 값을 최신 추천에 계속 사용할 수 있다는 뜻은 아니다.

구현에서는 기존 `.gitignore`에 포함된 다음 디렉터리를 사용한다. 경로는 로컬 저장 구현을 위한 구분이며 사용자에게 이 경로 자체를 지정받은 것은 아니다.

| 구분 | 로컬 경로 |
|---|---|
| 원본 | `data/raw/` |
| 가공 | `data/processed/` |
| 백업이 만들어지는 경우 | `backups/` |
| 학습 산출물 | `artifacts/models/` |

이 결정으로 백업 작업·외부 저장소 연결을 자동 생성하지 않는다. 실제 데이터·학습 산출물은 커밋하지 않는다. 데이터 레코드의 `delete_after`는 필수 필드이며 기한 없음은 명시적인 `null`로 저장한다. 필드 누락을 무기한 보관으로 간주하지 않는다.

이 기록은 프로젝트 운영 정책이다. 제공자가 웹 데이터의 무기한 저장·학습·공개를 허용했다고 확인한 기록은 아니다. 0-B의 미확정 상태와 지속·대량 수집 제한은 유지한다.

## D3: 첫 MVP

- 팀컬러: 클럽 팀컬러만 추천 조건으로 지원
- 강화: 5~11단계, 양 끝 포함
- 포메이션: 4-2-3-1, 4-1-2-3, 4-2-2-2
- 팀컬러 발동 단계·필요 인원·동일 인물 중복 등 조합 규칙은 D5에서 별도 확정

[공식 스쿼드 메이커](https://fconline.nexon.com/squadmaker)의 비로그인·빈 스쿼드 화면에서 선택해 확인한 슬롯이다. 선수 추가·스쿼드 저장·게시·로그인은 하지 않았다. 4-2-3-1은 Stage 0에서, 나머지 2종은 D3 답변 후 확인했다.

| 포메이션 | 11개 슬롯 |
|---|---|
| 4-2-3-1 | GK, RCB, LCB, RB, LB, RDM, LDM, CAM, RAM, LAM, ST |
| 4-1-2-3 | GK, RCB, LCB, RB, LB, CDM, RCM, LCM, ST, RW, LW |
| 4-2-2-2 | GK, RCB, LCB, RB, LB, RDM, LDM, RM, LM, RS, LS |

중앙·좌우 슬롯은 서로 다른 값으로 유지한다. 특히 4-2-2-2의 RM·LM을 RAM·LAM으로 바꾸거나 RS·LS를 ST 두 명으로 바꾸지 않는다. 선수의 슬롯 배치 허용 기준은 이 슬롯 표만으로 확정되지 않으며 D5·Stage 3에서 다룬다.

스키마는 클럽·국가·특성·강화 소속 정보를 유형별로 구분해 저장할 수 있고, MVP 추천 지원 여부는 별도 범위 정책으로 제한한다. 원본에 다른 강화·팀컬러가 존재한다는 사실을 MVP가 지원한다고 해석하지 않는다.
