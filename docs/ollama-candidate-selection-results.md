# C4 실제 로컬 ID 선택 비교

2026-10-20 / 데모 W3·Stage 4-A. [승인 계약](candidate-ollama-comparison-contract.md)에 따라 ID 선택 전송기와 1회 비교기를 구현했다. 실제 비교 범위는 후보 준비·모델 선택·엄격 ID 검증/원문 복원·기존 정규화까지다.

## 구현과 합성 검증

`ollama_selection.py`는 준비된 원문/후보 ID·필드·문맥을 로컬 모델에 보내고 위치 인덱스를 생성시키지 않는다. 요청 JSON schema는 현재 candidate_set_id만 고정하고 ID 배열을 요구한다. ID의 존재/필드/전체 출현 커버리지·원문 바인딩은 기존 디코더가 독립 검증한다. 누락/충돌도 후보를 모두 유지하며 선택 오류를 기본값·다른 모델·재호출로 복구하지 않는다.

`ollama_transport.py`에 고정 loopback HTTP/기한/상한/안전한 오류 처리를 공통화했다. 기존 직접 구간 추출기는 공개 import·프롬프트·요청/출력 계약을 유지하고 공통 전송기를 호출한다. 재귀 한도 초과 JSON도 안전한 오류로 반환한다. 이전 실행 당시 소스 해시는 당시 커밋의 기록이며 현재 리팩터링 파일에 다시 적용하지 않는다.

`candidate_comparison.py`의 기본 실행은 계획 출력이다. 실제 실행은 승인 root의 단일 잠금·고유 실행 ID를 요구하며, 준비 실패는 추론 시도 번호 없이 기록한다. 전송 전 pending/시도 번호를 fsync하고 프로세스 중단 시 미상 시도를 보존한다. 서버/연결/기한/비정상 envelope는 전체 중단, 완료된 잘못된 JSON/ID/길이 중단 응답은 개별 품질 실패로 기록한다. 기존 원본/잠금 초기화·자동 재개는 없다.

합성 신규 37개·전체 pytest 1,354개, Ruff 린트/포맷, 환경 import·pip check가 통과했다. 테스트는 MockTransport/대역만 사용하고 실제 모델·외부 요청을 호출하지 않았다. 원문/집합 변조·동일 값 출현 보존·동일 모델 설정·추적 비활성화·안전한 지표·HTTP/redirect/기한/바이트/JSON 오류·pending 선기록·1회 잠금·실패 미호출을 확인했다. 기존 직접 구간 41개도 회귀 통과했다.

## 실행 재현과 경계

계획 확인: `.venv/bin/python -m FRS.agent.candidate_comparison`. 이미 승인한 1회 명령은 `--run --run-id candidate-selection-20261020-001`이다. 실행 디렉터리는 `artifacts/candidate-comparisons/approval-20261020-001/candidate-selection-20261020-001/`이며 Git에서 제외한다. 실행이 종료되면 이 명령을 재실행하거나 승인 잠금을 삭제하지 않는다.

고정 사례는 기존 complete/missing/unsupported/conflicting/decimal_list와 commas_order/same_budget_twice다. 신규 정답도 후보 생성 결과와 독립된 수동 원문 구간으로 미리 고정했다. unsupported는 기존 문장 중간 마침표·미지원 제외 조건 때문에 준비 단계에서 명확화한다. 이 입력은 별도 준비 차단 평가이며 모델 성공에 포함하지 않는다. 모델별 실제 6사례 중 missing/conflicting은 근거가 맞아도 정상적으로 명확화해야 한다.

두 모델은 temperature0/seed123/num_ctx4096/num_predict1024/think=false/stream=false/keep_alive=0을 공유한다. 120초는 요청 전체 전송 기한, 응답은 최대128KiB다. 매 요청 모델 해제를 하므로 측정 지연은 모델 로드 비용을 포함한다. 상주 모델/동시 요청의 서비스 지연 목표가 아니다.

## 남은 한계

파서가 정형 문형의 필드를 이미 결정한다. 성공률은 ID 선택과 근거 복원 계약의 제한된 소량 검증이며 일반 자연어 해석 개선을 뜻하지 않는다. 원문/문형/분모가 다른 이전 직접 구간 결과 0/5와 단순 개선율로 비교하지 않는다. candidate_set_id의 schema 고정 역시 모델의 원문 이해 정확도가 아니다.

이번 실제 비교에서 스쿼드 엔진·DB·넥슨·실데이터·API/SSE·웹 연결을 실행하지 않는다. 실제 모델의 엔진/웹 E2E, 운영 모델 선정·동시성/취소·평가 확대는 후속이다. 프론트엔드 파일/WEB-*·기존 core/graph/presentation·수집 원본/모델은 변경하지 않는다. Stage1-D/1-F·제공자 허용 상태도 그대로다.
