# 로컬 조건 추출 어댑터와 1회 비교

2026-10-20 / 데모 W3·R4, Stage 4-A 실제 추출의 준비 증분. 모델 호출과 정규화·스쿼드 계산을 분리한다. 웹 파일과 HTTP/SSE 서버는 변경하지 않는다.

## 구현

`FRS/agent/ollama.py`는 설치된 qwen3.5:2b·qwen3:8b만 받는다. 목적지는 고정 loopback `http://127.0.0.1:11434/api/chat`이며 환경 프록시·리다이렉트·재시도·다운로드가 없다. 동기 `extract`는 내부 비동기 HTTP 전체를 120초 기한으로 감싼다. 이벤트 루프가 실행 중인 웹 핸들러에서 직접 호출하는 용도가 아니며 향후 API 실행 계층은 별도로 정한다.

원문과 코드포인트 문자표를 JSON 데이터로 전달하고 여섯 배열의 JSON Schema를 요구한다. 누락 기본값·추가 필드·중복 JSON 키·비유한 값·bool 인덱스·잘못된 구간 구조를 거부한다. 원문과 다른 오프셋을 이동하거나 찾기 검색으로 보정하지 않는다. 구조가 맞는 결과도 기존 정규화기의 원문 구간/값 검증을 통과해야 엔진에 도달한다. 모델이 빠뜨린 조건·부정·미지원 절의 의미를 스키마만으로 보장하지 않는다.

응답은 최대 128KiB, 완료/모델명/assistant 역할을 대조한다. 생성 길이 제한 도달은 실패이며 초안으로 성공을 만들지 않는다. 안전 오류 코드를 사용하고 모델의 별도 thinking 필드는 보관하지 않는다. 합성 비교의 content·추출 결과·선택한 토큰/지연 통계는 Git 제외 로컬 기록에만 보관한다.

## 고정 비교 계획

기존 사용자 승인: 같은 합성 5문장을 두 모델에 각각 한 번, 총 최대 10회, 순차·각 120초·재시도/다운로드/외부 전송 없음. 정상·급여 누락·미지원 선수 제외·상충 예산·소수 예산/강화 목록을 사용하며 정답과 문장을 실행 전에 고정한다.

실험 설정은 temperature 0, seed 123, num_ctx 4096, num_predict 1024, think=false, stream=false, keep_alive=0이다. 두 모델을 같은 조건으로 비교하려는 시험 설정이며 서비스 운영 기본값은 아니다. 각 요청의 모델 해제/로드 시간을 포함하므로 따뜻한 서버의 SLA로 해석하지 않는다. 긴 4,000자 원문이 이 컨텍스트에 모두 들어간다는 보장은 없고 이번 5문장은 짧은 소량 진단이다.

실행 계획에는 프롬프트·스키마·설정·사례·정답·소스 파일 해시를 고정한다. 읽기 전용 사전 점검은 Ollama 버전/태그/모델 정보 최대 4 HTTP 시도이며 추론 횟수와 구분한다. 각 추론을 보내기 전에 pending 시도를 파일에 기록·flush/fsync하고, 실패·결과 미상도 최대 횟수에 포함한다. 첫 실행 잠금을 생성하며 다른 ID로 같은 승인 실행을 반복하는 것도 거부한다. 네트워크/HTTP/전체 기한/불명확한 응답은 즉시 중단한다. 완료가 확인된 잘못된 추출은 해당 사례 실패로 기록하고 다음 별도 사례만 진행한다.

원문 구간 일치, 근거 전체의 정확 일치, 정규화 조건/되묻기 사유의 의미 일치를 나눠 측정한다. 5개 소량 결과는 전체 한국어 정확도·프롬프트 공격 내성·Agent 운영 SLA를 증명하지 않는다. 실제 모델 선정과 추가 실행은 관찰 결과/사용자 범위에 따른다.

## 실행과 중단 결과

기본 명령은 계획만 출력한다.

```sh
.venv/bin/python -m FRS.agent.comparison
```

실제 비교는 사용자가 승인한 실행에서만 `--run --run-id <고유ID>`를 사용한다. 잠금/manifest를 삭제·초기화하거나 남은 횟수를 새 승인으로 해석하지 않는다. 새 승인 이후에는 원래 기록을 보존하고 별도 승인 디렉터리/ID를 사용한다.

첫 실행 `ollama-extraction-20261020-001`은 `/api/version`의 첫 사전 점검에서 연결 거부로 종료했다. 사전 점검 시도 1회·추론 0회다. 최초 코드의 예외 기록 상태 `interrupted_or_failed`를 소급 변경하지 않았다. 이후 코드에서 사전 점검 실패를 안전한 `stopped_preflight`/시도 수로 기록하도록 보완하고 합성 테스트로 확인했다. 실제 서버를 다시 호출해 수정 결과를 검증한 것은 아니다.

- 원래 manifest SHA256: `e73d34cb19f19250fe716bacbe92716b7377db423d374f2be68f5fa72041c552`
- 원래 계획 SHA256: `b1723da07b88b770f7a2716a26efc9927c14fdb80bed4abd4880ea9992e1e693`
- 저장: backend-agent-mvp 작업 디렉터리의 `artifacts/llm-comparisons/ollama-extraction-20261020-001/manifest.json` 및 승인 잠금. Git 제외·무기한 로컬 보관.

위 기록은 첫 실행 종료 시점이다. 이후 사용자가 서버 시작과 새 비교 1회를 승인했고 아래 두 번째 실행을 진행했다. 첫 실행을 초기화하거나 남은 횟수를 재사용하지 않았다.

## 검증과 제한

새 합성 테스트 41개는 JSON/구간/HTTP·기한·정확한 사례별 정답·시도 선기록/재실행 금지·사전 점검 중단을 다룬다. MockTransport 응답을 주입한 추출기→LangGraph→실제 CP-SAT→독립 재검증→코드 표 연결과 잘못된 오프셋의 자료/엔진 전 차단도 확인한다. 실제 모델 의미 검증과 구분한다. 전체 pytest 1,233개·Ruff 린트/포맷·환경 import·pip check가 통과했다. head 2b67f93의 CI 39379359111도 성공해 PR #64를 aeb23a4로 Squash 병합했다.

API/SSE·실제 웹 연결·운영 모델/동시성/취소·LLM 서술 사실 검증·실제 E2E는 후속이다. 1-D/1-F 전체·실데이터 추천·공식 보너스도 미완료를 유지한다. 새 넥슨 요청·실데이터 변경·학습·유료 호출·외부 추적 전송은 없다.

구현 근거: [Ollama Chat API](https://docs.ollama.com/api/chat), [Structured outputs](https://docs.ollama.com/capabilities/structured-outputs). JSON Schema는 출력 구조의 수단이며 의미 정확도는 별도 평가한다.

## 두 번째 실행 결과 — 새 승인 1회

2026-10-20 사용자 답변으로 설치된 Ollama 서버 시작·같은 조건의 새 비교 1회를 승인받았다. 한국 시간 15:29에 실행 ID `ollama-extraction-20261020-002`를 시작해 완료했다. 승인 디렉터리는 `artifacts/llm-comparisons/approval-20261020-002`다. 기존 실행/잠금을 보존하고 새 승인 잠금을 사용했다.

서버는 CLI 도움말에서 지원을 확인한 OLLAMA_HOST=127.0.0.1:11434, OLLAMA_NO_CLOUD=1, OLLAMA_NOPRUNE=1, OLLAMA_NUM_PARALLEL=1로 시작했다. 클라우드 기능·시작 시 모델 blob 정리를 끄고 기존 설치 모델을 사용했다. 사용자 요청으로 시작한 서버는 종료하지 않았다. 새 모델 다운로드·기존 모델 삭제·프로세스 강제 종료는 없다.

사전 점검 4회와 추론 10회가 모두 HTTP/어댑터 처리까지 완료됐다. 타임아웃·연결/HTTP 실패·재시도는 0회이며 모델별로 같은 5문장을 한 번씩 보냈다. 이 실행의 승인은 소진됐으며 추가 호출은 진행하지 않는다.

### 실패 진단과 선정 판단

10개 모두 하나 이상의 원문 구간이 불일치했다. 사후 진단에서도 근거 문자열 전체가 정답과 같은 사례는 두 모델 모두 0/5였다. 잘못된 인덱스를 고치는 것만으로 해결된다고 판단하지 않는다.

- 정상 요청: 금액을 여러 출현으로 잘못 나누거나 필드 접두어/문장부호를 값에 포함했다.
- 필수 급여 누락: 누락을 유지한 경우에도 다른 근거가 잘못됐고, 작은 모델은 급여 필드에 강화를 넣는 오분류도 있었다.
- 미지원 선수 제외: 미지원 근거의 경계를 잘못 잡거나 다른 조건까지 포함했다.
- 충돌 예산: 예산 근거를 접두어와 혼동하거나 값에 접두어를 포함했다.
- 소수 금액·강화 목록: 값 바깥 조사/접두어를 포함하거나 하나의 강화 목록을 별도 출현으로 나눴다.

기존 정규화는 이를 성공 조건으로 보정하지 않았고 모든 사례를 근거/조건 오류로 거부했다. 이 시험은 추출·정규화 비교이며 실제 모델로 스쿼드 엔진/웹을 실행한 E2E 시험은 아니다. 단위 테스트의 목킹 경로에서만 엔진 연결을 확인한 결과와 구분한다.

**현재 직접 구간 생성 방식으로는 두 모델 모두 채택 보류다.** 더 빠르다는 이유로 2b를, 파라미터가 많다는 이유로 8b를 운영 모델로 지정하지 않는다. 다음 선택으로 코드가 원문 후보 구간/ID를 만들고 모델은 ID를 선택하는 어댑터 설계, 또는 현재 계약의 프롬프트 개선 설계를 사용자에게 질문했다. 새 계약·코드·추가 추론은 이번 결과에서 자동 승인하지 않는다.
