### 2. 스쿼드 구성의 입력과 제약 — 0:15–0:50 (35초)

예산, 급여, 클럽, 포메이션, 허용 강화가 필수 다섯 조건입니다. 한 선수씩 고르는 방식으로는 전체 예산과 자리를 동시에 맞추기 어렵고, 같은 인물의 다른 카드도 중복하면 안 됩니다. 화면의 요청으로 평가한 N01은 11명, 541억 BP, 급여 205를 반환했고 최적성을 확인했습니다. OVR 합은 1,033입니다. 이 수치는 모두 저장된 합성 선수와 가상 가격 결과입니다.

근거: docs/stage-w6-model-evaluation.md N01, docs/ai-mini-project-results.md §1–4. 실데이터·경기 성능 평가가 아님.

### 3. 조건 해석과 조합 탐색의 역할 분담 — 0:50–1:35 (45초)

코드가 먼저 원문 후보와 ID를 만듭니다. qwen3:8b는 후보 ID를 어떤 조건에 연결할지 선택합니다. 모델이 새 금액이나 선수를 만들어 넣지 않도록 제한한 구조입니다. 코드가 ID와 필드, 원문 근거를 검증하고 금액을 정확한 정수 BP로 바꿉니다. 유효한 조건만 고정 스냅샷과 CP-SAT에 전달하고, 별도 검증기가 예산과 급여, 중복과 배치, 만료를 다시 확인합니다. LangGraph는 이 명시적 흐름을 관리하고 Vue와 SSE가 진행 상태를 전달합니다. MCP는 로컬 stdio로 구현했으며 독립 Multi-Agent는 구현하지 않았습니다.

근거: docs/ai-mini-project-results.md §2, docs/stage-w5-mcp-implementation.md. 실제 LLM MCP Tool-use와 새 Q&A 웹 연결은 미검증.

## 예상 질문

- **96%와5/7은 무엇인가?** 24/25는 스쿼드 전체 최종 응답이고 준비 처리9개를 포함한다. 모델 의미는15/16이다. 5/7은 별도 문서 Q&A 사전 검사다.
- **정답을 검색했는데 왜 RAG가 실패했나?** K03은 정답 구간을 입력으로 받았지만 모델이 근거 부족으로 응답했다. 검색 성공을 전체 답변 성공으로 세지 않았다.
- **K05는 시세를 지어냈나?** 빈 답변/근거 부족을 선택했지만 출처를 남겨 계약 위반으로 거부했다. 기대한 정상 근거 부족 안내에 실패했다.
- **RAG가 스쿼드를 생성하나?** 별도 Q&A이며 기존 엔진의 예산/급여 계산이나 선수 선택은 변경하지 않았다.
- **LangSmith에 무엇을 보냈나?** 단계 관계/시간/상태·제공 토큰·corpus/생성기 종류의 최소metadata다. 원문·답변·검색 본문·비밀값은 trace 본문에 없다. 키는 인증 헤더에만 썼다.
- **Multi-Agent도 구현했나?** LangGraph의 명시 워크플로우다. 독립 역할의 런타임 Multi-Agent는 미구현이다.
- **MCP를 실제 모델이 호출했나?** 로컬 stdio 직접/도구12사례 대조다. 일반 호스트와 실제 LLM Tool-use는 미검증이다.
- **라이브 시연이 가능한가?** 현재 자료는 저장 결과다. 종료된 실행의 승인/잠금을 재사용하지 않는다. 추가 실제 모델/수신 조회/브라우저에는 새 범위가 필요하다.
