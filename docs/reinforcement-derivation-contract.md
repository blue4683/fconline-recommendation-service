# 강화 능력치 파생 설계 - 1강 기준, 1~13강 계산

2026-10-20 사용자 요청/후속 결정. 강화에 따른 공통 능력치 상승을 규칙으로 관리하여 **1강 기본 능력치에서 1~13강 능력치를 계산하는 방향**을 채택한다. **MVP 추천 허용 범위는 5~11강을 유지한다.** 이번 변경은 계획/계약 문서이며 계산기·수집기·기존 데이터·추천 코드·학습 모델은 변경하지 않는다.

## 규칙과 출처

첨부 표의 총 누적 OVR을 1강 대비 누적 보너스 B(level)로 전사했다. 사용자 설명은 이 증가가 모든 상세 능력치에 공통 적용된다는 것이다. 단계마다 +1씩 증가하는 식이 아니라 아래 누적표를 사용한다.

| 강화 | 1강 대비 누적 보너스 |
|---:|---:|
| 1 | 0 |
| 2 | 1 |
| 3 | 2 |
| 4 | 4 |
| 5 | 6 |
| 6 | 8 |
| 7 | 11 |
| 8 | 15 |
| 9 | 17 |
| 10 | 19 |
| 11 | 21 |
| 12 | 24 |
| 13 | 27 |

- 상세 능력치: `stat(level) = stat(1) + B(level)`.
- 기준 강화 b와 비교할 차이값: `delta(b→level) = B(level) - B(b)`.
- 기준 1강에 해당 포지션 OVR 키가 존재하면 `OVR(position, level) = OVR(position, 1) + B(level)`로 파생하는 설계다. 없는 OVR 키를 만들거나 다른 포지션으로 대체하지 않는다.
- 예를 들어 5강 대비 6~11강 차이는 각각 +2/+5/+9/+11/+13/+15다. 5강 관측에 1강 기준 누적값 +8/+11 등을 다시 더하지 않는다.

출처는 사용자 제공 이미지와 설명이다. 이미지 SHA-256은 `e9f061d3f0c6aefb93631f28b5278757342e82b0d85d779151f73da9a7f78adc`다. 이미지의 원래 게시 URL/적용일은 제공되지 않았으므로 공식 최신 규칙을 별도로 확인한 것으로 기록하지 않는다. 강화 성공 확률은 이번 능력치 파생·가격 계산에 사용하지 않는다.

## 기존 자료로 확인한 범위

추가 HTTP·원본 재수집 없이 보관된 가공 관측을 읽기 전용으로 대조했다. 1-B의 104장·1-D의 259장 두 배치를 독립적으로 집계했으며 배치 사이의 동일 카드 중복을 제거한 고유 카드 수로 해석하지 않는다. 카드 버전·기준 5강을 맞춘 뒤 stats_delta와 동일 OVR 키의 직접 관측 차이를 B(level)-B(5)와 비교했다.

| 배치 | 6~11강 행 | 상세 능력치 비교 | OVR 비교 | 불일치 |
|---|---:|---:|---:|---:|
| stage-1-b-20261018 | 624 | 21,216 | 9,984 | 0 |
| stage-1-d-enrichment-20261019 | 1,554 | 52,836 | 24,864 | 0 |
| 합계 | 2,178 | 74,052 | 34,848 | 0 |

각 행의 34개 능력치 키는 기준 카드와 일치했고, 대조한 강화 OVR 키는 모두 기준 OVR에 존재했다. 5강 자체 차이 0 검사는 위 수치에서 제외했다. 이 분석은 기존 가공값 간 규칙 대조이며 원본 HTML/해시 전체를 새로 재검증한 것은 아니다. 기존 원본 대조 결과는 [파일럿](stage-1-b-parser-pilot.md)·[상세 보강](stage-1-d-enrichment.md) 기록을 따른다.

**1~4강·12~13강의 새 실측과 1강 기반 전 구간 대조는 이번에 수행하지 않았다.** 사용자 규칙 채택, 이미지 전사 확인, 기존 5→6~11 관측 일치를 구분한다. 기존 unknown·기한·원본·배치를 승격/수정하지 않았다.

## 데이터 경계

| 항목 | 처리 |
|---|---|
| 상세 능력치 34개 | 강화 보너스를 적용할 명시 목록으로 관리. 실제 자료는 1강 원본과 규칙을 근거로 파생 |
| 포지션별 OVR | 존재하는 기준 포지션 키에 같은 누적 보너스. 결과는 절대 OVR로 저장/전달 |
| 가격 | 능력치와 독립. 카드×강화별 참고가격 관측/신선도가 필요하며 이 표로 생성하지 않음 |
| 급여 | 능력치 표의 적용 대상 아님. 현재 별도 관측·강화/능력치 버전 결합 계약 유지. 강화 간 동일 여부를 이 표로 가정하지 않음 |
| 키·몸무게·체형·개인기·왼발·오른발·특성 | 숫자라고 일괄 가산하지 않음. 필요한 강화별 별도 규칙/관측을 확인하고, 변경/불변 여부를 이 표만으로 확정하지 않음 |
| 등록 포지션·팀컬러 | 기존 자료/자격 계약 유지. 강화 능력치 파생으로 공식 발동/보너스 자격을 생성하지 않음 |
| 학습·확률 | 기존 5강 학습 모델·40피처 계약 보존. 1강 데이터를 기존 5강 입력처럼 전달하지 않음. 같은 카드의 파생 강화 행을 독립 카드 표본으로 보지 않음 |

보관의 기본은 1강 원본과 버전 있는 보너스표이며, 필요한 강화만 계산하고 요청 스냅샷에는 계산 결과/규칙을 고정하는 안이다. 능력치 요청만 비교하면 카드당 5~11강 7회에서 1강 1회로 약 85.7% 줄일 수 있지만, 가격·급여·메타데이터를 포함한 총 요청량 절감률은 별도다. 이미 종료한 수집을 이 계산으로 다시 시작하지 않는다.

따라서 “1강만으로 처리”는 상세 능력치/존재하는 OVR의 강화 파생을 뜻한다. **추천에 필요한 모든 가격·급여·자격 자료까지 1강 관측 하나로 확보한다는 뜻은 아니다.** 새 1강 수집 실행이나 기존 종료 승인의 재사용도 포함하지 않는다.

## 현재 5강 기준 코드와의 연결

현재 scorer/placement/스냅샷/학습 입력은 기본 5강·추천 5~11강에 맞춰 검증돼 있다. 다음과 같이 1강 자료를 현재 계약에 연결하는 호환 경로를 설계한다.

1. 1강 원본을 원본 강화/관측 시각/해시 그대로 보관한다. 기존 5강 원본이나 모델을 덮어쓰지 않는다.
2. 명시한 1강 기본값과 규칙으로 현재 계약용 5강 기본 능력치/OVR를 계산한다: 기본값+6.
3. 6~11강의 stats_delta는 `B(level)-6`, OVR는 `OVR(1)+B(level)`의 절대값으로 만든다. baseline_card_version은 새 파생 5강 버전을 참조한다.
4. 가격·급여·자격은 각각의 검증 배치와 결합한다. 파생 능력치가 있어도 필수 자료가 없거나 충돌/만료이면 후보에서 제외한다.
5. 계산 가능 범위 1~13과 추천 허용 5~11을 구분한다. 정규화·API·스냅샷의 허용 범위를 이번 문서 때문에 확대하지 않는다.

호환 5강 표현은 상세 능력치/OVR에 관한 설계다. 기존 모델의 40개 입력을 완성하려면 나머지 신체·개인기·발 정보의 강화 기준도 별도 검증해야 한다. 확인되지 않은 1강 메타데이터를 5강 실측처럼 복사해 학습/추론을 진행하지 않는다.

새 파생 배치/manifest에는 원본 배치·강화·버전/해시·규칙 버전/해시·파생 대상 강화·계산식을 연결하는 안이다. **계산값을 HTTP 관측값으로 기록하지 않는다.** 이 provenance와 스키마 표현은 구현 전 계약/검증 대상이며 현재 모델이 이미 해당 필드를 지원한다고 주장하지 않는다.

파생 실행 시각은 observed_at을 대신하지 않고 추천 기한을 연장하지 않는다. 원본 unknown/기한 미확정은 자동으로 ok가 되지 않으며 규칙 변경 시 새 버전을 만든다. 기존 관측과 파생값이 불일치하면 최신값/공식처럼 보이는 값을 임의로 선택하지 않고 충돌로 보고한다. 현재 운영 OVR 1~200·OVR/2·범위 밖 카드/슬롯 제외 정책은 유지하며 큰 값을 잘라 맞추지 않는다.

## 합성 Agent 계획 반영과 구현 게이트

[과제 로드맵](ai-mini-project-roadmap.md)의 W1에서 합성 기본 1강 + 버전 있는 보너스표로 강화 능력치/OVR를 생성하고, 기존 추천에는 호환 5강/5~11강 표현으로 전달하는 방향을 반영한다. 가상 가격·급여·자격은 명시한 합성 규칙으로 별도 생성하며 실데이터 예측값으로 소개하지 않는다. 반복 강화별 실제 능력치 요청은 향후 검증된 예외 표본만 남기는 방향으로 줄인다.

향후 구현은 누적표 전 13단계·5강 기준 차이·역변환/이중 가산 방지·기준/규칙 해시·절대 OVR·누락/충돌/범위 오류·unknown/기한 유지·가격/급여 미생성·기존 1,097개 회귀를 검증해야 한다. 새 기능 코드·실데이터 파생 파일·새 수집·추천 실행·학습은 이번 문서 변경에서 수행하지 않았다.
