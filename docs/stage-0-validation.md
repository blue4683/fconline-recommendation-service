## 판단

능력치·급여·포지션별 OVR·가격을 읽을 기술적 경로는 확인했다. 기존 상세 페이지 파서를 그대로 재사용할 수는 없지만, 별도 HTML 응답을 파싱하는 방식으로 구현할 수 있다. 가격의 의미·갱신 주기, 팀컬러의 전체 규칙, 동일 인물 중복 제한은 추가 확인이 필요하다.

Stage 0 전체를 완료로 처리하지 않는다. D1의 실데이터 방향과 저장·학습 요청은 확정됐으나, 0-B의 지속 수집·이용 허용 범위와 D2의 보관 기간·삭제 방식은 남아 있다. 경로와 무관한 Stage 1-0 코드 정비는 `AGENTS.md`에 따라 진행할 수 있다. 이는 설계도의 Stage 0 전체 종료 후 Stage 1 진입 원칙보다 저장소 지침의 공통 작업 허용 규칙을 우선한 것이다.

## 확인 방법과 실행 범위

공식 문서·공개 화면·화면이 사용하는 스크립트를 확인하고, 고정된 소수 선수에 대해 공개 상세 페이지와 능력치·가격 요청을 확인했다. 브라우저의 포메이션 선택은 저장하지 않은 임시 화면 상태로만 확인했다.

- 로그인, API 키 열람, 인증 API 호출, 접근 제한 우회는 하지 않았다.
- 실제 응답 원문은 메모리에서 확인했으며 파일·DB·테스트 fixture로 저장하지 않았다.
- 대량·주기 수집, DB 적재, 모델 학습, 애플리케이션 코드 수정은 하지 않았다.
- 패키지 설치, 가상환경 생성, DB 컨테이너 실행은 하지 않았다.
- 아래 내용은 스키마·구조·규칙에 대한 관찰 기록이다. 실제 선수 데이터셋이나 가격 이력은 포함하지 않는다.

## 0-A: 기술 조회 가능 여부

### 메타데이터와 ID

[공식 메타데이터 문서](https://openapi.nexon.com/game/fconline/?id=5)에 공개된 목록은 다음 6종이다. 이 목록에는 급여·가격 메타데이터가 없다. 공개 목록에 없다는 사실을 모든 내부 API의 부재로 확대하지 않는다.

| 파일 | 용도 / 확인 결과 |
|---|---|
| `matchtype.json` | 매치 종류 |
| `spid.json` | 선수 카드 ID. 88,359건은 같은 날의 검토 1 기록을 인용했으며 이번 작업에서 재조회하지 않음 |
| `seasonid.json` | 이번 조회 153건. 필드: `seasonId`, `className`, `seasonImg` |
| `spposition.json` | 이번 조회 29건. 필드: `spposition`, `desc` |
| `division.json` | 등급 |
| `division-volta.json` | 볼타 등급 |

공식 문서는 `spid`를 시즌 ID 3자리와 선수 ID 6자리의 결합으로 설명한다. 정수형에서 `season_id = spid // 1_000_000`, `pid = spid % 1_000_000`으로 분리할 수 있다. 이 분리 규칙만으로 동일 인물 카드의 게임 내 동시 배치 가능 여부까지 증명되지는 않는다.

위치 메타데이터는 중앙·좌우 슬롯과 `SUB`를 구분한다. 포메이션 슬롯을 단순히 `CM`, `ST` 등으로 축약하기 전에 이 차이를 보존해야 한다.

### 상세 페이지와 능력치 응답

고정 회귀 샘플 베컴·굴리트·라울·자이르-에머리의 공개 상세 페이지 4건은 HTTP 200이었다. 네 페이지의 기본 HTML에는 기존 파서가 찾는 `.info_ab`, `.info_etc`, `.content_bottom`이 없었고, 모두 `DataCenter.GetPlayerAbility(...)`를 통해 별도 내용을 불러왔다. 네 선수에 대해 기존 파서 함수를 실행한 결과는 아니다.

[공식 데이터센터 스크립트](https://fconline.nexon.com/Scripts/datacenter/datacenter.js)에서 다음 경로를 확인했고, 베컴의 강화 1·2단계에 대해 응답을 확인했다.

| 항목 | 확인 결과 |
|---|---|
| 요청 | `POST https://fconline.nexon.com/datacenter/PlayerAbility` |
| 인코딩·응답 | URL 인코딩 폼 입력 → HTML 조각. JSON 응답이 아님 |
| 입력 | `spid`, `n1Strong`, `n1Grow`, `n4TeamColorId`, `n4TeamColorLv`, `n4TeamColorId_Enhance`, `n4TeamColorLv_Enhance`, `n4TeamColorId_Feature`, `n1Change`, `strPlayerImg` |
| 부가 입력 | 화면 스크립트의 캐시 방지용 `rd`는 검증 요청에서 생략 |
| 로그인 | 이번 단건 검증은 로그인·특수 헤더 없이 HTTP 200 |
| 기존 선택자 | 응답 조각에는 `.info_ab`, `.info_etc`, `.content_bottom`이 존재 |
| 급여 | `.pay` / `.pay_side`에서 확인 |
| 포지션별 OVR | `.ovr_set` 안에서 `position`, 포지션 코드, `value` 클래스를 가진 요소로 확인 |
| 강화 | 화면에는 1~13 선택지가 존재. 실제 요청은 1·2단계만 검증 |

강화 1·2단계에서 능력치 값이 달라졌고, 해당 표본의 급여는 같았다. 모든 선수·단계에 대해 급여 불변이나 1~13단계 요청 성공을 검증한 것은 아니다. 성장·팀컬러 입력도 있으므로 후속 수집에서는 강화 외 조건의 기준값을 고정해야 한다. 포지션별 OVR 제공은 D7의 선택 근거이며, 성능 점수 방식을 확정한 것은 아니다.

### 가격

같은 공식 스크립트의 `POST /datacenter/PlayerPriceGraph`는 `spid`, `n1strong`을 입력받는다. 부가 `rd` 입력을 생략한 강화 1단계 단건 요청에서 로그인 없이 HTTP 200 HTML 조각을 받았다.

응답에는 시세·현재가 표시, 7/30/90/180/365일 구간, 차트 데이터 스크립트가 있었다. 표본에서는 `만` 단위 표기를 확인했다. 다음은 여전히 미확정이다.

- 현재가가 기준가·최근 체결가·다른 지표 중 무엇인지
- 가격 갱신 빈도와 수집 이후 추천에 쓸 수 있는 신선도
- `조`·`경` 등 다른 단위와 품절·미제공·비정상 응답의 전체 표현
- 선수·강화 단계별 제공 범위와 지속적인 요청 허용량

공식 매치 API 문서의 갱신 안내를 시장 가격의 갱신 주기로 전용하지 않는다. 구현 시 가격 상태·관측 시각·의미를 따로 남기고, 표시된 숫자를 실제 구매 가능 가격으로 보장해서는 안 된다.

### 매치 API와 계정

[매치 상세 공식 문서](https://openapi.nexon.com/game/fconline/?id=3)의 `GET /fconline/v1/match-detail` 응답 스키마에는 `matchInfo[].player[]`의 `spId`, `spPosition`, `spGrade`, `status`가 있다. `status`에는 경기 통계와 `spRating` 등이 포함된다. 출전 포지션 필드는 확인했지만 인증된 실제 매치 응답은 조회하지 않았다. 출전 빈도나 평점을 곧바로 포지션 적합성 정답으로 간주하지 않는다.

사용자가 사용 가능한 애플리케이션·키를 보유했다고 확인했다. 키 자체를 읽거나 유효성을 호출로 시험하지 않았으므로, 이 기록은 보유 여부에 대한 사용자 확인이다.

## 0-B: 이용 허용 여부

### 기존 약관 해석의 보완

[영문 API 약관](https://openapi.nexon.com/support/terms/)과 [한국어 API 약관](https://openapi.nexon.com/ko/support/terms/)의 구조와 내용이 다르다. 앞선 검토의 8.7·8.15는 **영문 약관의 조항**이다. 한국어 문서에 동일 번호·문구가 없으므로 국내 계정에 같은 조건이 일률 적용된다고 확정하지 않는다.

영문 약관에는 API 데이터의 최대 30일 TTL·보관 제한(8.7)과 승인된 API 범위 밖의 자동 수집 제한(8.15)이 있다. 해당 문구가 존재하는 것과 현재 계정·웹 응답·학습 모델에 적용되는 범위가 확정된 것은 구분해야 한다.

한국어 약관은 별도 구조이며, 허용 범위를 벗어난 정보 복제·저장·가공·배포와 API 재제공, 무단 자동화 등에 관한 제한을 둔다. 이용 범위는 관련 정책·가이드에도 따르며 출처 표시 의무와 종료 시 데이터 삭제 규정이 있다. 동일한 30일 삭제 조항을 찾지는 못했다. 게임 문서의 30일 이내 갱신 안내를 모든 데이터·모델의 삭제 기한과 동일하게 해석하지 않는다.

[넥슨 홈페이지 이용약관](https://member.nexon.com/policy/stipulation.aspx)의 [조회된 약관 본문](https://member.nexon.com/policy/policywrapper.aspx?policytype=31&date=20240322)은 서비스로 얻은 정보의 사전 승낙 없는 복제·배포 등에 대한 제한을 포함한다. 조회 본문에서 특정 자동 수집 용어를 찾지 못했다는 이유로 수집을 허용한다고 판단할 수는 없다.
