# Stage 1-B 파서와 1회 파일럿

2026-10-18, 실데이터 경로. 사용자 승인: 회귀 4명과 시즌·포지션 층화 100명, 강화 5~11 확인을 포함한 **1회 파일럿**이다. 제공자 허용 여부는 여전히 불명확하며 Stage 1-C·지속 수집·공개 배포 승인이 아니다.

## 요청과 저장 제한

- 표본 선별·공식 메타데이터·재시도를 모두 합쳐 최대 1,000 HTTP 시도.
- 순차 요청, 모든 시도 앞에서 최소 1초 대기. timeout·연결 오류·403/429·비정상 응답·30초 초과 응답은 전체 수집을 중단한다.
- 502/503/504만 1회 재시도하며 이것도 요청 상한에 포함한다. 404는 실패로 기록하며 선별 후보에서는 제외한다. 선택한 표본의 강화·상세 응답이 없으면 완료로 간주하지 않는다.
- HTTP 클라이언트 기본 UA를 사용한다. 출처 헤더·로그인·인증 키·환경 프록시·netrc를 사용하지 않는다. 리다이렉트를 자동 추적하지 않는다.
- 고정 실행 ID `stage-1-b-20261018`의 경로를 배타적으로 생성하여 같은 승인을 새 실행에 반복 사용하지 않는다. 중단한 파일럿을 자동 재개하지 않는다. 본격적인 체크포인트 재개는 Stage 1-C 범위다.
- 요청을 보내기 전에 누적 시도를 manifest에 기록한다. 각 HTTP 시도의 상태·소요 시간·오류 종류를 검증된 `CrawlLog`로 저장한다. 능력치 강화 단계와 상세 페이지 자원을 로그 계약에 추가했다.
- 원본은 `data/raw/stage-1-b-20261018/`, 가공 결과는 `data/processed/stage-1-b-20261018/`. 두 경로 모두 Git 제외 대상이며 `delete_after=null`로 로컬 무기한 보관한다.
- 파일럿은 로컬 파일 저장까지만 수행한다. DB 적재·가격 수집·모델 학습·스케줄러를 실행하지 않는다.

## 파싱 계약

`FRS/utils/crawling/ability_parser.py`는 네트워크 없이 HTML을 모델로 변환한다. 별도 능력치 POST 응답에서 이름·등록 포지션·34개 상세 능력치·급여·포지션별 OVR·신체·개인기·주발·특성을 읽는다. 요청 선수 ID와 `skillData_<spid>`, 요청 강화 단계와 `en_level<N>`이 일치해야 한다. 능력치 누락·새 항목·비정수·상충하는 중복 값·급여 표시 불일치는 오류다.

상세 능력치의 직접 표시 숫자만 읽고, 자식 `diff` 표시를 합치지 않는다. 숫자 포지션 보정 라벨만 제외하며 정상 포지션 코드는 enum으로 검증한다. 기존 `keyword.json`의 영문 키(기존 철자 포함)를 유지한다. 키·모델 feature 계약 정리는 Stage 2-0에서 한다.

선수별 기본 관측은 강화 5이며, 6~11은 같은 배치·카드의 실제 응답과 비교한다. `stats_delta`는 강화 5의 관측값을 뺀 값이며 그 기준 강화·기본 카드 버전을 참조한다. 강화 5 자체의 차이값은 0이다. 강화 공식을 외삽하거나 누락 단계에 값을 채우지 않는다. 각 단계의 관측 OVR도 보관한다.

국적은 능력치 응답에서, 클럽 이력은 상세 페이지의 `.data_detail_club`에서 읽어 별도 유형으로 저장한다. 클럽 기록은 상세 응답의 관측 시각·해시를, 국가 기록은 능력치 응답의 시각·해시를 따른다. **경력·국적은 게임 내 팀컬러 발동 자격 확인이 아니다.** 이 기록은 모두 `unknown`이며 추천의 지원 범위는 클럽만이다.

`version`은 각 원본 응답 바이트의 SHA-256이고, `batch_id`는 파일럿 실행 ID다. 이는 응답의 출처를 추적하는 규칙이며 나중의 요청별 추천 스냅샷 계약을 대신하지 않는다. D8 신선도 기간은 아직 미확정이므로 모든 추천 데이터는 `status=unknown`, `valid_until=null`로 저장한다. 값 파싱 성공과 추천 사용 가능 상태를 구분한다.

기존 `process_data.py`·기본 추천 실행을 이 파서로 자동 전환하지 않는다. 새 파서는 명시적인 파일럿 진입점에서만 사용한다.

## 표본과 요청 계산

공식 공개 `spid.json`을 1회 읽고, 회귀 4명을 제외한 후보 200명을 시즌별 순환 방식으로 뽑는다. 시드 `20261018`과 정렬 규칙을 고정한다. 후보의 강화 5 응답에서 실제 첫 등록 포지션을 읽어 `(시즌, GK/DEF/MID/FW)`별 층을 만들고 순환 방식으로 100명을 선택한다. 입력 순서를 바꿔도 같은 표본을 선택하며 네 포지션군이 모두 있어야 완료할 수 있다.

포지션군은 파일럿의 구조 검증용 구분이다. 탐색기 배치 허용, 좌우 슬롯 매핑이나 D5·D7 점수 규칙을 확정한 뜻이 아니다. 희귀 포지션·급여 구간·지원 팀컬러별 모집단 대표성이나 Stage 1-D 커버리지를 보장하지 않는다.

| 요청 | 정상 시도 수 |
|---|---:|
| 공식 메타데이터 | 1 |
| 회귀 4 + 후보 200의 강화 5 | 204 |
| 회귀 4 + 선택 100의 강화 6~11 | 624 |
| 회귀 4 + 선택 100의 클럽 이력 상세 | 104 |
| 합계 | 933 |

추가 재시도에 사용할 수 있는 여유는 최대 67회이며 전체 상한에서 차감한다. 표본 ID·선별 후보·응답 해시·관측 시각은 로컬 manifest에 남긴다.

## 실행과 검증

다음 기본 명령은 네트워크 없이 계획을 출력한다.

```sh
python -m FRS.utils.crawling.pilot
```

승인된 1회 실행 진입점은 `python -m FRS.utils.crawling.pilot --run`이다. 실행 경로가 이미 있으면 거부하므로 재실행 목적으로 디렉터리를 삭제하거나 이름을 바꾸면 안 된다.

완료한 로컬 결과는 다음 명령으로 추가 네트워크 요청 없이 검증한다.

```sh
python -m FRS.utils.crawling.verify_pilot
```

검증기는 원본 해시·전체 시도 로그·최소 요청 간격·층화 재현·104개 기본 카드·카드별 강화 7단계·급여·34개 차이값·OVR·버전 참조·국적/클럽 분리·보관/신선도 정책을 확인한다. 주 파서와 다른 정규식 경로로 각 원본의 34개 직접 표시 숫자도 대조한다. 이는 저장된 HTML의 표시값 대조이며 별도 브라우저 렌더링 대조나 게임 클라이언트 규칙 검증은 아니다.

단위 테스트는 가상 선수·가상 클럽·합성 HTML과 목킹된 HTTP만 사용한다. 전체 933회 경로, 상한 예약·재실행 거부·403/429 즉시 중단, 구조 변경·강화 기준·관측 기간, 독립 표시 대조와 원본 변조 감지를 검증한다. 실제 응답을 fixture로 커밋하지 않는다.
