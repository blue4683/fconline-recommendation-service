# Stage 1-E 공통 후보 검색

2026-10-19. D1은 실데이터 경로를 유지하되, 사용자 결정에 따라 Stage 1-D를 미완료로 두고 **합성 자료만으로 공통 검색을 먼저 구현·검증**했다. 실제 자료의 신선도·공식 팀컬러 자격을 확정하거나 추가 수집한 작업은 아니다.

## 확정한 조회 계약

사용자는 자료 종류별 배치 ID 명시, 등록 포지션 정확 일치, 충돌 관측·미상·기한 지난 자료 제외와 사유 보고를 선택했다. 최신 배치 자동 선택·좌우 포지션 확장은 후속 스냅샷·D5에서 결정한다.

`FRS.core.candidate_search`의 `BatchSelection`에는 player_card·card_salary·card_price·reinforce_stats·team_color 배치 ID를 모두 입력한다. 자료 종류마다 수집 배치가 다를 수 있으며 하나의 배치 ID로 강제 결합하지 않는다. 비어 있는 ID·누락한 종류는 검증 오류다. 기본 강화 조회에서도 강화 자료의 배치 ID는 명시하되 해당 강화 차이값은 사용하지 않는다.

`CandidateQuery`는 등록 포지션, 급여·가격 상한, 팀컬러 이름·유형, 강화 단계, 시간대 있는 기준 시각, 배치 선택을 받는다. 상한은 정수이며 0도 빈 후보를 조회하는 유효한 값이다. 가격 상한의 기술 범위는 BSON Decimal128로 정확히 왕복하는 34자리까지다. 강화는 MVP의 5~11, 실제 지원 클럽 기본값은 리버풀·첼시·바이에른 뮌헨이다. 테스트·임시 통합 검증에만 가상 클럽 목록을 명시적으로 주입한다.

미지원 팀컬러는 `request_errors=("unsupported_team_color",)`를 반환하며 관측을 읽지 않는다. 지원 요청이라도 등록 포지션 정확 일치가 없으면 후보가 없다. 예를 들어 CB를 RCB·LCB로 자동 확장하지 않는다.

## 관측 결합과 제외 보고

후보의 검사 대상은 **선택한 player_card 배치에 존재하는 서로 다른 spid**다. 다른 자료에만 존재하는 spid와 선택하지 않은 기본 카드 배치는 검사 대상 수에 포함하지 않는다. 기본 카드 배치가 비어 있으면 검사·제외 수 모두 0이다.

자료는 선택한 배치·spid·요청 강화, 팀컬러의 정확한 유형·이름으로 연결한다. 완전히 동일한 문서는 중복 제거하며, 같은 키에서 내용이 다르면 `conflict`로 제외한다. 만료된 관측과 신선한 관측이 충돌해도 최신값을 자동 선택하지 않는다. 이는 선택한 배치를 보수적으로 검증하는 규칙이며, 과거 시점 재현을 위한 다중 버전 스냅샷 엔진은 아니다.

모든 필수 관측은 `status=ok`, `observed_at <= when < valid_until`, 삭제 기한이 있으면 `when < delete_after`를 만족해야 한다. 미상·거래 불가·stale, 미래 관측, 기한 만료는 각각 제외 사유로 남긴다. `valid_until=null`인 실데이터를 임의로 승격하지 않는다.

기본 강화에서는 급여의 version이 기본 카드와 일치해야 한다. 다른 강화에서는 ReinforceStats의 기준 강화·기준 카드 version이 기본 카드와 일치하고, 급여 version이 해당 강화 관측 version과 일치해야 한다. 기본 강화 급여를 다른 강화에 대입하지 않는다. 가격·팀컬러는 독립적인 응답 버전이므로 카드 version과 같다고 가정하지 않으며 선택 배치와 원본 관측 정보를 그대로 보존한다.

검사 순서는 기본 카드 → 필요한 강화 관측 → 급여 → 가격 → 팀컬러다. 각 카드에 첫 제외 사유 하나를 반환하여 제외 건수 합계가 중복되지 않는다. 기본 카드 단계에는 등록 포지션 확인, 강화 단계에는 기준 연결 확인, 급여 단계에는 버전과 상한, 가격 단계에는 상한을 확인한다. 양 상한은 경계값을 포함한다.

`SearchResult`는 후보 관측 묶음, `Exclusion(spid, resource, reason)`, 요청 오류를 담는다. `inspected_count = len(candidates) + excluded_count`이며 `exclusion_counts`는 자료:사유별 건수다. 결과는 spid 순서이고 성능 순위나 점수는 아니다. 능력치 차이값은 관측 묶음으로 반환하며 성능 점수를 계산하지 않는다.

## MongoDB 연결

`MongoCandidateRepository(database).search(query)`는 주입한 DB의 5개 컬렉션을 읽고 같은 순수 검색에 전달한다. UTC 인식·BSON Decimal128 변환을 적용한다. status·기간·상한을 DB에서 먼저 제거하지 않아 충돌과 제외 사유가 숨지 않게 한다. DB 장애·잘못된 저장 문서는 빈 결과로 위장하지 않고 오류로 전달한다.

`create_candidate_indexes(database)`를 명시적으로 호출할 때만 배치·강화·spid, 팀컬러 유형·이름에 맞는 비유일 인덱스를 생성한다. 검색·import는 DB를 수정하지 않는다. 충돌 증거를 임의 덮어쓰기하거나 unique 인덱스로 제거하지 않는다.

현재는 선택한 자료 배치를 메모리로 읽는다. 대량 배치의 성능, 실행 계획, 다중 컬렉션 읽기의 원자적 일관성은 검증하지 않았다. 쓰기가 끝난 배치를 호출자가 명시하는 계약이며, Stage 3-0의 스냅샷 관리·최신 선택·모든 DB 쓰기 경로의 불변성 보장은 후속 작업이다. 일반 DB 연결과 실제 자료 적재는 이번에 실행하지 않았다.

## 검증

- 전체 pytest **268개 통과**, 그중 검색 관련 합성 검사 88개. 외부 네트워크·실제 DB 접속을 막는 기본 테스트 설정 유지.
- Ruff 린트·포맷, import 환경 확인, pip check 통과.
- 기본·보조 등록 포지션, 좌우 확장 제외, 급여·가격 경계/0, 빈 배치, 미지원 팀컬러, 5종 자료별 누락·배치 불일치·충돌·미상·stale·거래 불가·만료·미래·보관 기한, 강화 기준·급여 버전 연결, 정렬·중복·제외 집계 검증.
- BSON 34자리 BP 변환과 Mongo 조회 필터·오류 전파·명시적 인덱스를 단위 검증.
- Docker를 사용자가 켠 뒤 캐시된 고정 MongoDB 7.0.45 이미지로 **인증된 임시 컨테이너**에서 실제 통합 검증 통과. 5/6강 결합, 34자리 BP, 만료·미지원·중복·충돌·인덱스 재생성 확인. 기존 DB·볼륨 미사용, 임의 로컬 포트·메모리에서 생성한 일회용 자격 증명 사용. 종료 후 임시 컨테이너·볼륨 정리 확인.

통합 검증 재현 명령은 다음과 같다. Docker와 docker-compose.yml의 이미지가 로컬 캐시에 있어야 한다. 다운로드하지 않으며 기존 .env를 읽지 않는다. 기본 pytest에는 포함되지 않는다.

```sh
.venv/bin/python -m scripts.validate_candidate_mongo
```

가상 관측의 1시간 유효 기간은 고정 테스트 입력이며 D8의 실제 신선도 정책을 정한 값이 아니다. 실존 선수·실제 수집 응답을 fixture로 넣지 않았다. Stage 1-E 공통 검색의 구현·로컬 검증은 완료했으며 원격 CI·PR 병합은 별도로 확인한다. 1-D·1-F와 Stage 1 전체의 완료를 뜻하지 않는다.
