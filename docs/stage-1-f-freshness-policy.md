기간은 사용자가 선택한 **포트폴리오 초기 운영 정책**이다. 가격 변동이나 제공자의 갱신 주기를 실증해 안전성이 보장된 기간이 아니다. 실제 운영 관측에 따라 사용자 결정으로 조정할 수 있다.

운영은 **수동 갱신 명령부터 구현하고 자동 실행은 끈다.** cron·APScheduler 설치/등록·정기 수집·외부 알림을 활성화하지 않는다. ‘갱신 간격’은 다음 갱신이 필요한 시점이며, 해당 시점에 네트워크 요청을 자동 실행한다는 뜻이 아니다. 갱신하지 못하면 기존 만료 제외 계약을 따른다.

첫 관리 대상은 완료 배치 `stage-1-d-enrichment-20261019`에서 보강한 **259개 카드의 5~11강**이다. 다른 1,078개 기본 카드나 새 후보로 대상을 자동 확대하지 않는다. 전체 1,337개는 배치 간 ID 합집합이며 최신 통합 데이터셋이 아니다.

## 기존 확정 계약과 함께 적용할 원칙

- 유효기간과 갱신 시점은 원래 `observed_at`을 기준으로 계산한다. 배치 종료 시각·재파싱 시각·프로그램 시작 시각으로 관측 시각을 바꾸지 않는다.
- 기준 시각이 `valid_until`과 같거나 이후면 추천에서 제외한다. 미상·충돌·만료 관측 제외 및 자료별 명시적 배치 ID 계약은 유지한다.
- 신선도와 품질/자격/가격 의미 검증은 별개다. 기간만 설정해 `unknown`이나 `price_type=unknown`을 자동 승격하지 않는다. 기존 수집 배치의 unknown·valid_until=null도 덮어쓰지 않는다.
- 갱신은 새로운 `batch_id`로 저장하고 기존 원본·문서·모델은 D2에 따라 로컬 무기한 보관한다. 만료는 추천에서 제외할 조건이며 삭제 시점이 아니다. 기간 기반 자동 삭제나 MongoDB TTL 삭제 인덱스를 추가하지 않는다.
- 실제 갱신을 실행하기 전에 출처별 요청량과 총 상한을 산정한다. 기존 수집 예외는 종료됐으며 이번 정책 선택은 새 외부 요청·반복 수집 허가가 아니다. 제공자 허용 0-B도 미확정이다.
- 최신 배치 자동 선택·미완료 갱신 배치의 추천 사용·실패 시 이전 기한 연장 등은 도입하지 않는다. 기존 명시 배치·기준 시각 조회를 유지한다.
