# Stage 1-F 수동 갱신·새 정책 검증 배치

2026-10-19. 실데이터 경로의 부분 증분이다. [D8](stage-1-f-freshness-policy.md)과 [참고가격·공식 필터 자격 계약](stage-1-f-observation-policy.md)을 구현했다. 자동 실행은 꺼져 있다. 새 넥슨 요청·DB 적재·학습·추천 스냅샷 활성화는 하지 않았다. Stage 1-D·1-F 전체는 미완료다.

## 관측 정규화

`refresh_observations.py`는 공식 목록의 요청 URL·POST·200·원본 SHA256·소속 필터/팀컬러 ID·급여 구간·강화/성장/보너스 조건을 확인한다. 양수 표시값은 reference, 0은 null/unknown이다. 누락/형식 오류를 0으로 채우지 않고 중단한다. 공식 필터에 실제 포함된 카드만 club 자격 관측으로 만든다. 결과 부재는 자격 상실로 해석하지 않는다.

능력치·급여는 기존 전체 능력치 파서와 출처/ID/강화/배치/시각 연결을 검증한다. D8은 원래 observed_at에 더한다. 평가/파싱 시각으로 기한을 연장하지 않는다. 만료 관측은 stale이며, 만료된 기준 카드로 계산한 강화 차이는 기존 계약에 따라 unknown으로 제외될 수 있다. 강화 차이의 기한은 기준/강화 관측 중 더 이른 기한이다.

## 수동 명령과 상한

기본 명령은 저장 자료를 검증하고 계획만 출력한다. 최신 배치를 자동 선택하지 않는다.

```sh
.venv/bin/python -m FRS.utils.crawling.refresh_run
.venv/bin/python -m FRS.utils.crawling.refresh_plan --plan
```

실제 수집에는 `--run`, `--jobs catalog profiles` 또는 그중 하나, 새로운 `--run-id stage-1-f-refresh-...`, 정확한 `--max-attempts`가 모두 필요하다. **이 문서는 실행 승인이 아니며 이번 작업에서는 실제 --run을 실행하지 않았다.** 기존 수집 예외의 남은 횟수는 재사용하지 않는다.

| 작업 | 범위 | 정확한 요청 상한 |
|---|---|---:|
| catalog | 세 클럽 × 다섯 급여 구간의 첫 응답, 가격과 자격 공동 관측 | 15 |
| profiles | 고정한 259카드 × 5~11강, 능력치·급여 공동 관측 | 1,813 |
| 둘 다 | catalog 이후 profiles | 1,828 |

관리 대상은 기존 완료 보강 배치의 259개로 고정한다. 새 후보·페이지 순회·PlayerInfo 경력 조회는 없다. 매 시도 전에 누적 횟수와 요청을 기록하고 최소 1초 간격, 재시도 0회다. 302/403/429를 포함한 오류·비정상 지연·파싱/관측 값 충돌은 중단한다. 목록에 관리 카드가 누락되면 15회에서 중단하고 후속 능력치 요청이나 추가 탐색을 하지 않는다.

종료/중단 실행은 재실행·자동 재개하지 않는다. 프로세스 중단 시 예약한 미상 시도를 보존한다. 부분 파일이 남아도 completed 검증 전에는 계획 기준 배치로 받지 않는다. 새 실행의 외부 수집 범위는 별도 승인 대상이다. 단위 테스트는 합성 응답만 사용하며 로그인·출처 위장·랜덤 UA를 추가하지 않았다.

`verify_refresh.py`는 완료 상태·대상·정확한 요청/로그 수·간격·원본/가공 해시·요청 provenance·재파싱 결과·강화 기준을 대조한다. 기존 문서와 배치를 덮어쓰지 않고, 자동 활성화/최신 선택을 하지 않는다. CrawlLog의 허용 resource에 player_list를 추가했다.

## 외부 요청 없는 파생 검증

`derive_refresh.py`는 기존 완료 목록/보강 배치를 먼저 검증한 뒤 **새 batch_id**에 새 계약의 문서를 만든다. 원본은 복사하거나 수정하지 않고 manifest 해시로 참조한다. source_mode=derived, network_requests_sent=0, validation_at을 기록하며 observed_at과 version은 원래 응답 그대로다. 기존 unknown 배치도 그대로 보존한다. 이는 새로운 HTTP 관측이나 현재 가격 재확인이 아니다.

```sh
# 새 ID만 가능하며 기존 파생 경로는 재사용하지 않는다. 외부 요청 없음.
.venv/bin/python -m FRS.utils.crawling.derive_refresh --batch-id stage-1-f-derived-your-new-id
# 완료된 파생 배치를 자료 종류별로 명시해 오프라인 계획을 확인한다.
.venv/bin/python -m FRS.utils.crawling.refresh_plan --plan \
  --profile-batch-id stage-1-f-derived-20261019-001 \
  --catalog-batch-id stage-1-f-derived-20261019-001
```

your-new-id는 새로운 영어 소문자·숫자·하이픈 ID로 대체한다. 파생 검증도 원본을 다시 파싱하므로 수분 걸릴 수 있다. 완료 후 검증기는 원본/가공 해시뿐 아니라 정규화 결과까지 대조한다. 해시를 함께 바꾼 가공값 변조도 거부한다. 만료를 삭제로 처리하지 않으며 원본·가공 자료는 D2에 따라 Git 제외 로컬 경로에 무기한 보관한다.

## 검증 결과와 제한

전체 pytest 410개, Ruff 린트·포맷, 환경 import·pip check 통과. 합성 검증은 정상 실행, 요청 상한·재시도 금지·HTTP 오류/중단·대상 누락·가격 충돌·기본 계획 전송 없음·원본/가공 변조·관측 시각 보존·만료 비연장 등을 포함한다. 실제 HTTP 갱신 검증은 미실행이다.

동일 가격을 서로 다른 클럽 요청에서 관측한 경우 각 provenance를 보존한다. 값이 달라지면 중단하며 값이 같아도 자동 최신 선택하지 않는다. 기존 1-E 검색은 서로 다른 관측을 conflict로 제외할 수 있다. 중복 선택·활성 스냅샷 정책을 임의로 만들지 않았다. 목록 첫 응답의 전수성, Stage 1-D의 N=3 부족, 팀컬러 발동/단계/보너스 규칙은 여전히 남아 있다. 2-0은 설계만 완료했고 코드·학습은 실행하지 않았다.

## 실제 저장 자료 검증

네트워크 소켓·requests 전송을 차단하고 `stage-1-f-derived-20261019-001`을 새로 만들었다. 원래 목록/보강 manifest 해시를 참조하며 기존 파일은 수정하지 않았다. 검증 시각은 2026-10-19 14:09:37 KST이며 새로운 HTTP 관측은 0회다.

| 자료 | 문서 수 |
|---|---:|
| 기본 카드 | 259 |
| 강화별 급여 | 1,813 |
| 강화 차이 | 1,813 |
| 참고가격 관측 | 2,142 |
| 공식 필터 자격 관측 | 306 |

이 시각 기준 ok 6,172개·unknown 161개(0 가격 관측)다. 서로 다른 가격 키 1,813개 중 미상은 154개, 여러 출처 관측이 있는 키는 329개다. 같은 값이라도 관측 시각/해시가 다르므로 기존 검색 계약에서는 conflict로 제외한다. 이를 숨기거나 최신 값으로 합치지 않았다.

새 배치를 명시한 순수 후보 검색을 ST·급여 상한 99·가격 상한 10^34−1 조건으로 확인했다. 5강/11강 각각 리버풀 3·첼시 9·뮌헨 6개 후보를 반환했고 요청 오류는 없었다. 각각 전체 259개 중 등록 ST 불일치 223·가격 관측 conflict 13·미상 가격 5개가 먼저 제외됐다. 추가 자격 부재는 클럽별 15/9/12개다. 이 결과는 포메이션 11명 구성이나 전 포지션 N=3 달성을 뜻하지 않는다. 점수·모델 호출·DB 적재는 없었다.

파생 배치도 가격 갱신 예정은 원래 관측에 따른 10월 19일 21:41 KST, 능력치/급여는 10월 22일 09:53 KST다. 재파싱으로 갱신 시점을 미루지 않는다. 결과 요약은 Git 제외 `data/processed/stage-1-f-derived-verification.json`, `data/processed/stage-1-f-candidate-verification.json`에 보관한다. 이후 조회 시각에는 기한을 다시 평가해야 한다.
