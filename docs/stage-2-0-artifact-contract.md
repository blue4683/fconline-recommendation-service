# Stage 2-0 공통 변환·전체 확률·모델 산출물 계약

2026-10-19. 실데이터 경로의 계약 코드이며 검증 자료는 합성이다. [원시 입력 계약](stage-2-0-input-contract.md)에 이어 공통 전처리·전체 클래스 확률·재현 매니페스트를 구현했다. 사용자는 **기존 StandardScaler·체형 정수 인코딩 유지, 미학습 체형은 오류로 거부하고 입력 수정 요청**을 확정했다. 이전 설계/입력 증분의 후속 제외 범위보다 현재 사용자 승인을 우선했고 AGENTS.md·설계도 §5에 기록했다.

## 학습 행에서만 fit하는 공통 변환

`model_contract.py`의 fit_training_contract는 호출자가 명시한 train/test 행을 기존 카드 그룹 검사기로 검증한다. 분할을 생성하지 않으며 비율·시드를 정하지 않는다. split_seed도 정수 또는 None을 호출자가 명시해야 한다. None은 이미 지정한 행의 생성 시드를 별도 기록하지 않았다는 뜻이다.

TrainingContext에는 InputSelection, 원본 배치별 manifest SHA256, 입력 카드 문서 해시, 원래 상태 집계가 필요하다. 이 값은 호출자가 완료 배치의 원본/출처/해시를 검증한 뒤 제공한다. 이 계약이 파일을 다시 수집하거나 출처 검증을 대신하지 않는다. 라벨 행은 원래 selection을 보존하며 출처·버전·강화 기준을 다르게 바꾼 context는 오류다.

전처리는 지정한 train 행에서만 숫자 39개 StandardScaler와 체형 LabelEncoder를 fit한다. 같은 카드의 복수 라벨 행도 사용자 확정 행 확장 정책대로 train 안에서 유지한다. 체형은 정수 인코딩한 뒤 float64로 표현하며 별도로 표준화하지 않는다. 포지션 LabelEncoder도 train 라벨만 fit한다. 검증 자료의 통계나 클래스·체형을 fit에 섞지 않는다.

출력은 원시 스펙과 같은 40개 열 순서의 float64 표다. 학습 입력과 추론 입력에 **동일한 저장 변환 객체의 transform**을 적용한다. 이미 fit한 전처리기는 재학습하지 않는다. 미학습 체형·포지션 라벨, 입력 열/자료형/강화 기준 불일치, 비유한 변환은 오류이며 자동 범주 확대·대체·재학습은 없다.

FittedContract는 전처리 상태, 학습 클래스 순서, 출처, 행 수, train/test 행 번호·카드 그룹·시드와 라벨 데이터 해시를 기록한다. 이 기록은 모델 품질이나 실제 학습 완료의 증명이 아니다.

## 전체 클래스 확률

artifacts.PositionPredictor.predict_proba(spids, cards=..., selection=...)는 호출자가 조회할 카드 ID와 검증된 관측을 명시하도록 한다. 내부 DB/최신 조회가 없다. 입력을 공통 변환한 뒤 주어진 모델의 predict_proba만 호출한다. 학습한 전체 클래스와 model_version, 카드별 클래스 확률을 반환한다.

모델 클래스는 포지션 인코더의 0..K−1 순서와 일치해야 하며, 확률을 위치 코드로 역매핑한다. 0 확률도 보존하고 미학습 좌우 슬롯을 추가하지 않는다. 행/열 수·유한성·0~1 범위·확률 합을 검사한다. 합의 수치 허용 오차는 절대 1e−6이며 상대 오차는 0이다. 잘못된 값을 정규화·반올림·클리핑하여 통과시키지 않는다.

probabilities.threshold_positions는 기존 **0.1 이상** 목록을 별도로 만든다. 이는 선수 성능 점수나 D5 배치 허용 규칙이 아니다. 등록 포지션 확률 반환은 후보 데이터의 추천 신선도/팀컬러/예산 검증을 대신하지 않는다.

## 로컬 번들과 model_version

save_bundle은 새 디렉터리에 다음 파일을 저장한다. 기존 경로를 덮어쓰지 않는다.

| 파일 | 내용 |
|---|---|
| model.joblib | 호출자가 제공한 분류기 |
| contract.joblib | 공통 전처리기·스케일러·체형/포지션 인코더·학습 입력/분할 기록 |
| manifest.json | 원시 스펙·변환 상태·클래스 순서·모델 종류/설정·출처/분할·파일 해시·런타임·model_version |

매니페스트는 UTF-8·정렬 키·고정 JSON 구분자·비표준 NaN 금지로 직렬화한다. model_version 자체를 제외한 내용의 SHA256이 model_version이다. XGBoost 기본 missing=NaN 같은 모델 설정은 명시한 __nonfinite_float__ 표기로 기록한다. 파일 내용·피처/클래스 순서·학습 출처·런타임이 바뀌면 다른 버전이다. 동일 파일/매니페스트 내용의 해시는 결정적이며 서로 다른 플랫폼의 직렬화 바이트가 항상 같다는 보장은 아니다.

런타임 기록/검사는 Python·NumPy·pandas·scikit-learn·SciPy·joblib·XGBoost·Pydantic의 정확한 버전이다. OS를 동일하게 요구하지 않으며, 이 증분에서 다른 OS로 만든 실제 학습 모델의 예측 동일성을 검증한 것은 아니다.

manifest는 파일 저장 후 마지막에 원자적으로 기록한다. 중단되어 manifest가 없거나 파일 집합/해시가 다르면 미완료로 거부한다. 저장 실패 경로는 보존하고 자동 복구·덮어쓰기하지 않는다. 완성 번들도 호출자가 model_version을 명시하여 load_bundle로 읽어야 한다. 최신 자동 선택은 없다.

로드는 manifest 구조·해시/명시 버전·스펙·런타임·파일 집합/SHA256을 먼저 확인하고, 검증한 동일 bytes를 역직렬화한다. 이후 모델과 실제 전처리/클래스 상태를 매니페스트와 대조한다. 호출자가 작성한 로컬 joblib 번들을 위한 경로이며 임의 외부 파일의 신뢰성을 SHA256이 보증하는 것은 아니다. 모델 부재·변조·불일치 때 레거시 자동 학습이나 기존 pickle로 대체하지 않는다.

산출물은 D2에 따라 Git 제외 artifacts/models 아래에 무기한 보관한다. 이번 검증에서 생성한 번들은 pytest 임시 경로의 합성 전처리/확률 대역이며 운영 모델을 생성하지 않았다. 실제 수집 자료·모델 파일·새 fixture를 커밋하지 않았다.

## 구현 범위와 검증

이번에는 합성 train 행의 전처리·라벨 인코더 fit과 학습하지 않는 확률 대역을 사용했다. 실제 XGBoost는 기본 설정의 JSON 기록 가능성만 확인했고 fit을 호출하지 않았다. 실데이터의 새 읽기·분할·전처리 fit·모델 학습/평가·외부 수집·DB 적재는 실행하지 않았다.

합성 검증은 train 전용 통계/범주·같은 변환의 저장 전후 일치, 미학습 체형 오류/인코더 불변, 관측/강화 기준 연결·카드 그룹 분리, 전체/0 확률·클래스 역매핑·부정확한 확률 거부, 파일/피처/클래스/라이브러리/버전 변조 거부, 저장 중단/재사용 금지, 모델 부재 시 학습 없음 등을 포함한다.

Stage 2-0의 계약 코드는 이 합성 검증 범위에서 완료하며, 실제 데이터로 2024 XGBoost 재현·비교 평가하는 2-A/2-B는 별도다. 학습 배치·분할 정책과 실제 학습 실행을 이번 결과에서 추정하지 않는다. 1-D의 N=3 커버리지 부족·팀컬러 발동 규칙, 1-F의 실제 HTTP 갱신 검증도 미완료로 유지한다.


검증 결과: 새 합성 테스트 **50개**, 전체 pytest **553개**, Ruff 린트/포맷·환경 import·pip check 통과. 기존 입력 계약 검증 93개와 새 산출물 검증을 합친 관련 테스트는 143개다. 이번 검증에서 실패 사례는 검사를 완화하거나 값을 보정하지 않고 오류로 거부했다. 최신 head의 원격 CI·Squash merge 결과는 해당 PR에서 별도로 확인한다.
