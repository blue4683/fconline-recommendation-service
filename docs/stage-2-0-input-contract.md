# Stage 2-0 원시 입력·라벨·카드 그룹 계약

2026-10-19. 실데이터 경로. 사용자 승인에 따라 [계약 설계](stage-2-0-model-data-contract.md)의 입력 어댑터·40개 피처·등록 포지션 라벨·동일 카드 그룹 검증을 구현했다. 기존 AGENTS.md의 설계 전용 제한보다 현재 사용자 승인을 우선했고, 이 선택을 설계도 §5와 개발 지침에 기록했다. 1-D·1-F 전체 미완료는 유지한다.

## 입력 어댑터

`FRS/core/position_recommend/data_contract.py`는 I/O 없이 PlayerCard 또는 그 스키마에 맞는 dict를 검증한다. 호출자는 InputSelection에 **카드별 spid·batch_id·version과 base_reinforce_level**을 명시해야 한다. 카드 순서는 명시한 관측 순서다. 자동 최신 선택이나 누락 관측 대체를 하지 않는다.

```python
from FRS.core.position_recommend.data_contract import (
    InputSelection,
    ObservationKey,
    to_model_input,
    to_labeled_input,
)

# cards는 별도로 명시한 완료 배치의 원본·출처·해시 검증을 마친 PlayerCard 목록이다.
selection = InputSelection(
    observations=tuple(
        ObservationKey(spid=c.spid, batch_id=c.batch_id, version=c.version)
        for c in cards
    ),
    base_reinforce_level=5,
)
X = to_model_input(cards, selection=selection)
labeled = to_labeled_input(cards, selection=selection)
```

원시 X는 카드당 한 행·40개 열이다. 능력치 34개와 키·몸무게·체형·개인기·왼발·오른발을 설계 순서로 추출한다. 기존 accelartion 등 키 이름을 보존했다. 숫자 열은 int64, 체형은 pandas string[python]이다. 체형은 이 단계에서 문자열로 남으며 아직 모델 fit에 전달할 최종 숫자 표가 아니다.

spid는 원시 표의 인덱스이며 모델 열에 들어가지 않는다. 이름·급여·가격·등록 포지션·OVR·관측 메타데이터·인물 ID도 피처에서 제외한다. stats 안의 추가 키도 선택하지 않는다. 필수 피처 누락·잘못된 자료형·범위를 0이나 다른 관측으로 채우지 않는다. 모델 객체도 재검증해 가변 stats나 model_copy를 통한 스키마 우회를 검사한다.

스키마가 허용한 부가 문자열은 기존 정규화를 따르며, 완성된 피처 표를 받을 때는 validate_model_input으로 열 이름/개수/순서·자료형·누락/범위를 검사한다. float/객체형 숫자·빈 표·추가/중복 열을 자동 변환하지 않는다. feature_spec은 원시 스펙의 버전·순서·자료형·추출 원천·결정적 SHA256을 반환한다. 이는 최종 모델 매니페스트나 model_version이 아니다.

동일 문서의 반복은 하나로 취급하지만, 같은 카드의 내용·관측 시각·버전·배치가 다르면 충돌이다. 호출자가 명시하지 않은 다른 관측도 입력에서 조용히 제거하지 않고 오류로 보고한다. 순수 어댑터는 완료 배치/원본 파일 검증을 대신하지 않는다.

## 등록 라벨과 분할 검사

등록 포지션마다 동일 X를 펼쳐 단일 클래스 y를 만든다. labeled.X의 인덱스는 행 번호이며 labeled.metadata에 spid·person_id·batch_id·version을 별도로 보존한다. 라벨 없는 카드는 학습 행을 만들 때 오류다. 피처만 필요한 원시 어댑터에서는 라벨 부재를 허용한다.

관측한 Position 코드를 그대로 사용하며 15개 클래스나 좌우 확장을 하드코딩하지 않는다. 반환 라벨은 아직 정수 클래스 인코딩이나 모델 출력 확률이 아니다.

validate_card_split(labeled, train_indices=..., test_indices=...)는 호출자가 정한 분할이 전체 행을 한 번씩 포함하는지, 행 번호/라벨/메타데이터가 정렬되는지, 같은 카드의 피처·관측이 일치하는지, 동일 카드가 양쪽에 걸치는지 검사한다. 분할을 생성하지 않으며 비율·시드·층화 방식을 결정하지 않는다. 카드 그룹과 인물 그룹은 다르며 인물 단위 비교 평가는 후속 2-B 범위다.

## 완료 배치의 읽기 전용 검증

`FRS/diagnostics/model_input_report.py`는 명시한 기존 1-B·1-C·1-D 보강 배치만 읽는다. 각 단계 검증기로 완료 상태·출처·원본 숫자/해시·가공 결과를 먼저 대조하고 파일 집합이 검증 중 바뀌지 않았는지 확인한다. 카드별 관측 키를 고정한 뒤 입력/라벨 요약과 출처 해시를 출력한다. 파일·DB를 갱신하지 않으며 임의 배치 경로나 최신 검색을 받지 않는다.

```sh
.venv/bin/python -m FRS.diagnostics.model_input_report \
  --batch-id stage-1-b-20261018 stage-1-c-20261018
```

이 두 배치에는 서로 다른 1,104개 카드가 있다. 1-D 보강 배치를 함께 넣으면 기존 카드와 중복될 수 있으므로 임의로 최신 선택하지 않고 오류다. 별도 입력을 검증하려면 해당 완료 배치를 단독으로 명시하거나 호출자가 검증된 관측 집합을 명시해야 한다. 파생/미래 새 배치 로더 지원을 자동 확대하지 않았다.

과거 unknown/stale 관측도 사용자 정책에 따라 오프라인 입력 검증에 사용할 수 있다. 원본 상태·observed_at·valid_until은 바꾸지 않는다. 이 경로의 성공을 현재 추천 사용 가능성으로 해석하지 않는다.

공통 변환·출력·매니페스트의 후속 구현은 [산출물 계약](stage-2-0-artifact-contract.md)을 따른다. 아래 완료 범위는 입력 계약 증분 당시의 상태다.

## 완료 범위와 후속 작업

이번에는 원시 입력·라벨·카드 그룹 계약과 읽기 전용 진단만 구현했다. 외부 수집, DB 적재, 실제 분할, 전처리 fit, 모델 로드·학습, 확률 출력, 모델/전처리 매니페스트 생성은 실행하지 않았다. 레거시의 모델 부재 시 자동 학습 경로도 호출하지 않는다.

공통 숫자 변환·체형 인코더·스케일러, 클래스 확률 응답과 모델 매니페스트는 후속 구현이다. 인코더/미학습 범주 처리·분할 등 미확정 제품/학습 정책을 이 증분에서 확정하지 않는다. **Stage 2-0 전체는 미완료**다. 1-D 커버리지·팀컬러 발동 규칙과 1-F 실제 HTTP 갱신 검증도 여전히 남아 있다.
