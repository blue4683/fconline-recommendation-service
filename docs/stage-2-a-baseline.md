## 구현과 재현

`FRS/core/position_recommend/train.py`의 기본 실행은 계획 출력이다. 실제 실행은 새 ID를 명시하며 기존 디렉터리를 재사용하지 않는다.

```sh
.venv/bin/python -m FRS.core.position_recommend.train
# 같은 ID의 실행이 존재하면 거부한다. 아래 실행은 완료 여부를 먼저 확인한다.
.venv/bin/python -m FRS.core.position_recommend.train --run --run-id stage-2-a-20261019-001
```

명시한 1-B/C 완료 배치를 기존 검증기로 원본부터 대조한다. 기본 5강 1,104개와 40피처/라벨 계약을 확인한 뒤 GroupShuffleSplit로 카드 그룹을 분리한다. 30%는 카드 그룹 수 기준이므로 라벨 행 비율은 정확히 30%가 아닐 수 있다. 카드 그룹 경계를 지켜도 같은 인물이 다른 카드로 양쪽에 남을 수 있으며 2-B의 인물 분할과 구분한다.

원시 40피처·복수 등록 라벨 행과 공통 변환은 [2-0 계약](stage-2-0-artifact-contract.md)을 따른다. train에서만 전처리/라벨 인코더를 fit한다. 검증 입력의 미학습 체형은 모델 fit 전에 오류로 거부하고 분할/시드/범주를 자동 수정하지 않는다. 미학습 정답 포지션은 확률 클래스를 확장하지 않으며 평가에서 재현율 0으로 기록한다.

| XGBoost 설정 | 값 |
|---|---|
| objective | multi:softprob |
| n_estimators / max_depth | 50 / 5 |
| gamma / reg_lambda | 0 / 1 |
| random_state / importance_type | 100 / gain |
| 실행 자원 | CPU, n_jobs=1 |

2024 코드의 모델 설정을 현재 고정 XGBoost/런타임과 현재 수집 자료에 적용한 재학습이다. 과거 데이터·라이브러리·모델의 동일 바이트 재현을 뜻하지 않는다. CPU/단일 작업 스레드는 로컬 자원·재현 실행을 위한 선택이며 다른 모델 탐색은 하지 않았다.

모델은 artifacts/models/실행ID/bundle에 model.joblib·contract.joblib·manifest.json으로 저장한다. run.json에 진행/완료/중단 상태, report.json에 집계·출처 해시·분할·지표, validation_truth.json과 validation_probabilities.json에 로컬 검증 상세를 기록한다. 모델 저장 후 다시 로드해 동일 검증 카드의 확률이 정확히 같은지 확인한 뒤 completed로 기록한다. 중단/미완료 번들을 완료로 보고하지 않으며 자동 재시작/덮어쓰기는 없다.

## 평가 정의

새 evaluation.py는 포지션 코드를 글자 단위로 나누지 않는다. 기존 Classifier.precision의 교체는 2-B 증분에서 수행하며 이번 새 평가 경로는 이 함수를 호출하지 않는다.

- 등록 라벨 포함률: 검증 카드의 모든 등록 라벨 중 예측 집합에 포함된 라벨 비율.
- 카드 하나 이상/전체 라벨 포함률: 서로 다른 검증 카드 중 등록 라벨 하나 이상/전부가 예측 집합에 포함된 비율.
- 평균 예측 집합 크기: 서로 다른 검증 카드별 0.1 이상 포지션 수의 평균.
- 포지션별 재현율: 해당 포지션을 등록한 검증 카드 중 이를 예측한 카드 비율. support와 hit 수를 함께 기록한다.

동일 카드의 여러 라벨 행을 중복 카드 예측으로 집계하지 않는다. 임계값 0.1은 기존 호환 기준이며 선수 성능/포지션 배치 허용 점수가 아니다. 성공 임계값을 새로 정하지 않고 수치를 보고한다.

## 범위와 한계

신규 넥슨 HTTP·DB 적재·추천 상태 승격은 없다. 수집 데이터와 학습 파일·개별 검증 결과는 D2에 따라 Git 제외 로컬 경로에 보관한다. pytest는 합성 카드만 사용하며 실제 수집 응답/선수 레코드를 fixture에 넣지 않았다.

이번 결과는 등록 포지션 분류기의 단일 분할 관측이다. 카드/인물 분할·전처리 누수의 비교와 문자열 평가 오류 정정은 2-B에서 이어간다. 1-D 커버리지·팀컬러 발동 규칙, 1-F 실제 갱신 검증은 미완료다. 모델을 API/추천 스냅샷에 자동 활성화하지 않는다.
