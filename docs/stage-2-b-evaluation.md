# Stage 2-B 분할·전처리 비교와 평가 정정

2026-10-19. 실데이터 경로이며 사용자 승인한 1-B/C 기본 5강 1,104카드·1,740등록 라벨 행만 사용했다. 비율 70/30·분할 시드 123·15개 클래스·XGBoost 설정·임계값 0.1은 [2-A](stage-2-a-baseline.md)와 같다. 추가 수집·DB 적재·추천 상태 승격은 없다.

## 비교 방법과 재현

`FRS/core/position_recommend/compare.py`에서 아래 5가지를 동일 입력과 설정으로 비교한다. 기본 실행은 계획만 출력하며 실제 실행은 새 ID가 필요하다. 완료/중단 디렉터리를 덮어쓰거나 자동 재시작하지 않는다.

```sh
.venv/bin/python -m FRS.core.position_recommend.compare
# 아래 ID는 이미 완료됐다. 확인 없이 다시 실행하지 않는다.
.venv/bin/python -m FRS.core.position_recommend.compare --run --run-id stage-2-b-20261019-001
```

- `legacy_row_global`: 등록 포지션별 행을 train_test_split으로 나누고 전처리/라벨 인코더를 전체 자료에 fit한다. 2024 코드의 알려진 분할·fit 순서 문제를 현재 40피처 계약 위에서 재현한다. 과거 데이터·라이브러리·모델·평가 버그를 그대로 재현한 점수는 아니다.
- `card_global` / `card_train`: spid 기준 GroupShuffleSplit. 전처리/인코더를 전체 자료 / train에만 fit한다.
- `person_global` / `person_train`: person_id 기준 GroupShuffleSplit. 전처리/인코더를 전체 자료 / train에만 fit한다. 다른 시즌 카드도 같은 인물이면 함께 묶는다.

전체 fit은 **비교 전용**이며 `comparison_only/experiment.joblib`와 별도 experiment.json에 기록한다. 운영 매니페스트를 만들지 않아 일반 load_bundle로 로드할 수 없다. train 전용의 카드/인물 분할은 공통 계약·정상 번들 저장/로드를 거친다. FitRecord는 인물 그룹에서도 카드/인물 교집합을 거부한다. 미학습 체형은 오류이며 시드·분할·범주를 자동 조정하지 않는다.

각 경우의 원본 출처 해시·행 분할·fit 범위·인코더/변환 상태·런타임·모델·검증 확률·정답·집계·파일 해시를 Git 제외 `artifacts/models/stage-2-b-20261019-001/`에 보관했다. 모든 모델은 저장 후 다시 로드하여 확률이 정확히 같은지 확인했다. 전역 fit 산출물의 experiment_version은 진단 식별자이며 서비스 모델 버전으로 채택하지 않는다.

보류한 행 라벨 포함률은 test 행의 단일 정답 코드가 예측 집합에 포함된 비율이다. 카드 지표는 test에 나타난 **서로 다른 카드당 한 번** 예측하여 모든 등록 라벨을 평가한다. 행 분할에서는 같은 카드의 다른 라벨 행이 train에 남으므로 두 지표의 분모·평가 대상이 다르다. 이를 하나의 점수로 혼용하지 않는다. 등록 라벨 포함률·카드별 포함률·포지션별 재현율의 상세 정의는 2-A와 같다.

같은 그룹 분할에서 전체 fit과 train fit 사이의 확률 최대 절대 차이는 카드/인물 모두 **0.0**이었다. 이번 자료·설정에서는 fit 범위를 바꾸어 지표가 달라지지 않았다는 관측이며, 전체 fit을 정당화하거나 다른 자료/모델에서도 누수 영향이 없다는 결론은 아니다. 정상 경로는 train 전용 fit을 유지한다.

카드 분할과 인물 분할의 등록 라벨 포함률 차이는 약 3.28%p다. 검증 카드·라벨 구성도 달라지고 한 시드만 사용했으므로 순수한 인물 누수 효과나 통계적 유의성으로 해석하지 않는다. 행 분할의 정정된 행 지표는 오히려 낮았다. 행 분할의 누수를 확인했다는 사실과 점수 방향/원인은 구분한다. 모델은 등록 포지션 분류기이며 선수 성능 점수가 아니다.

## C5·C6 정정과 호환 범위

Classifier.precision은 단일 문자열을 하나의 포지션 코드로 처리하고 등록 코드 목록도 정규화한다. 예측 집합과 등록 라벨 중 하나 이상의 교집합을 행 단위로 집계하며 기존 백분율 반환을 유지한다. 잘못된 코드·예측 문자열·빈 정답·행 수 불일치는 오류다. 새 비교의 보류 행 지표는 evaluation.row_coverage의 단일 라벨 계약을 사용한다.

Classifier.train의 전체 fit/무작위 행 분할 자동 학습 경로를 닫고 새 수동 학습 명령을 안내한다. Classifier.call도 모델 부재 시 자동 학습하지 않는다. 레거시 prepare/encoding/scale_dataset 및 기존 pickle 로더는 호환 코드로 남아 있어 새 공통 번들 경로를 대체하지 않는다. 레거시 추천 경로를 새 서비스의 정상 실행 경로로 보고하지 않는다.
