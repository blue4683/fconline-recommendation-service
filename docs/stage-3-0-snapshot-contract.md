# Stage 3-0 순수 요청별 스냅샷 계약

2026-10-20 사용자 결정. 1-D·1-F 미완료를 유지하고 명시 배치 자료를 메모리에 고정해 후보 검색·성능·기본 배치를 결합하는 순수 코드와 합성 테스트를 먼저 구현한다. DB·새 수집·실데이터 실행·학습·solver·API 연결은 제외한다. 기존 단계 선행 조건보다 이번 승인 범위의 결정을 우선한다.

## 확정한 정책

- 요청에 허용 강화 집합을 명시하며 5~11 범위에서 카드별로 서로 다른 강화를 선택할 수 있다. 카드·강화 조합별 후보를 보존하고 임의의 최선 강화나 최신 관측을 선택하지 않는다.
- 요청 시작 시각 t0와 자료 종류별 배치 ID를 명시한다. 전달된 각 자료를 한 번 읽고 검증·복사한 뒤 같은 메모리 자료만 사용한다. 최신 배치 자동 선택과 추가 조회는 없다.
- 기존 1-E 정확 등록 검색은 변경하지 않는다. 3-0에서 D5의 확정 계열에 속한 등록 코드별 순수 검색 결과를 결합해 슬롯 후보를 확보하고 같은 카드·강화·슬롯의 중복을 제거한다. 충돌 관측을 최신값으로 해소하지 않는다.
- 유효 후보에는 선택 강화의 관측 가격·급여, 성능 점수, 기본 배치 및 원래 출처를 결합한다. 미상·충돌·만료·배치 불가·OVR 누락은 제외하고 사유를 남긴다. 합계 제약이나 11인 스쿼드의 해 존재를 판정하지 않는다.
- 응답 직전 유효 후보에 사용한 관측의 가장 이른 기한이 지났으면 스냅샷 전체를 `data_expired`로 반환한다. 자동 재계산·갱신·수집을 하지 않는다. 기한과 같은 시각부터 만료다.

## 구현 계약

포메이션·클럽·예산/급여 상한·허용 강화 집합·자료별 배치·t0를 검증한다. 후보 개별 가격/급여는 합계 상한 이하인지 확인하되 팀 합계는 후속 solver/validator의 책임이다. 클럽 양성 자격 관측은 기존 후보 검색 계약을 따르며 발동 인원·보너스 규칙을 새로 정하지 않는다.

스냅샷에는 요청, t0, 실제 사용한 관측의 observed_at 최소/최대, 배치 목록, 유효 후보 전체의 최저 기한, 성능/배치 정책 버전과 내용 해시를 기록한다. 모델 확장은 꺼져 있으므로 model_version은 없다. 후보가 비어 있으면 사용 관측 시각과 기한도 없으며 이를 게임 전체의 해 없음으로 해석하지 않는다.

입력의 중첩 dict와 스냅샷의 외부 반환값을 나중에 수정해도 고정된 내용과 해시가 바뀌지 않게 한다. 재현을 위해 입력 순서와 완전히 같은 관측의 중복이 결과를 바꾸지 않도록 정렬·중복 제거한다. 제외된 관측의 기한은 유효 후보의 만료 시각 계산에 넣지 않는다.

응답 확인 시각은 시간대가 있고 t0 이상이어야 한다. 유효 결과는 동일 스냅샷을 참조하고, 만료 결과는 후보를 반환하지 않는다. 여기의 메모리 고정은 DB 트랜잭션/일관 읽기를 구현했다는 뜻이 아니다.

## 검증과 제한

합성 테스트로 허용 강화별 후보, 등록 계열 검색 결합, 성능/기본 배치 결합, 출처·해시·깊은 불변성, 충돌/미상/만료·부분 제외, 시각 경계, 빈 후보와 단일 읽기를 검증한다. 실제 I/O와 수집·학습은 실행하지 않는다. 동일 인물 중복/팀컬러 발동 등 D5 잔여와 D4·D6, 1-D·1-F, 전체 Stage 3는 미완료다.
