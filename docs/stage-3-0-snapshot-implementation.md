# Stage 3-0 순수 스냅샷 구현

2026-10-20. 실데이터 경로를 유지하며 [승인한 계약](stage-3-0-snapshot-contract.md)을 외부 I/O 없는 코드·합성 자료로 구현했다. 1-D·1-F 전체 완료나 실데이터 추천 검증을 뜻하지 않는다.

## 입출력과 고정 방식

`FRS/core/squad_recommend/snapshot.py`의 `SnapshotQuery`는 포메이션·클럽·급여/가격 상한·허용 강화 집합·자료 종류별 `BatchSelection`·시간대 있는 t0를 명시한다. 3개 MVP 포메이션과 5~11강을 사용하며 빈 집합·중복 강화·잘못된 정수·미지원 포메이션·암묵 모델 버전은 거부한다. 강화는 정렬하고 시각은 UTC로 정규화한다. 지원 클럽 기본값은 기존 3개이며 합성 테스트는 별도 가상 클럽 범위를 전달한다.

`build_snapshot`은 전달된 5종 iterable을 각각 한 번 순회해 스키마와 중첩 필드를 재검증·복사한다. 잘못된 관측은 오류로 반환하며 빈 결과로 숨기지 않는다. 배치/시간/상태/버전 충돌 검증에는 기존 순수 `candidate_search`를 사용한다. 기존 검색 함수와 MongoDB 어댑터는 변경하지 않았다.

슬롯을 D5 등록 계열로 대응하고 그 계열의 등록 코드별 정확 검색 결과를 메모리에서 결합한다. 같은 등록 코드·강화 검색을 재사용하므로 좌우 슬롯이 같은 자료를 다시 읽지 않는다. 여러 등록 코드에 일치한 카드도 카드·강화·슬롯당 한 후보만 남긴다. 다른 등록 코드에서 발생한 position_mismatch가 유효 후보를 제외하거나 실제 가격 누락 사유를 가리지 않게 한다. 최신 관측 선택은 없다.

후보에 성능/기본 배치 계약을 함께 적용한다. 각 후보는 spid·강화·슬롯·OVR·점수·기본 배치 근거와 카드/가격/급여/자격/필요 강화의 원래 관측 전체를 포함한다. 가격은 큰 Python 정수를 그대로 보존한다. 5강에는 사용하지 않은 강화 관측을 포함하지 않으며, 높은 강화의 OVR은 절대값이다. 같은 인물의 다른 시즌이나 여러 강화 중 하나를 여기서 임의로 선택하지 않는다.

## 불변성과 버전

`RequestSnapshot`은 정렬된 JSON의 불변 bytes만 보관한다. `to_dict`와 `check_response`는 매번 독립된 사본을 반환한다. 원본 자료나 반환값의 중첩 사전을 수정해도 이미 만든 스냅샷 내용/해시는 유지된다. 같은 입력 행 순서나 완전히 동일한 관측 중복은 결과를 바꾸지 않는다.

`snapshot_id`는 요청·후보·제외 사유·메타데이터를 포함한 내용 SHA256이다. 메타에는 t0, 유효 후보가 실제 사용하는 관측의 최소/최대 observed_at·배치 목록·관측 개수·가장 이른 기한을 기록한다. 모델 확장이 꺼져 있으므로 model_version=null이다. 성능/배치 정책 버전은 각각 유지하며 스냅샷 정책 버전은 `6b5e1adfe9f8ee4a29b5227694d92e2b10f055d6ee5fb2c73412b1633e743264`다.

## 응답 시 만료

`check_response(when)`은 시간대 있는 t0 이상 시각을 요구한다. 유효 후보에 사용한 모든 관측의 valid_until/delete_after 중 최저 기한과 같은 시각부터 전체 `data_expired`를 반환하고 후보는 빈 목록이다. 자동 재계산·갱신·수집은 없다. 기한 전 후보가 있으면 ready, 후보가 없으면 no_candidates다. 제외 관측과 사용하지 않은 강화의 기한은 유효 스냅샷 기한에 넣지 않는다. 빈 후보의 관측 범위/기한은 null이며 전체 게임의 해 없음이라는 판정이 아니다.

`to_dict`는 고정 내용의 점검용 내보내기다. 실제 응답 시각 검사는 `check_response`를 사용해야 한다. 여기의 메모리 고정은 DB 트랜잭션·동시 갱신 중 일관 읽기나 외부 파일 로드/검증 구현을 뜻하지 않는다.

## 검증과 남은 범위

합성 테스트 62개와 전체 pytest 747개·Ruff 린트/포맷·환경 import·pip check를 통과했다. 모든 단위 테스트는 기존 기본 실행 규칙대로 외부 사이트를 호출하지 않는다. 스냅샷 전용 검증은 가상 선수·가상 수치만 사용했다.

- 전체 5~11강 보존, 허용 강화만 사용, 누락 강화 대체 없음, 절대 OVR·성능/배치 결합과 독립 배치 출처
- 각 포메이션·양방향 CB 계열·복수 등록 중복 제거·미승인 인접 배치 거부·부분 제외
- 자료별 충돌/미상/기한/미래 관측·상한·누락·잘못된 중첩 입력과 요청 거부
- 관측 원래 시각·유효 후보 전체의 최저 기한·제외 관측의 영향 배제·정확한 만료 경계
- 원본/반환값/규칙 사본 불변·순서/동일 중복 재현·generator 단일 읽기·파일/네트워크 I/O 없음

새 넥슨 요청·DB 적재/연결·실데이터 스냅샷 실행·학습·solver·API 연결은 없다. 후보 개별 가격/급여가 요청 상한 이내인지 확인하지만 팀 합계·동일 인물 중복·팀컬러 발동/보너스·11인 해 존재·최적성은 검증하지 않는다. D4·D6와 D5 잔여 정책, 실제 자료 커버리지/갱신은 별도다.
