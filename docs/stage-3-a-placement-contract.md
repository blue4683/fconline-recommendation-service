# Stage 3-A 기본 배치 계약

2026-10-20 기록. 사용자가 D5의 초기 기본 배치를 **등록 포지션과 같은 계열 슬롯 허용**, 모델 확장은 **꺼둠**으로 확정했다. 순수 배치 계약 코드·합성 단위 테스트로 진행하며 DB·새 수집·실데이터 실행·solver·API 연결은 제외한다. 기존 성능 코드 승인에서 제외했던 배치 부분은 이번 후속 승인 범위에서 해제한다.

## 확정한 기본 배치 규칙

요청 슬롯과 카드의 등록 포지션을 각각 아래 표의 계열로 대응하고 같은 계열이 하나 이상 있으면 `base` 배치를 허용한다. 두 방향 모두 같은 대응을 사용하므로 등록 CB→RCB/LCB뿐 아니라 등록 RCB→LCB도 같은 CB 계열이다.

| 등록 코드 또는 슬롯 | 계열 |
|---|---|
| RCB, LCB | CB |
| RDM, LDM | CDM |
| RCM, LCM | CM |
| RAM, LAM | CAM |
| RS, LS | ST |
| 그 외 | 원래 코드 |

이 표 밖의 범위를 임의로 확장하지 않는다. 예를 들어 LB와 RB, RB와 RWB, RW와 RM, RF와 RW, CF와 ST는 서로 다른 계열이다. 기본 배치에는 모델 확률을 입력받지 않으며 임계값·감점·미학습 좌우 클래스 보충을 도입하지 않는다. 모델 확장 정책은 후속 결정 전까지 비활성이다.

이전 D7 승인은 점수 조회 대응에 한정됐다. 이번 D5 답변으로 등록 계열 배치가 추가 승인된 것이며 점수용 별칭에서 자동으로 유도한 승인이 아니다. 향후 D7의 점수 키 대응을 바꾸더라도 D5 배치 정책을 자동 확대하지 않는다.

## 순수 코드의 계약안

- 명시 spid·MVP 슬롯·강화·기준 시각과 사용자가 선택한 기본 5강 PlayerCard를 받는다. 배치 판정은 그 기본 카드의 등록 포지션 관측을 근거로 한다.
- 카드 문서·spid·기본 강화·현재 신선도를 확인한다. 미상/만료·다른 카드·잘못된 관측을 배치 가능으로 표시하지 않는다.
- 허용이면 allowed=true·placement_type=base와 일치한 등록 포지션 및 관측 참조를 반환한다. 제외이면 allowed=false와 사유를 반환하며 다른 카드/슬롯 평가를 중단하지 않는다.
- 해당 강화의 OVR 유무·성능 점수와 기본 배치 판정을 분리한다. OVR이 없어도 등록 계열은 허용일 수 있고 OVR 점수가 있어도 등록 계열 밖이면 배치는 불가다. 실제 후보 사용에는 두 계약과 별도 제약을 모두 확인해야 한다.
- 기본 배치 규칙 버전은 점수 규칙·관측·모델 버전과 구분한다. 등록 계열/모델 비활성/지원 범위/신선도 규칙이 다른 결과를 같은 버전으로 보고하지 않는다.

## 경계와 후속 검증

현재 1-E candidate_search의 **정확 등록 포지션 일치** 계약과 MongoDB 어댑터는 변경하지 않는다. 슬롯별 후보 검색/병합은 3-0 스냅샷에서 별도 연결할 작업이다. 새 배치 계약만으로 기존 검색이 좌우 후보를 자동 확보하거나 후보 부족을 해결했다고 보고하지 않는다.

기본 배치는 같은 인물 중복, 급여/예산, 팀컬러 자격·발동, 강화 능력치 사용 가능, 전체 포메이션의 11명 배치를 보장하지 않는다. 이들 D5 잔여 규칙, D4·D6·3-0 및 1-D·1-F는 미완료다.

후속 합성 검증에는 표의 각 대응과 대칭·정확 일치, 미승인 인접 포지션 거부, 여러 등록 포지션 근거, 모델 입력 부재, 점수/배치 결과 분리, 신선도 경계·잘못된 카드/요청·원본/사양 불변을 포함한다. 이 문서 PR은 결정/계약만 기록하며 실제 코드는 후속 기능 PR로 분리한다.


후속 기능 PR의 실제 입출력·사유·규칙 버전과 합성 검증 결과는 [기본 배치 코드 기록](stage-3-a-placement-implementation.md)을 따른다.
