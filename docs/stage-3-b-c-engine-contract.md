# Stage 3-B/3-C 합성 스쿼드 엔진 계약

2026-10-20 사용자 승인. 1-D·1-F 미완료를 유지하고 CP-SAT 탐색기·비교용 탐욕 2종·검증기를 합성 자료로 먼저 구현한다. DB·새 수집·실데이터 실행·학습·API 연결은 제외한다. 이전 스냅샷 증분의 solver 제외는 이번 범위에서 해제하며 전체 Stage 3나 D6 벤치마크 완료로 보고하지 않는다.

## 사용자 결정

- D4: CP-SAT과 자리별 최저가 우선/성능 우선 탐욕 방식 2종을 사용한다. 라이브러리는 Python 3.11 호환 버전을 검증·고정한다.
- D5: 포메이션의 11개 자리마다 정확히 1명, 같은 spid는 최대 1자리, person_id가 같은 선수는 시즌·강화가 달라도 최대 1명이다. 기존 등록 계열 base 배치만 사용한다.
- 11명 모두 선택한 클럽의 검증된 양성 자격 관측을 요구한다. 공식 발동 단계·능력치 보너스는 검증/적용하지 않는다.
- 같은 스냅샷의 가격·급여 합계는 요청 상한 이하다. 입력된 합계를 믿지 않고 관측에서 재계산한다.
- 초기 CP-SAT 실행은 최대 10초·작업 스레드 1개·시드 123이다. 이 값은 운영 설정이며 D6 통과 기준이 아니다.
- 목적함수는 성능 점수의 2배인 원래 OVR 합이다. BP·급여는 반올림/절삭 없이 정수로 유지하며 64비트를 넘는 합계 제약도 자리수별 제약으로 표현한다.
- 탐욕 방식은 포메이션에 정의된 자리 순서로 진행한다. 가격 우선은 가격 오름차순, 성능 우선은 점수 내림차순이며 동점은 spid·강화 오름차순이다. 되돌리기는 없다. 완성 실패는 탐욕 실패이며 해 없음의 증명이 아니다.

## 입력과 검증 경계

스냅샷 내용 해시를 명시한 자리/spid/강화 선택만 받는다. 선수명·가격·급여·점수 등은 선택 입력으로 받지 않고 같은 불변 스냅샷에서 읽는다. 검증기는 탐색기와 독립적으로 인원·자리·카드/인물 중복·허용 강화·배치·클럽·관측 상태/기한·합계·성능을 재검증한다. 요청 시각과 응답 시각에 스냅샷의 전체 만료 정책을 적용하며 자동 재계산은 없다.

기존 스냅샷이 가격/급여를 큰 정수로 보관하므로 solver에 float로 변환하지 않는다. 예산과 선택 금액의 차이를 비음수 자리수로 표현하여 덧셈·자리올림의 정수 등식으로 정확한 상한을 유지한다. CP-SAT 모델 검증이 실패하면 내부 오류로 보고하며 정밀도를 임의로 낮추지 않는다. 합성 테스트에는 64비트 초과 및 1 BP 경계, 급여 합계 경계를 포함한다.

## 결과 상태와 미완료 범위

CP-SAT의 OPTIMAL/FEASIBLE은 독립 검증을 통과한 경우만 선수 목록을 반환한다. 각각 optimal/feasible로 구분하며 feasible은 최적성을 보장하지 않는다. INFEASIBLE은 이 스냅샷 기준 해 없음, UNKNOWN은 미확정, MODEL_INVALID 또는 검증 불통과는 내부 오류다. 자리 후보가 0명이면 탐색 전에 해당 자리를 보고한다. 보유 자료 밖까지 불가능하다고 주장하지 않는다. 응답 시 전체 스냅샷 기한 도달은 data_expired이며 선수 목록을 반환하지 않는다.

최적해의 점수가 같으면 특정 스쿼드 구성을 보장하거나 별도 가격 최소화 목적을 추가하지 않는다. 비교 방식도 같은 스냅샷·제약·점수를 사용하고 성공 결과를 같은 검증기로 확인한다. 테스트용 작은 문제는 전수 탐색 최적값과 대조한다. 3-D 상태 구분에 필요한 최소 반환 처리는 이번 탐색기 계약에 포함하며 대규모 벤치마크·지연시간 목표·유효해 반환율 등 D6는 후속이다.
