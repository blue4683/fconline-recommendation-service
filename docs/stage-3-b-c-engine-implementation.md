# Stage 3-B/3-C 합성 스쿼드 엔진 구현

2026-10-20. [승인한 계약](stage-3-b-c-engine-contract.md)에 따라 CP-SAT·탐욕 2종·독립 검증기를 구현했다. 실데이터 경로를 유지하지만 이번 실행 자료는 가상 선수·가상 수치이며 DB·넥슨 요청·실데이터 스쿼드 실행·학습·API 연결은 없다.

## 탐색과 독립 검증

`FRS/core/squad_recommend/solver.py`의 `solve_squad(snapshot, config=None, clock=...)`는 같은 RequestSnapshot을 사용한다. 초기 설정은 최대 10초·1스레드·시드 123이며 SolverConfig에서 유효한 명시 설정을 검증한다. 각 슬롯 정확히 1명·spid/person_id 최대 1명·가격/급여 합계 상한을 제약으로 만들고 원래 포지션 OVR 정수 합을 최대화한다. 카드별 혼합 강화는 기존 허용 집합을 따르고 임의 가격 최소화 보조 목적은 추가하지 않는다.

`validator.py`의 `prepare_snapshot`은 모든 후보의 원래 문서·자료별 배치·상태/기한·카드/강화/버전 연결·클럽 자격을 재검증한다. 성능/기본 배치를 다시 계산해 캐시된 점수·OVR·배치 근거와 대조하고, 후보 중복/충돌 및 관측 범위/배치/개수/최저 기한/정책 메타의 불일치를 거부한다. 이 검증은 신뢰된 수집의 출처 인증을 대신하지 않는다. 내용 해시는 전달 자료의 식별자이며 외부 서명이나 원본 사이트의 진위를 보증하는 장치가 아니다.

`SquadSelection`은 snapshot_id와 11개 SquadPick(slot, spid, reinforce_level)을 받는다. 가격·급여·성능 등 추가 입력은 거부한다. `validate_squad(snapshot, selection, when=...)`은 같은 스냅샷에서 선택을 찾아 인원/슬롯·강화·배치·클럽·카드/인물 중복을 검사하고 관측 정수로 합계를 재계산한다. 무효 결과는 사유만 있고 선수/합계는 없다. 유효 결과는 포메이션 순서의 11명·정수 가격/급여·OVR 합·성능 합이다.

탐색기는 성공 후보를 독립 검증기에 넘긴 뒤, 비용이 큰 검증까지 끝난 **응답 직전**에 clock을 다시 읽어 전체 스냅샷의 최저 기한을 확인한다. 기한과 같은 시각부터 data_expired로 바꾸고 선수 목록은 반환하지 않는다. 자동 재계산·수집은 없다. 테스트는 clock을 주입하며 기본 실행은 현재 UTC를 사용하므로 과거 합성 스냅샷을 현재 시각에 유효하다고 취급하지 않는다.

## 큰 정수의 정확한 제약

가격 계약은 최대 34자리 BP다. BP·급여를 float나 만/억 단위로 바꾸지 않는다. `선택액 + 비음수 잔액 = 상한`을 기수 1,000,000의 자리수 등식으로 만든다. 각 자리에서 후보의 해당 숫자×선택 변수·잔액 숫자·이전 자리올림의 합을 예산 숫자와 다음 자리올림으로 연결하며 마지막 자리올림은 0이다.

정확히 11명이 선택되므로 자리올림 범위 0~11로 충분하다. 개별 금액은 스냅샷에서 이미 상한 이하로 검증했으므로 예산보다 높은 미표현 자리수를 무시하지 않는다. 모든 금액/상한을 그대로 보존하며 모델 검증이 실패하면 내부 오류로 반환한다. 목적 계수는 원래 OVR(점수×2)이고 결과 성능과 상한/간극은 다시 2로 나눈다.

## 결과와 비교 방식

EngineResult는 method·status·snapshot_id·엔진 정책/OR-Tools 버전·실제 CP-SAT 설정·원래 탐색 상태·자리별 후보 수·사유 및 성공 시 ValidationReport를 반환한다. coverage의 수는 각 자리의 카드×강화 후보 수이며 서로 다른 인물 수나 1-D의 N=3 커버리지 달성을 뜻하지 않는다. 엔진 정책 버전은 `521c1b0a6ebad08ce9e9d442eab58ca2c78ecdf2284e377089ae3ac51c8d0e8e`다.

| 결과 | 의미 |
|---|---|
| optimal | CP-SAT 최적해와 독립 검증 통과 |
| feasible | 유효해, 최적성 미확인. best_bound/absolute_gap은 성능 단위 |
| infeasible | 같은 스냅샷 기준 해 없음. 빈 슬롯은 탐색 전에 해당 자리 보고 |
| unknown | 유효해를 반환하지 못하고 해 없음도 증명하지 못함 |
| internal_error | 모델/실행/스냅샷/독립 검증 오류. 선수 반환 없음 |
| data_expired | 응답 시 전체 스냅샷 기한 도달. 선수 반환 없음 |
| greedy_failed | 탐욕 방식이 완성하지 못함. 해 없음의 증명 아님 |

`greedy_squad(snapshot, method="cheapest" 또는 "performance", clock=...)`는 같은 스냅샷/제약/점수를 사용한다. 포메이션 순서로 최저가 또는 최고 OVR 후보 중 당장 중복/합계를 지키는 첫 후보를 선택하고 동점은 spid·강화 오름차순이다. 되돌리기·자동 CP-SAT 대체는 없고 성공도 같은 검증기를 통과해야 한다. 탐욕 실패 문제에서 실제 CP-SAT 유효해가 있는 사례를 검증했다.

## 의존성과 검증

OR-Tools 9.15.6755와 전이 의존성 absl-py 2.5.1·immutabledict 4.3.1·protobuf 6.33.6을 고정했다. 기존 NumPy/Pandas/모델 라이브러리 버전은 변경하지 않았다. macOS arm64 Python 3.11의 실제 CP-SAT 실행을 확인했다. PyPI의 Linux x86_64/aarch64 3.11 wheel을 확인하고 x86_64 wheel 다운로드도 성공했다. 실제 Linux 실행 결과는 최신 head의 GitHub CI에서 별도로 확인한다.

합성 테스트는 큰 BP/급여의 1 단위 경계·최대 34자리 BP·64비트 급여 상한·혼합 강화·전수 탐색 최적값 대조·탐욕 실패/동점·카드/인물 중복·팀 합계·모든 포메이션·관측/캐시/메타 불일치·최적/유효/미확정/해 없음/오류·탐색/검증 중 만료와 파일/네트워크 I/O 부재를 포함한다. 신규 합성 71개와 전체 818개가 통과했다. 새 /tmp/frs-engine-deps-venv에서 고정 requirements-dev를 설치해 전체 테스트를 재현했고 Ruff·환경 import·pip check도 통과했다. 같은 PR의 설계도 §11/인수인계에 기록한다.

1-D 커버리지·1-F 실제 갱신, 공식 팀컬러 발동 단계/보너스, D6 대규모 벤치마크와 지연시간 목표, DB/API·실데이터 연결은 미완료다. 이 구현은 3-D의 필요한 최소 상태 구분을 포함하지만 전체 Stage 3 완료나 실제 경기 성능의 증명은 아니다.
