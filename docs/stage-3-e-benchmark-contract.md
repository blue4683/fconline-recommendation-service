# Stage 3-E 합성 벤치마크 계약

2026-10-20 사용자 승인. 1-D·1-F 미완료를 유지하고 외부 수집/DB·실데이터 실행·학습·API 연결 없이 합성 벤치마크를 선행한다. 앞선 3-B/C의 벤치마크 제외는 이번 범위에서 해제한다.

## 확정한 구성과 D6

- 포메이션 3종, 해 존재 30개·해 없음 15개·작은 전수 탐색 대조 문제 15개, 총 60개다. 생성 시드는 123, 자리당 후보 카드 규모는 3/10/30개이며 작은 문제는 3개 규모다. 카드별 강화는 기존 허용 범위 5~11을 사용한다.
- CP-SAT 설정은 기존 10초·1스레드·시드123을 유지하고 같은 스냅샷·제약·점수로 두 탐욕 방식을 비교한다.
- D6: 해 존재 문제의 CP-SAT 유효해 반환율 ≥95%, 반환해 제약 준수·작은 문제 최적값 대조·상태 보고 정확도 100%, OPTIMAL의 유효 탐욕 결과 대비 악화 0건이다.
- 개선/동점 비율·최적성 간극·p50/p95 지연시간은 측정한다. 수치 지연 목표는 첫 결과 후 별도 결정하며 임의 목표를 통과했다고 표시하지 않는다.

## 구현과 판정의 구분

정규 해 존재 30개와 작은 15개는 모두 기준 스쿼드를 먼저 구성·독립 검증한다. 유효해 반환율의 전체 해 존재 분모는 45개이며 정규 30개를 별도로 보고한다. 작은 문제 15개는 최적값과 반환값을 전부 대조하고 미반환/미확정도 최적값 대조 통과로 취급하지 않는다. 문제 생성/기준 스쿼드 검증이 실패하면 실행 오류로 보고한다.

해 없음 15개에는 빈 자리, 비용/급여의 합계 하한 미달, 인물 수 부족/필수 자리 인물 충돌처럼 구성상 불가능함을 확인할 수 있는 사례를 포함한다. UNKNOWN은 해 없음의 증명이 아니며 INFEASIBLE로 바꾸지 않는다. 알려진 해 존재에 infeasible을 보고하거나 해 없음에 선수 목록을 반환한 경우, 오류/잘못된 최적성 표기는 상태 정확도 실패다. 해 존재에서 truthful UNKNOWN은 유효해 반환율에서 실패로 반영하고, 해 없음에서 UNKNOWN은 따로 기록한다.

유효 결과는 검증기를 다시 호출해 제약 준수를 확인한다. OPTIMAL과 유효 탐욕 결과를 비교한 실제 건수·동점/개선/악화를 기록하며 탐욕 실패를 0점 유효 스쿼드로 바꾸지 않는다. 엔진의 최소 상태 단위 테스트와 합성 벤치마크 결과를 구분한다.

자리당 3/10/30은 등록 계열별 서로 다른 spid 카드 수다. 같은 CB/CDM/ST 계열의 두 슬롯에는 같은 카드 풀을 사용하고 서로 다른 인물을 골라야 한다. 생성 카드당 관측 강화 하나를 사용해 실제 카드×강화 후보 수를 함께 기록한다. 불가능 사례는 의도적으로 이 규모를 충족하지 않을 수 있으며 실제 후보 수를 보고한다. 가상 선수/가상 클럽·수치만 사용하고 실제 선수/원본 관측은 읽지 않는다.

생성·스냅샷·전수 탐색·각 방식 실행 시간을 구분한다. 요청 경로 지연은 스냅샷 구성+각 방식의 탐색/독립 검증이며 원본 생성·전수 탐색은 평가 비용으로 따로 기록한다. p50은 중앙값, p95는 최근접 상위 순위(ceil(0.95×표본 수))다. 이는 합성 로컬 관측이며 운영 지연이나 경기 품질의 증명이 아니다.

## 산출물과 남은 범위

생성기·실행기·회귀 테스트를 커밋하고 개별 문제 ID/구성·스냅샷 해시·원본 시각·방법별 상태/지표·D6 판정·런타임/정책 버전을 Git 제외 로컬 artifacts/benchmarks에 보관한다. 같은 실행 ID를 덮어쓰지 않는다. 기본 명령은 계획 출력이며 명시 실행으로 60개를 실제 측정한다. 요약 결과표와 재현 명령은 README에 기록한다.

성공 여부는 실제 결과로만 보고하며 통과를 위해 문제/기준을 사후 변경하지 않는다. 지연 목표 미확정과 1-D·1-F·공식 팀컬러 발동/보너스·DB/API/실데이터 연결은 계속 미완료다.

실제 생성/집계/실행·재현과 결과는 [벤치마크 실행 기록](stage-3-e-benchmark-results.md)을 따른다.
