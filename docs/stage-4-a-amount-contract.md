# Stage 4-A 원문 구간·금액 파서 코드 계약

2026-10-20 사용자 후속 승인. [정규화 설계](stage-4-a-normalization-contract.md)의 설계 전용 제한 중 원문 구간 검증·순수 금액 파서·합성 단위 테스트만 코드로 확대한다. LLM·전체 요청 조립·강화/클럽/포메이션 별칭 파서·DB/API·새 수집·실데이터 실행은 제외한다.

## 확정한 입력과 처리

- 원문은 최대4,000자, 금액 구간은 최대100자다. Python 유니코드 코드포인트 기준이며 초과를 잘라서 처리하지 않고 오류로 반환한다.
- start/end/text는 수정 전 원문과 정확히 일치해야 한다. 0기반·end 미포함이며 빈/범위 밖/다른 출현 위치로 자동 복구하지 않는다. NFC 변환·공백 정리 이전에 대조한다.
- 예산은 BP 또는 만/억/조/경 단위를 명시해야 한다. 숫자 단독이나 1조5000 같은 뒤 단위 생략은 되묻기 위한 오류다. 단위를 BP나 억으로 추측하지 않는다.
- 아라비아 숫자·올바른 쉼표/공백·소수와 십/백/천을 지원한다. 큰 단위는 내림차순·중복 없이 사용하고 한글 숫자(일조 등)는 이번 범위에서 제외한다.
- 정수BP로 정확히 표현되는 최종 합계만 허용하며 기존 0~10^34-1 범위를 유지한다. 반올림·절삭·float 변환·부분 해석은 없다. 약/내외·금액 범위/충돌 표현은 숫자 하나로 확정하지 않는다.

## 순수 코드 입출력

SourceSpan은 원문 구간을 명시하며 구간 검증 함수는 원문/구간 형식·길이·경계·text 일치를 확인한다. 금액 파서는 문자열만 받아 정수 BP 또는 사유가 구분된 오류를 반환한다. 원문+구간 정규화 함수는 검증한 구간·원래 text와 BP·독립 규칙 버전을 함께 반환한다. 원문/반환 근거를 자동 수정하거나 로그/파일로 저장하지 않는다.

숫자 토큰은 ASCII 십진 숫자·3자리 쉼표 묶음·소수점으로 검증한 뒤 처리한다. 큰 단위 사이의 계수는 숫자와 십/백/천의 조합으로 계산하고 내부 작은 단위도 내림차순·중복 없이 사용한다. 숫자 사이 공백을 없애 붙이거나 알 수 없는 접미사를 버리지 않는다. 1조 5천억·1.5조·150,000BP를 정확히 변환한다. 기본 BP 계수도 명시 단위가 필요하다.

표준 라이브러리 Fraction의 문자열 입력/유리수 연산으로 소수를 정확히 유지하고 마지막 분모가1인지 확인하는 방식을 사용한다. Fraction 자체가 허용하는 지수·분수/부호·밑줄 등은 파서의 승인 문법으로 확장하지 않는다. [Python 공식 문서](https://docs.python.org/3.11/library/fractions.html)를 확인했으며 Python3.11.15를 유지한다. 의존성을 추가하지 않는다.

## 검증과 남은 범위

합성 테스트는 34자리/1BP 정밀도·소수/단위 조합·큰/작은 단위 순서·쉼표/공백·누락/모호성/미지원 토큰·0/상한·길이 경계·구간 위조/유니코드 인덱스·원본/규칙 불변·파일/네트워크 부재를 포함한다.

이번 코드는 금액 구간 하나를 검증한다. 전체 문장의 필수5조건 누락·부정/수정 의도·구간 밖 금액 충돌·미지원 조건 누락을 판정하거나 요청을 조립하지 않는다. LLM 공급자/모델/비용·별칭/강화 문법·최종 응답 정책·4-D는 후속이며 1-D·1-F는 미완료다.
