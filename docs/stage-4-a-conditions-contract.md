# Stage 4-A 필수 5조건 코드 계약

이 문서는 기존 순수 명시 급여 계약과 과거 재현 기준이다. 실데이터 브랜치의 새 웹/API·MCP 요청은2026-10-22 사용자 결정으로 [급여310 고정 정책](fixed-salary-310-contract.md)을 적용한다. 원문 급여 생략을 허용하며 다른 명시 급여는 수정 안내로 차단한다.

2026-10-20 사용자 후속 승인. 원문 근거가 있는 수동/합성 추출 결과를 정규화한다. [금액 계약](stage-4-a-amount-contract.md)의 원문4000/금액100 코드포인트·수정 전 구간 대조·정확 BP·불변/버전 계약을 유지한다. LLM·DB/API·새 수집·실제 스쿼드 실행은 제외한다. 1-D·1-F 미완료도 유지한다.

## 사용자 확정 문법

| 조건 | 허용 | 거부/한계 |
|---|---|---|
| 예산 | 기존 정확 금액 파서 | 단위 생략·분수 BP·약/범위/충돌은 오류/되묻기 |
| 급여 | ASCII 비음수 정수와 올바른 세 자리 쉼표 묶음 | 소수/부호/단위 생략 보충 없음. 기존 0~2^63-1 계약 유지 |
| 클럽 | 리버풀·첼시·바이에른 뮌헨 | 뮌헨 등 별칭·다른 클럽은 미지원 |
| 포메이션 | 4-2-3-1·4-1-2-3·4-2-2-2 | 4231 등 축약·다른 값은 미지원 |
| 강화 | 5강 같은 단일·5~11강 같은 양 끝 포함 범위·5강,7강 같은 목록 | 5~11만 지원. 중복은 정렬한 집합. 역순/잘못된 문법/범위 밖 값을 버리지 않고 보고 |

강화 범위는 물결표(~), 목록은 쉼표(,)를 사용한다. 목록의 각 항목에는 강을 명시하며 범위의 마지막에도 강을 명시한다. 필드 앞뒤/문법 기호 주변 공백은 원문 구간을 대조한 뒤 처리한다. 클럽 내부 공백이나 하이픈을 고쳐 별칭으로 대응하지 않는다. 아직 정하지 않은 다른 구분 기호·혼합 범위 목록은 자동 확장하지 않는다.

## 구현 구조와 검증 경계

추출 DTO는 다섯 필드의 원문 구간 목록과 별도 미지원 조건 구간 목록을 받는다. 하나의 값이 반복되면 모든 근거를 보존하고 동일 정규값으로 합칠 수 있다. 서로 다른 값은 충돌로 보고하며 마지막 값 선택/강화 목록 합집합으로 덮지 않는다. 각 강화 목록 내부 중복을 집합으로 정리하는 결정과 필드 간 충돌 처리를 구분한다.

모든 근거의 start/end/text를 먼저 검증하고 필드별 파서를 적용한다. 누락·원문 불일치·문법 오류·미지원 값/조건·서로 충돌하는 값은 사유를 모아서 반환한다. 문제가 하나라도 있으면 완성 조건은 반환하지 않는다. 값 일부를 버리거나 기본값으로 채운 요청을 만들지 않는다. 결과에는 검증한 근거, 규칙 버전, 현재 지원 목록을 포함한다. 원문을 오류 메시지에 복사하거나 파일/로그로 저장하지 않는다.

완성 조건은 price_cap·salary_cap·team_color·formation·allowed_reinforcements 다섯 값이며 자료 배치/기준 시각/SnapshotQuery와 결합하지 않는다. 이 모듈은 외부 추출기를 부르거나 원문 전체에서 조건을 자동 탐색하지 않는다. 호출자가 보고하지 않은 미지원 절·부정 의미·잘못된 필드 분류는 이 검증만으로 검출할 수 없다. 원문 의미 정확도는 후속 Stage 4-D 평가 대상이다.

## 검증 계획

다섯 조건 정상 조합·강화 단일/범위/목록/중복·급여 쉼표/정수 경계·정식 값과 별칭·필드별 누락·동시 오류·원문 구간 불일치·동일 값 반복/충돌·미지원 조건을 합성 테스트한다. 입력/결과 불변·명시 배치/시각 자동 삽입 없음·파일/네트워크 없음도 확인한다. 필수 pytest/Ruff 검증과 최신 head CI를 통과한 뒤 develop에 Squash 병합한다.
