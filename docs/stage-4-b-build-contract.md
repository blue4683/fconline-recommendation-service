# Stage 4-B 합성 build 연결 계약

2026-10-20 사용자 선택. 1-D·1-F 미완료를 유지하고 원문+수동/합성 추출 근거를 기존 정규화·스냅샷·엔진에 연결한다. 실데이터 경로의 공통 코드이지만 실행 검증은 합성 자료만 사용한다. DB/API·새 수집·실데이터 실행·LLM 호출은 포함하지 않는다.

## 연결 경계

1. 원문과 ExtractedConditions를 기존 5조건 정규화기에 전달한다.
2. 누락·미지원·문법/구간 오류·충돌이 있으면 정규화 결과만 반환한다. 자료 iterable·내부 배치/시각·시계·스냅샷·엔진을 사용해 요청을 완성하지 않는다.
3. 정상일 때만 외부 호출자가 명시한 BatchSelection·시간대 있는 t0와 다섯 조건을 SnapshotQuery로 결합한다. 자료별 배치를 재검증하고 최신 선택이나 현재 시각으로의 보충은 하지 않는다. 응답 확인 clock도 호출자가 명시한다.
4. 전달한 메모리 자료만 기존 build_snapshot으로 한 번 복사한다. 기존 후보 제외·충돌·신선도·허용 강화·클럽/배치 계약을 유지한다.
5. 기존 solve_squad를 CP-SAT 기본10초/1스레드/시드123으로 호출한다. 독립 검증·동일 인물·전원 클럽 자격·정확 합계·응답 만료 판정을 변경하지 않는다. 결과 상태/근거를 그대로 반환하며 재시도나 탐욕 방식 대체를 하지 않는다.

반환 구조는 정규화 결과·생성된 불변 스냅샷·엔진 결과와 연결 규칙 버전이다. 정규화가 실패하면 스냅샷/엔진은 None이다. 새로운 API의 단일 상태 우선순위나 사용자 표시 형식은 정하지 않는다. 배치/시각/자료 형식 같은 내부 계약 위반은 기존 검증 예외로 알리고 해 없음이나 사용자 누락으로 꾸미지 않는다. 이 예외가 발생해도 엔진을 호출해 부분 자료로 복구하지 않는다.

엔진 반환 뒤 후보를 다시 읽거나 비용이 큰 표 생성/직렬화를 하지 않는다. 엔진 응답 경계의 만료를 유지하며 후속 HTTP/표 출력 경계는 별도다. 정상 스쿼드는 같은 스냅샷의 독립 검증 통과 결과만 사용한다. 해 없음은 전달한 명시 자료 범위의 결과이며 전체 게임 자료의 해 없음으로 확대하지 않는다.

## 검증 계획

세 포메이션·클럽과 강화 선택의 합성 정상 조합, 예산/급여 상한 1단위 경계, 명시 배치 불일치·충돌/미상 제외·해 없음·응답 만료와 기존 상태 보존을 확인한다. 누락·미지원·원문 불일치 시 자료 iterable/시계/스냅샷/엔진 미호출, 내부 계약 위반 시 엔진 미호출, 원본 보존·자료 한 번 읽기·파일/네트워크 없음도 확인한다. 실제 CP-SAT·독립 검증기를 사용하는 합성 연결 테스트와 의미 있는 상태 대역을 구분한다.

4-A의 실제 의미 추출·LLM/비용·4-C 표/서술·4-D 의미/E2E 평가·API/DB 연결은 후속이다. 이번 합성 연결을 자연어 이해 성공이나 실데이터 서비스 완료로 보고하지 않는다.
