# W6 사전 정답 25문장 — v1

작성일: 2026-10-21. 기준 코드: develop `83c7eed5e06f70833b4c7bc35c1d6a7b8d5fe8e2`. 사용자가 확정한 정상8·해없음3·미지원5·필수누락4·모호/금액/정정5를 고정한다. **문서상 사전 정답이며 실행 결과가 아니다.** 평가 방법·고정 자료·변경 절차는 [평가 계약](stage-w6-evaluation-contract.md)을 따른다.

## 표기와 공통 판정

- 원문 열의 백틱 안 문자열 전체가 입력이다. 백틱은 입력에 포함하지 않는다. 공백·쉼표·마침표를 바꾸거나 문장을 합치지 않는다. 사례는 각각 독립 요청이며 앞 요청의 조건을 상속하지 않는다.
- 정답 벡터 순서는 **(예산 BP, 급여 상한, 클럽, 포메이션, 허용 강화 집합)**이다. BP·급여는 정확한 십진 문자열로 적고 강화 집합은 정렬된 정수 배열이다. `null`은 누락이며 0이 아니다.
- 정답 벡터는 채점용 의미다. 명확화 응답의 `conditions`는 기존 계약대로 전체 `null`, `squad`도 `null`이다. 부분 정답을 추천 조건으로 사용하지 않는다.
- `성공`: 정답 조건과 일치하고 `optimal` 또는 `feasible`인 검증된 11명. `feasible`은 최적성 확인으로 설명하지 않는다. 동일 목적값의 선수 조합은 달라도 된다.
- `해없음`: 정답 조건 그대로 실행한 `infeasible`, 스쿼드 없음. `unknown`·탐욕 실패·기술 오류·만료를 해 없음으로 바꾸지 않는다.
- `준비 명확화`: 후보 준비 단계에서 차단, 모델·자료 읽기·엔진 호출 0회. `정규화 명확화`: 후보 선택·근거 검증 후 필수 누락/값 충돌로 차단, 자료 읽기·엔진 호출 0회. 두 단계 모두 최종 상태는 `needs_clarification`이다.
- 아래 사유 코드는 현재 소스를 정적으로 대조한 기대값이다. 메시지 문장의 완전 일치보다 단계·필드·사유·원문 근거를 채점한다. 추가 오류가 생기면 무조건 허용하지 않고 근거와 함께 실패로 기록한다.

## 근거 구간과 오라클 고정

위 표의 원문과 벡터/사유가 사람이 정한 오라클이다. 평가 구현 때 반환 결과에서 정답을 역으로 만들지 않는다. 정상/I/M/A01은 원문의 각 값 출현을 원래 순서대로 각 필드에 연결한다. 예산·급여 접두사와 마지막 `로/으로 구성해줘`·마침표는 값 구간에서 제외한다. N04/N08의 강화 목록은 전체를 보존하고, A01의 두 예산은 다른 출현이다.

원문 오프셋은 Python 유니코드 코드포인트 기준 0 시작·end 미포함이다. 후속 평가 코드에서 원문 슬라이스·정답 토큰·선언 필드를 독립 대조해 고정하고, candidate_set_id/구현 해시와 함께 기록한다. 모델에게 새 오프셋이나 값을 만들게 하지 않는다. 준비 차단9개(U01~U05, A02~A05)는 미해석 절/오류 구간과 사유를 확인하며 선택을 호출하지 않는다. 나머지16개(N8/I3/M4/A01)는 올바른 선택 뒤 의미와 상태를 대조한다. **16회는 향후 1회전의 추론량 산정값이며 호출 승인이 아니다.**

25문장은 현재 정형 문법을 검증하기 위해 작성한 공개 회귀 세트다. 비공개 일반화 평가나 자유 한국어/대화 이해 성능으로 표현하지 않는다. 실제 선수·가격·자격 관측은 사용하지 않았다.
