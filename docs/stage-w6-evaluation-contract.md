## 2. 고정 평가 자료와 정답 근거

정답 근거는 현재 소스를 읽어 도출한 아래 경계다. 이번에는 자료 생성·엔진 실행으로 검증한 수치가 아니다.

재현용 실행은 run_id·observed_at·요청 t0·응답 시계·자원별 배치 ID·material/generator/policy/규칙 해시를 명시해 잠근다. 오프라인 고정 시계와 실제 서버 시계를 구분한다. 과거 W5 자료의 기한을 현재로 연장하지 않는다. 실제 모델 평가의 새 실행 ID·관측 시각·상한은 후속 실행 범위에서 확정하며, 이 문서가 새 자료 생성/실행을 시작하지 않는다.

## 3. 평가 경로와 정답 판정

후속 최소 경로는 변경 없는 원문 → 후보 준비 → 선택 → ID/원문 검증 → 정규화 → 고정 합성 스냅샷 → CP-SAT/독립 검증 → 코드 표/템플릿이다. HTTP/브라우저/MCP 검증은 측정 경계를 별도로 표기한다. 경로를 섞어 하나의 E2E 지연/모델 성능으로 집계하지 않는다.

- 정상8: 5조건 모두 정답과 일치하고 11명·전원 클럽 양성 자격·같은 인물 최대1·등록 계열 배치·허용 강화·BP/급여 상한·점수/합계·응답 기한을 검증한다. `optimal`/`feasible` 모두 유효 결과지만 최적성 주장은 상태와 일치해야 한다.
- 해없음3: 원래 조건 그대로 `infeasible`이어야 한다. 해 존재를 못 찾은 `unknown`은 실패이며 해 없음의 증명으로 세지 않는다.
- 미지원5/함정 중4: 준비 명확화9개는 호출 차단 자체가 정답이다. 이를 모델이 이해한9개로 보고하지 않는다. 일반 절은 `unrecognized_context`로 안내하는 현재 한계를 보존한다.
- 누락4/예산 충돌1: 올바른 ID 선택 뒤 명확화5개다. 누락을 기본값으로 보충하거나 충돌 중 한쪽을 삭제하면 실패다. 선택 오류로 명확화에 도달하지 못한 것도 실패다.
- 명확화14개 모두 추천 표가 없어야 하고, 원문 근거/필드/사유·현재 지원 목록을 보존한다. 지원되지 않는 조건을 조용히 무시하지 않는다.

`candidate-selection.v1`은 모든 준비된 값 ID를 선언 필드에 한 번씩 명시 선택하는 계약이다. 이 공개 정형 평가에서 의미의 상당 부분은 코드 후보 준비/정규화가 담당한다. 모델 선택률과 전체 파이프라인의 입력 처리율을 분리하며 “자유 자연어 이해25개”로 설명하지 않는다.

## 4. 지표와 분모

아래는 후속 평가의 기록 계약이며 실제 측정값은 모두 **미측정**이다. 합성 대역 결과는 실제 모델 결과와 다른 표에 둔다. 정확한 분수와 백분율을 함께 기재하고 0분모는 N/A로 쓴다.

| 지표 | 분모·성공 판정 |
|---|---|
| 실행 완결도 | 계획25개 중 terminal 결과를 기록한 수/25. 미실행·중단·기술 실패 수를 함께 표기 |
| 출력 스키마 유효율 | 실제 추론 시도 수. 정상 JSON/Pydantic 통과만 분자. 연결 오류·timeout·잘림·출력 없음도 시도했으면 분모에 남김 |
| ID/근거 유효율 | 실제 추론 시도 수. 스키마와 registry/ID/필드/모든 출현 커버리지·원문 구간 검증 모두 통과 |
| 선택 대상 의미 정확도 | 모델 호출 대상16개(N8/I3/M4/A01). 각 필드 값·누락·충돌·근거가 사전 정답과 일치. 준비 차단9개는 넣지 않음 |
| 전체 조건 의미 정확도 | 계획25개. 준비 차단은 지정 단계/사유/근거와 일치, 나머지는 5조건·누락·충돌 모두 일치해야1점. 일부 필드만 맞은 부분 점수는 진단으로만 분리 |

중도 중단 시 `not_attempted`를 남기고 정답 점수를 주지 않는다. 결과표에는 완료된 부분의 진단 수치와 계획25개 대비 달성률을 구분한다. 실행이 끝나지 않은 표를 최종 정확도로 이름 붙이지 않는다. 대역/사전 정답 주입으로 통과한 값은 **계약 검증**, 실제 qwen3:8b의 정확도는 **미측정**이다.

## 5. 실행 기록·시간·비용

후속 기록에는 코퍼스 버전/파일 SHA256·기준 commit·정답 해시·설정/프롬프트/selector/정규화/엔진/모델명과 digest·런타임·자료/시각·사례 ID·원문 해시·기대값·관측값·실패 단계/사유·실제 시도/종료 상태를 남긴다. 시작 전 계획/상한과 종료 후 실제 사용량을 구분하고 raw 응답/실행 보고서는 Git 제외 로컬에 보관한다. 모델 내부 추론문/비밀값을 공개 보고서에 넣지 않는다.

- 준비/모델 선택/정규화/스냅샷·탐색·검증/표 구성·최종 직렬화의 시간과 전체 시간을 구분한다. 계측하지 못한 항목은 null로 남긴다.
- 전체 지연은 해당 경로의 요청 수신부터 최종 결과 직렬화까지다. HTTP/SSE 첫 이벤트·첫 토큰·마지막 이벤트·프로세스 기동은 서로 다른 지표다. 실제 계측 경계를 보고서에 적는다.
- p50/p95는 해당 집합의 관측 wall time을 정렬한 nearest-rank(ceil(p×n), 1시작)로 계산한다. 성공 결과만의 시간과 실패/timeout 포함 terminal 결과 시간을 구분하고 표본 수를 적는다. 준비 차단과 실제 추론 요청도 분리한다. 미실행 사례의 시간은 만들지 않는다.
- 모델 로드 포함 첫 요청과 warm 요청을 구분한다. 설정 때문에 매 호출 재로드했다면 모두 load-inclusive로 쓰며, 추가 warm-up을 몰래 호출하지 않는다. 25개의 작은 공개 세트 결과로 운영 SLA를 주장하지 않는다.
- 기존 D6 p95≤1초는 합성60문제의 엔진 경로 기준이다. 모델·Agent·MCP·HTTP의 새 지연 통과 기준으로 가져오지 않는다.
- 제공된 토큰/로드/추론 통계만 기록한다. 없는 값은 null이며0이 아니다. 실패/결과 미상 요청도 시도 수에 넣고 재시도/자동fallback은 허용하지 않는다.
- 로컬 추론의 API 청구 여부와 전력·장비·소요시간을 구분한다. 측정하지 않은 총비용을0원이라고 쓰지 않는다.

## 6. 비교 주장과 이번에 하지 않는 것

W5의 실제 stdio12개 직접/MCP 일치는 프로토콜/전송 계약 검증이며 실제 모델의25문장 정확도가 아니다. 앞선 직접 구간 생성0/5와 ID 선택6/6은 사례·경로가 달라 통제된 개선율로 계산하지 않는다. 기존 CP-SAT/탐욕60문제는 별도 엔진 자산이다.

현재 응답은 코드 템플릿이며 LLM narrate/check 비교는 구현하지 않았다. “환각 제거100%”, “Before/After 의미 정확도 향상”을 이번 문서나 기존 대역 검사로 주장하지 않는다. 후속 최소 비교안은 같은 고정 정답 선택/자료를 사용한 직접/MCP 계약 일치와 실제 모델의 이번25문장 성적을 각각 보고하는 것이다. 모델이 직접 선수를 고르는 baseline·서술 재생성·추가 모델·RAG·별칭/세션은 마감 전 필수 범위로 추가하지 않는다.

LangSmith 등 외부 업로드/계정 등록·모델 다운로드·실제 모델/메타데이터 요청·상주 서버·수집·배포·master 병합은 이번 승인에 포함하지 않는다. 반복3회/추론 상한/중단 조건/실행 ID도 이번에 결정하지 않는다. 한 회전에서 준비 차단9개를 제외한 추론 대상은16개라는 **산정값**만 제공한다. 서버 시작·상태 조회는 별도 요청량이다.

## 8. 변경 관리와 이번 검증

코퍼스/정답은 모델 호출 전에 v1로 고정한다. 오타나 계약 불일치가 발견되면 원래 문서/결과를 보존하고 v2 변경 이유·영향 사례·diff·사용자 결정 필요 여부를 기록한다. 결과를 보고 어려운 문장을 빼거나 같은 실행 ID에서 프롬프트/모델/정답을 바꾸지 않는다. 필수 문형/제품 범위 변경이면 구현 전에 확인한다.

이번 검증은 소스의 문형/범위·정적 생성 경계와 문서25개 개수·ID 중복·링크·diff·보호 경로 보존 확인이다. 코드 변경이 없어 로컬 기능 테스트/모델/엔진을 새로 실행하지 않는다. GitHub 문서 PR의 자동 CI 결과는 완료된 뒤 별도로 기록한다. W6 코드/실제 평가·실데이터1-D/1-F·외부 제출은 미완료다.
