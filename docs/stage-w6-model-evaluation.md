작성일:2026-10-21. 경로:과제용 **실제 로컬 LLM + 합성 선수 자료**. [사전 정답25문장](stage-w6-evaluation-cases.md)·[지표 계약](stage-w6-evaluation-contract.md)을 유지하고 [대역 검증](stage-w6-evaluation-implementation.md)과 분리한다. 사용자 승인으로 실모델 실행기를 구현·합성 검증한 뒤 새1회 평가를 완료했다. **전체 E2E24/25(96%), 실제 모델 대상 근거/의미15/16(93.75%)**였다. 25문장을 모두 모델이 이해했다고 뜻하지 않는다.

- 사용자 승인:고정25문장·qwen3:8b 새1회, 준비 차단9개 미호출, 추론최대16회·상태최대2회·순차·추론당120초·재시도/다운로드/외부 전송 없음, 서버/연결 오류 즉시 중단, 로컬 기록 보존. 필요 시 설치된Ollama 시작/이번 서버만 종료.
- `FRS/evaluation/model.py`:기존 원문/후보/그래프/스냅샷/엔진/출력·독립 채점을 재사용하며 기존 대역 실행기/Agent/API/웹은 변경하지 않았다. 새 모델/프롬프트/스키마 조정·자동fallback·기본값 보충·추가 수집·HTTP 서버/브라우저·외부 tracing은 실행하지 않았다.
- 모델 응답만으로 정답을 만들지 않고, 먼저 정상8개의 유효11명·해없음3개의 양수 하한을 합성 자료로 검증했다. 코드/원문/정답·후보 계획을 고정하고 각 사례 전에 계획 불변을 확인했다.
- 새 승인 루트 `artifacts/agent-model-evaluation/approval-20261021-001/`의 `approval-consumed.lock`을 배타적으로 생성한다. 요청 전 시도 번호·pending을 fsync해 실패/결과 미상도 상한에서 제외하지 않는다. 재실행/자동 재개/남은 횟수 재사용은 금지한다.

- 준비 오류는 선택/자료 읽기 없이 차단한다. 선택 오류는 기술 오류로 구분하고 추가 추출이나 정상 정규화로 위장하지 않는다. 서버/연결 오류면 현재 실패를 기록하고 나머지는 미실행으로 남긴다.
- 사례별 요청 t0와 응답 시각은 실제 wall clock이며, 관측 시각은 배치 시작 시 한 번만 명시했다. 지연 측정은 기록/Agent 생성·실행/최종 투영·직렬화까지이며 사후 독립 채점·합성 자료 생성/사전 증명·서버 기동/metadata는 제외한다.

## M02 실패와 안전 경계

M02 원문은 `급여 300, 첼시, 4-1-2-3, 5강으로 구성해줘`다. 기대 동작은 price_cap의빈 ID 배열 → 예산 누락 명확화다. 실제 모델은 급여 후보ID를 price_cap에도 배정했다. 출력은 스키마를 통과했지만 코드가 `field_mismatch`로 거부했다.

따라서 이 사례는 **의미/E2E 실패**이고, 안전 차단을 정확한 조건 이해로 바꾸어 채점하지 않았다. 자료 조회·스냅샷·탐색·추천 표는 실행/반환하지 않았다. 자동으로 예산을 채우거나 잘못된 필드를 지우지 않았으며 재호출도0이다. 실패 응답을 남기고 남은 다른 사례를 순차 처리했다.

실제 원본을 테스트fixture로 커밋하지 않고 같은 잘못된 필드 배정 구조를 합성해 회귀 테스트에 추가했다. 평가 뒤 프롬프트/모델/정답/코퍼스를 수정하지 않았다. 추가 재평가/새 문형·스키마 정책은 별도 범위다.
