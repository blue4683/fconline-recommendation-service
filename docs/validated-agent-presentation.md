# R3 검증된 코드 출력

2026-10-20, 웹 제외 백엔드 W2/R3 구현. FRS/agent/presentation.py는 내부 AgentRunResult를 합성 데이터의 코드 출력 자료로 만든다. 실제 HTTP/SSE나 확정된 웹 계약이 아니며 프론트엔드 파일을 수정하지 않는다.

## 출력과 검증

- 정규화 오류는 issues/지원 목록과 코드 안내만 반환하며 자료·엔진·응답 시계를 읽지 않는다. 추출 실패의 원문 예외나 초안을 복사하지 않는다.
- 정상 조건과 build의 정규화 결과/스냅샷 조건이 같은지 확인한다. 비교 탐욕 결과나 다른 스냅샷·비합성 출처를 Agent의 성공으로 내보내지 않는다.
- optimal/feasible은 스냅샷과 선택 11명을 기존 독립 검증기로 다시 대조한다. 보고된 합계/선택과 재검증 결과가 다르면 전체 표를 거부한다.
- 선수 표는 포메이션 자리 순서다. BP·급여·상한·합계·spid/person_id는 정확한 10진 문자열이고 OVR/0.5 단위 점수만 기존 작은 숫자를 유지한다.
- 표 구성과 검증 뒤 응답 clock으로 가장 이른 사용 관측 기한을 다시 확인한다. 만료면 표를 제거하고 만료 안내만 반환한다. 해 없음·미확정·내부 오류도 서로 구분한다.
- 설명은 고정 코드 템플릿만 사용한다. 가상 자료 기준의 검증/최적성 상태만 안내하고 실제 경기 성능·가성비·팀컬러 보너스·미검증 선수 설명을 만들지 않는다.
- CodePresentation은 불변 bytes와 독립 복사본이다. 그래프/정규화/엔진/출력 버전을 기록하며 모델 메타데이터는 이 계층에서 제공하지 않았다고 명시한다. 실제 모델을 쓰지 않았다고 추측하지 않는다.

## 경계

이 검증은 계산 결과와 구조화 조건/스냅샷의 일치를 보장하는 범위다. LLM이 원문 의도를 잘못 추출했는지는 별도 의미 평가 대상이다. 원문을 고치거나 자료를 최신으로 바꾸거나 실패한 결과를 몰래 다른 후보로 대체하지 않는다.

현재 결과 kind는 code_presentation이며 API/SSE envelope나 web-agent.v0의 확정판이 아니다. 실제 API 어댑터에서 요청 ID/스트림·모델 출처·전송 직전 기한·서버 준비 상태를 연결해야 한다. 이후 서술/대기열/전송 지연이 추가되면 이 검사 이후에도 최종 만료 확인이 필요하다.

## 검증

신규 합성 16개가 실제 엔진 표/자리/합계·큰 BP/2^53 초과 급여·출력 직전 만료·합계/조건/스냅샷 변조·비성공 상태·최적성 미확인·오류 시 자료/시계 미접근·비합성 출처/비교 탐욕 거부·출력 불변/I/O 부재·잘못된 시계를 확인했다.

전체 pytest 1,192개·Ruff 린트/포맷·환경 import·pip check가 통과했다. 최신 head CI/병합은 실제 완료 후 기록한다. 웹/실제 LLM 서술/사실 검사·API/SSE·실데이터·새 수집은 이번 증분에서 실행하지 않았다. 승인된 두 모델 추출 비교는 다음 R4에서 수행한다.
